# A2｜讨论与研究

> **职责：承接用户需求，与用户共同完善功能、交互、UI、架构及实现方案；保存比较、参考、实验和待决问题。** 本目录为协作研究层，不直接授权产品施工。

## 研究过程

1. 从 [A1｜需求与想法](../A1-需求与想法/README.md) 接收用户目标、问题与原始意图；不得擅自修改用户的目标。
2. 研究使用场景、功能拆分、交互方式、模块归属、接口约束、安全与数据边界；必要时参考外部项目或进行隔离实验。
3. 明确区分 **用户已确认决定／AI 建议／研究证据／待用户裁决／已否定方案**，保留能够核查的来源与时间。
4. 对存在冲突的方案给出差异、风险和建议，由用户判断。未定事项不得被写成正式已确认需求。
5. 研究内容得到用户确认后，**另由产品整理环节**转化为功能需求、UI/操作交互设计、架构决定，并在检查版本边界后形成任务书和模块契约更新；研究原文保留溯源。

## 边界与现行文档

- **本层不是正式施工入口**；Codex 仍按用户指定的施工任务书，进入模块 README、CONTRACT、源码与测试。
- 不因为研究了语音交互、TTS、模型音频 API 或其他候选方案，就自动加入 0.1.1、0.1.2 或“下一版本”。
- 既有 `docs/research/`、`docs/product/`、`docs/decisions/` 等文件暂保持位置和当前权威关系；本轮**不进行大规模迁移、删除和链接改写**。

## 当前阶段

此目录只建立第二环节的归属和入口；**不把讨论过程直接升级成最终技术设计或施工任务**。
