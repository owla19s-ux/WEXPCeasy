## 1. 读表规则与状态字典

**一条功能必须分开记录三个事实，不能混成“已完成”：**

| 维度 | 使用状态 | 可判定标准 |
| --- | --- | --- |
| **施工** | 待施工／已有基础／部分实现／实现待复验／实现完成／不属本版／冻结 | 以具体源文件、公开端口及功能行为为依据；仅有 README/原型不等于已有基础 |
| **验证** | 未运行／用例存在待运行／同 SHA 通过（限指定范围）／失败／跳过／待真实服务／待 Windows E4／独立签收 | CI 结果必须带 **run URL + 被测 SHA + 测试范围**；跨模块成功不能由单模块绿灯推断 |
| **验收** | **未签收**／已签收／不适用 | 只有独立复核功能行为、拒绝/异常/恢复证据后才能标“已签收”；本表已映射的 24 项当前均未完成独立签收 |

**入口顺序**：用户授权的本版任务 → 本表 §3 对应 B 编号 → §4 的 F/U 细项 → 对应模块 README → 公开接口、源码与测试。复杂跨 owner 任务才按需要扩展依赖；不以 A0 历史研究或旧任务书自动增加施工范围。本表负责**版本状态**，A1 负责长期功能定义，源码 README 负责模块实现边界；A0 独立保留研究历史，不在本表创建跨层研究导航。

**范围**：B1/B2/B3 各 8 项，共 **24 个固定任务**；D-01～D-10 是 B3 工作包拆解，非新版本任务。90 条 F 是本版基础子行为清单，20 组 U 拆成 40 个 UI 检查点；它们不是 154 项彼此独立的新任务。长期 F01–F15 共 216 项，不等于 0.1.1 必须全部交付。

**范围红线**：自由格子工作流、正式调度器、DSH 插件及外部连接器、完整环境下载安装/升级/卸载、语音及未获确认的高级 UI 不属本版自动施工；F01-007 的 Placement 历史方案冻结，不创建该实体。未决高风险权限不擅自确认。

**更新规则（避免历史快照互相覆盖）**：

1. §0 和 §5 记录唯一的**当前已核对代码 SHA + CI 运行集合**。其它章节提到旧 SHA 时必须明确为“历史静态审查/参考”，不等于当前测试通过。
2. 每次施工回执更新 §3 对应 B 任务、§4 对应 F/U 子项：填 owner、实际行为、施工状态、验证状态、未通过原因、下一步及新证据。无法判断时保留“待复验”，**禁止用文件数量、存在测试或过去绿色运行推断通过**。
3. 只有独立验收者可更新“已签收”。文档维护与代码施工分离；即使只有一个模块确认，也只更新该模块/子行为，不给整个批次签收。
4. 缺口写成 `功能编号 → owner → 可复现失败/依赖 → 证据 SHA/链接 → 解除条件`。若测试仍在排队/跳过，明确写“未运行”，不填虚构百分比。
5. 旧计划及 B1/B3 细则在 A2 的历史任务记录目录按需查证，不与本表平行维护当前进度；新版 0.1.2 将独立建立版本状态主表，不覆盖本表。

### 4A.2 防遗漏与验收口径

- **设置页面不是“已经有框架就完成”**：四个一级分类（连接与服务、权限、验证、系统）已出现导航骨架，但服务按钮禁用、权限仅说明、系统缺少目录配置。各一级分类下的小类行为必须分别核验，不能合并为一个 B3-05“通过”。
- **多视图不是通用文件编辑器**：目前可读预览/摘要与有限视图标签已有代码，文件保存/冲突/草稿仍需独立落实。高级双完整视图、多个 Windows WEX 窗口组织、任意类型视图扩展不是已批准的本版范围。
- **虚拟形象与交互栏属于两套 UI 状态**：已观察到基础位置与开关逻辑；入口尚未连真实 AI，不得把占位测试算成产品使用成功。
- **跨模块页面不应制造第二个业务 owner**：UI 专管展示与交互，Space/API/AI/Conversations/Connections/Permissions 保留事实；App 提供可信 IPC。需要接口时先记录最小端口与缺失责任 owner。
- **U01～U20 不能全算本版交付承诺**：这些是现有设计的 UI 能力簇；每个簇内未确认子行为、后置版本、待硬件与高风险权限按正式 0.1.1 范围收口。先让 Codex 处理已确认且可执行的子功能。
- **更新总表时必须回填同一 U 行的真实状态、对应源码与测试、最新 SHA/Actions、未通过的行为**；不得仅修改“已完成”字样而不提供证据。其它模块将按同法逐域审查，此次仅做 UI。

## 6. Codex 连续施工要求与交接回执

- **持续施工单位 = 一个可独立验收的模块或其明确功能集合**；在授权范围内连续执行：查看最新代码/契约 → 差异定位 → 实现 → 测试 → 修复 → 回归 → 提交 → 回执。除真实阻塞、已完成整单或授权/工具环境不具备外，不因每个文件或一次提交就停止要求“继续”。
- 只修改本次已授权 **源码与测试**；不可擅改 README、CONTRACT、产品功能表、版本计划、本总表和 A0。用户另行授权文档治理时按专项边界处理。
- 默认在最新 `main` 上工作；写入前核查远端新提交。需要隔离时用短期分支，绝不以本表快照 SHA 覆盖 main。
