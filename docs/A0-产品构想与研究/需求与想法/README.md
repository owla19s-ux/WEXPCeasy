# 需求与想法

保存**用户提出的产品目标、功能设想、场景、痛点、反馈**，以及讨论中形成的**基础方案、UI 交互、架构构想**。允许多种可能并存，允许尚未确定。

- 区分「用户原话/目标」「AI 的理解与建议」「讨论中的候选设想」「已确认的需求意图」「已否定或修订」；能追溯来源和变化。
- 需求意图确认不代表已经完成技术验证、接口设计或版本安排。
- 有必要开展实验或深入比较时，关联 [方案与研究](../方案与研究/README.md)；不因出现技术术语就自动把内容挪到研究层。
- 不在此建立第二份正式功能总表，也不据此指挥 Codex 施工。
