# WEX 自由格子工作流画布技术路线研究（2026-11-01）

> 研究结论：WEX 的工作流画布需求不需要完整通用图形编辑器。当前更适合自研轻量画布，优先使用 DOM + SVG 实现基础交互；图布局/路由算法可按需独立引入。本文是技术比较，不代表已完成原型验证或冻结技术栈。

## 1. 目标能力

二维自由画布、可移动矩形节点、DOM 内嵌通用内容、正交连接线和方向箭头、节点移动后重算路径、基础避障、多分支/汇合/循环的呈现、手动布局与自动整理，以及业务数据/运行调度/视图布局相互独立。

## 2. 候选方案比较

| 方案 | 优势 | 局限/成本 | 对 WEX 的判断 |
|---|---|---|---|
| React Flow | React 集成直接；已有 WEX 原型；自定义节点和边生态成熟 | 复杂正交避障、路径冲突和自动布局仍需补充；交互容易受现成组件模型影响 | 保留为历史实验和比较样本，不作为最终核心依赖 |
| AntV X6 | 图编辑能力完整；提供端口、网格、正交/Manhattan 路由等能力 | 引入完整图编辑引擎；React 集成、状态传递和序列化需要适配；不能代替 WEX 业务模型和调度器 | 技术候选，当前不优先采用 |
| JointJS | 图编辑、路由和布局能力丰富 | 社区版与商业扩展许可边界需要核查；整体能力可能超出当前需求 | 备选 |
| Rete.js | 节点式可视化编程、插件和数据/控制流方向有参考价值 | 更接近可视化编程框架；WEX 已有 workflows/runtime 业务归属，不需要另一套节点执行体系 | 借鉴交互，不引入其执行模型 |
| WEX 自研轻量画布 | 掌握节点、连接和交互语义；DOM 节点适合嵌入工作内容；SVG 适合正交连线；避免整套图形引擎绑定 | 需要自己维护画布坐标、拖动缩放、路径路由、选择、自动布局和性能 | 当前推荐路线 |

## 3. 推荐实现组合

### 节点层：HTML DOM / React

节点用独立 React 组件渲染，展示名称、详情、状态、任务统计，以及对话摘要、代码文件、审查问题和后续专业预览容器。复杂节点内容不宜全部绘制到 Canvas 2D；DOM 更适合键盘输入、文本选择和编辑器。

### 连线层：SVG

SVG 独立覆盖在节点层之上，负责水平/垂直线段、90° 转角、方向箭头、端口、选中态、路径命中和控制点。节点位置变化时，只重新计算受影响的连接路径。业务边 ID 和路径坐标必须分离。

### 画布控制

自研最小能力：平移、缩放和坐标转换；节点拖动、框选、单选/多选、调整大小；连接端口拖动和业务校验；网格背景、可选吸附、对齐参考线；布局持久化、撤销/重做。

### 正交路由

第一阶段先实现可预测的简单路由：读取端口和方向；优先尝试直线或少量 90° 转角；检查是否穿过其他节点；冲突时尝试替代通道；多条线使用间距规则减少重叠；允许用户调整视觉弯折点并保存到 views。

复杂场景再评估 Manhattan/A* 网格寻路、交叉惩罚、端口分配和局部重路由。第一版不追求通用 CAD 级路由。

### 自动布局

先实现基础分层布局：依据执行依赖计算层级，支持横向优先、纵向优先、并行分栏和汇合对齐。循环边需特殊处理，不能假设所有工作流都是 DAG。

复杂结构可以独立评估 ELK.js；Dagre 可作为轻量分层布局候选。算法库只返回节点位置/路径建议，不拥有工作流定义。自动整理应先预览，应用后可撤销，支持局部整理。

## 4. 外部算法和组件的使用原则

自研轻量画布不等于所有数学算法都必须自研。后续可单独引入成熟布局或路由算法，但输入输出必须是普通、可版本化的数据；不得持有 workflows 权威数据或控制任务派发、运行状态、权限；必须可替换，不能把专有对象格式泄漏到业务契约。引入前核对版本、许可证、维护状态和实际性能。

候选参考：

- [React Flow](https://reactflow.dev/)：React 节点编辑与交互参考。
- [AntV X6](https://x6.antv.antgroup.com/)：图编辑、端口和正交路由参考。
- [JointJS](https://www.jointjs.com/)：成熟图编辑能力与许可区分参考。
- [Rete.js](https://retejs.org/)：节点式可视化编程参考。
- [ELK.js](https://github.com/kieler/elkjs)：复杂图自动布局候选。
- [Dagre](https://github.com/dagrejs/dagre)：轻量有向图分层布局候选。

实际实施前须重新核对官方文档、当前版本 API、许可证和性能，不把候选当成已验证依赖。

## 5. 风险与验证门槛

| 风险 | 后续验证 |
|---|---|
| 多条正交线互相重叠/穿过节点 | 密集分支、汇合和节点重排样本 |
| 自动布局破坏用户整理 | 全局/局部布局预览、撤销和固定区域样本 |
| 节点数量增加导致 SVG/DOM 性能下降 | 逐级增加节点与边，测量帧率和重算范围 |
| 业务边与视觉路径耦合 | 改位置/弯折后断言 Workflow Definition revision 不变 |
| 异步布局覆盖手动布局 | 并发自动整理与用户拖动，验证修订冲突 |
| 画布重构导致工作流数据迁移 | 更换渲染实现后读取同一业务定义与运行历史 |

本研究不声称已完成上述实验。现有 React Flow 原型的历史构建和 DOM 测试只证明当时原型的局部能力，不证明新路线或真实浏览器交互已通过。

## 6. 结论

当前推荐：WEX 自己实现轻量自由画布，React/DOM 呈现节点，SVG 绘制正交连接；基础路由和布局先做简单、可测试的版本，复杂算法以后按需引入。WEX 自己实现工作流业务数据和调度器，画布仅作为交互与展示层。该路线需要通过最小真实浏览器原型验证后，才进入正式产品实现。
