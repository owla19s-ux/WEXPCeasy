# A0｜产品构想与研究

> **定位**：单人产品决策 + AI 协作设计阶段的资料入口。收集产品想法、基础方案与架构设想，进行可行性研究，并保存历史参考；**不等于正式产品功能表、已确认架构、版本排期或 Codex 施工授权**。

## 资料分类（不是审批流程）

- [需求与想法](需求与想法/README.md)：用户希望做什么产品、功能设想、使用场景、问题反馈，以及与 AI 初步讨论的基础方案、交互和架构设想。允许未成熟、不完整、反复修改。
- [方案与研究](方案与研究/README.md)：针对具体想法和候选方案，进一步验证“能不能做、怎么做、代价和风险如何”；包括已确认供研究的方案、技术实验、对比分析和证据。**“确认研究方案”不等于“正式决定采用”或“验证通过”。**
- [历史参考](历史参考/README.md)：APS、WEX、WEXPC 等历史阶段有价值的原始资料及外部项目参考；保留来源和历史语境，不默认继承旧架构/权限/版本结论。

## 权威与交接边界

1. 用户决定产品目标与取舍；AI 可以提出建议和反对意见，但要区分用户原意、AI 推测和研究事实。
2. A0 可以包含早期基础设计、架构草案、被否定方案和实验记录；**任何新想法都不自动进入下一阶段或任何既有版本**。
3. 经过用户确认后，才由产品整理环节将结果纳入现有 [正式产品资料](../product/README.md)、适用的架构/决策文档，并按实际版本形成或更新任务书。
4. Codex 仍按**用户指定任务书 → 对应模块 README/CONTRACT → 源码与测试**施工，A0 不替代施工入口。工程回执也不能自行重写用户产品意图。
5. 某项研究被正式设计吸收后，应保留来源关联，但不允许研究原文与正式设计争夺权威。
