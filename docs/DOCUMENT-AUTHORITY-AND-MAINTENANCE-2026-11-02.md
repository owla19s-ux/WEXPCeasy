# WEX 文档权威与维护原则

更新：2026-11-04。本文是现行文档治理规则，不新增产品决策。

## 最短阅读路径

根 [README](../README.md) → 当前模块 README → 最新源码与测试。[AGENTS](../AGENTS.md) 是兼容入口，不维护第二套规则。版本、功能、契约或政策问题出现时再定向查阅；不强制每次读完整 docs、版本表或研究契约。

根 README 决定当前施工模块；A1 保存已确认产品规格，A2 保存版本功能及真实工程状态；版本功能表不自动派工，也不写死施工优先级。施工 AI 依当前授权、目标模块 README/CONTRACT、源码与测试自主评估依赖。普通施工的文档修改限制依根 README；用户明确授权的文档专项维护可在授权范围内整理文档，不取得产品源码或政策修改权限。

## 分层隔离与最小引用（2026-11-07 补充）

A0（构想与研究）、A1（正式产品设计）、A2（版本与工程状态）**各自独立维护正文与内部索引**，不因为可以互相追溯就建立默认交叉导航，不复制同一份权威状态。跨层引用只在明确的设计依据、版本任务或验收证据需要时按具体文件保留。

源码模块 README 默认只说明本模块职责、公开接口、直接依赖、现有实现和验证方式；子目录通常只需引用自身的上级模块或直接业务 owner。**不在每个模块中重复列 A0 历史研究、A1/A2 总索引、文档审计与批次报告**。正式设计或当前版本状态确实影响施工时，可保留一个指向具体依据的定向链接，而不是把全套目录挂在模块里。

A2 默认以**模块为基本关联单位**连接源码目录；只有跨模块依赖复杂、接口需要共同验收、任务存在特殊证据链时，才为该任务增加必要的多模块引用或专门索引。此例外不得变成所有任务的固定模板。

文档完整性审计允许扫描全部文件和链接，**扫描范围不等于文档必须互引**；保留 A0 原始研究及审计证据，不以精简导航为理由删除独立事实、关键契约或旧记录。

## 维护与冲突

1. 模块 README 保留必要稳定契约摘要；详细历史研究只链接唯一正文。兼容 CONTRACT 不追加正文。尚未迁移的研究 CONTRACT 原地标明研究性质，不因文件名成为正式接口。
2. 新版产品决策需记录来源、修订范围与旧结论适用性。A 明确文档错误直接修；B 旧资料保留历史标识；C 核对源码后修状态；D 真正产品冲突记录双方依据，暂停受影响修改。
3. 研究报告、失败日志、原始测试与外部来源信息不因旧而删除；完全重复也须核对用途、入链和历史价值。第三方快照不改写，问题单列。
4. 移动必须同步全部内部引用，保留旧/新路径及原因。历史正文只修确定的路径/状态，不重写当时结论。
5. 当前正式入口的本地文件、大小写、编码及标题锚点均需检查；远端 URL 不可达与本地断链分开报告。
6. 提交不等于验收。Windows E4、真实 Provider、外部 Agent、插件隔离及未决权限不能由文档整理宣告通过。
