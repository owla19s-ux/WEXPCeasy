## 冲突处理和版本状态

- **事实冲突**：优先核对实际对象和时间/版本/环境；不同日期状态可同时为真，不直接覆盖历史原文。
- **需求冲突**：分别记载用户已确认、B 候选、C 待实验、D 待裁决；不得以旧研究投票取代用户批准。
- **Owner 冲突**：保留原文并列出两个具体对象/职责，核对模块契约及实际实现，待明确后同步总表与契约。
- **状态文本**：每份报告标注“截至 YYYY-MM-DD / commit”；后续修正应加顶部修订提醒或索引提示，禁止抹掉原始测试记录。
- **维护范围**：根 README 只提供当前最小入口；docs README 提供目录导航；product README 解释产品范围，避免在三处复制可变的统计/详细业务规则。
- **删除条件**：必须先完成链接入度、正文同一性、使用方依赖及历史追溯检查；未经确认不批量删除旧研究、跳转页或原始报告。
