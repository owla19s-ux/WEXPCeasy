# WEX 工作流自由画布与节点工作界面设计（2026-11-01）

> **状态：** 自由画布方向、WEX 自主掌握工作流业务与调度、前期通用节点界面范围，已由用户确认。本文是跨模块设计基线，不代表产品代码已实现，也不冻结正式 Schema、函数签名、IPC、持久化格式或具体算法。

## 1. 核心定位

工作流编辑器不是通用流程图产品。自由格子画布只是 WEX 工作流的表层 UI 与交互工具；工作流定义、运行事实、节点调度和恢复机制由 WEX 自己维护。

工作流相关能力分为三层：

1. **工作流业务层**：定义节点、执行关系、条件、输入输出、运行实例和规则。
2. **画布交互层**：将业务结构投影为格子、正交连接和状态信息，提供编辑、布局和导航。
3. **节点工作界面层**：打开节点后呈现实际工作内容；前期使用通用界面，复杂专业工作台以后扩展。

同一份工作流业务定义可以有不同展示视图。更换画布或布局方式，不应要求迁移工作流数据。

## 2. 自由格子画布

### 2.1 节点与布局

- 节点以可编辑矩形格子呈现，可以自由移动和调整大小。
- 不固定为表格，不强制纵向堆叠或横向流水线；横向、纵向、分区或混合排列均可。
- 背景网格、对齐参考线和吸附可以作为辅助，但不把画布锁定为固定单元格。
- 节点位置、尺寸、分组和视口属于视图布局数据，不是执行顺序或业务关系。

### 2.2 正交连接

- 只允许水平直线、垂直直线和 90° 转角组成的折线路径。
- 显示方向箭头，不使用任意自由曲线或手绘线。
- 路径尽量避开节点；多条线的重叠、交叉和端口分配逐步优化。
- 用户可调整连接线转角或路径；手动弯折点属于视图数据。

**执行关系与视觉路径必须分开：** A → B 的业务依赖不因节点移动、自动整理或连线绕行而改变。新增/删除执行依赖必须通过 workflows 的受控编辑能力；调整线条弯折只修改 views。非执行视图中的关系也不得自动解释成工作流执行边。

### 2.3 节点卡片摘要

基础节点卡片可以显示名称、详情、状态颜色、任务总数、已完成数、执行中数量、待处理数量、当前任务、失败/阻塞提示和结果摘要。

颜色只是状态的视觉投影，不能作为状态权威。任务统计和节点状态必须来自 workflows 的权威运行数据；画布不得自行维护可写的运行状态副本。

## 3. 手动编辑与自动整理

手动编辑包括添加/删除节点、修改名称和详情、拖动/调整大小、建立或删除连接、选择节点、调整视觉弯折点、撤销/重做和保存布局。

自动整理是基础辅助能力，不是唯一布局方式。至少支持研究横向优先、纵向优先、依赖分层、并行分支分栏、汇合节点对齐、局部整理和全局整理。

自动整理只计算视图位置与视觉路径，不更改节点业务定义、执行依赖、条件、权限或运行状态。应用前应允许预览，应用后可撤销；局部整理不能无故重排无关区域。循环和复杂嵌套结构的布局规则暂不冻结。

## 4. 数据、调度与展示的职责边界

| 对象/事实 | 权威 owner | 画布或其他模块的作用 |
|---|---|---|
| Workflow Definition、修订、节点业务身份/配置、执行依赖 | workflows | 受控编辑和读取投影 |
| Workflow Run、Step Run、节点业务进展、Task 关联 | workflows | 展示权威状态和统计 |
| 等待、派发、恢复、资源/并发协调 | workflows/runtime | 调度器推进，不由 UI 推断 |
| Operation、外部调用尝试、观察和回执 | connections | workflows 保存引用并依据证据推进 |
| 授权策略与判定 | permissions | 实际编辑/派发前调用权限边界 |
| 节点位置/大小、viewport、视觉路径、布局方案 | views | 保存和恢复用户布局 |
| 画布交互与节点卡片渲染 | workflows/editor | 将 UI 意图转为受控业务/视图编辑请求 |
| 工具协议和外部调用 | connections 及具体适配器 | 提供可替换能力，不拥有 WEX 工作流语义 |

WEX 自己维护工作流定义、节点身份、依赖关系、运行实例和调度机制。图形库只负责绘制和交互；第三方 Agent、插件或专业软件可以执行具体工作，但不能成为 WEX 工作流数据和调度状态的唯一权威。

调度器属于 workflows/runtime，不新建与 workflows 平行的顶层执行平台。节点不是 Task，Task 不是 Operation；节点运行状态、Task 工作轮次和 Operation 外部尝试必须保留各自语义。具体调度规则继续以 workflows/CONTRACT.md 的 A/B/C/D 状态和后续验证为准，本文件不冻结算法。

## 5. 节点工作界面：前期与后续

### 5.1 前期通用界面

前期不为每种节点开发独立专业软件。节点卡片先显示摘要，点击后进入通用工作界面，按任务类型组合现有基础组件：

- 普通任务：详情、任务清单、状态、产物和日志。
- AI 对话：对应 Conversation、执行过程和追加指令。
- 代码编写：对话、文件浏览、代码编辑、差异和工具调用记录。
- 代码审查：审查结论、问题列表、代码差异和验证证据。
- 文件/数据处理：文件列表、数据摘要、处理状态和结果。

节点预览与打开后的工作内容可以不同；不是所有节点都需要实时画面。摘要、检查和监看方式可按能力及当前任务决定，不先冻结为不可变节点类型枚举。

### 5.2 后续专业扩展

3D、视频、音频等复杂工作台以后按真实 Context 需求作为独立扩展，不列入基础画布前期范围。专业界面可以组合观察多个相关节点和共享资源，但仍使用 WEX 的工作流、Task、权限、连接器和产物体系，不另起工作流引擎。

## 6. Context、工具连接与运行环境

视频、3D 等场景需要更多工具连接与环境配置，但不需要另造一套工作流组织机制。

- Context 可以关联工具/连接器、外部应用、本地运行环境、依赖版本、模型与素材、项目资源路径等。
- 具体连接配置、凭证、资源和环境细节仍由各自 owner 管理；Context 保存关联与组合范围，不复制凭证或工具实现。
- 工作流节点声明所需能力和资源引用，运行时由 WEX 检查当前 Context 的能力是否可用，再通过受控连接边界调用。
- 外部工具提供的节点/步骤可以作为能力适配或导入来源，但不得成为 WEX 唯一的工作流语义和持久化格式。
- 外部工具或插件下线时，WEX 保留工作流定义、运行历史、产物引用和已完成证据；受影响步骤标记为能力不可用/待迁移，而不是令整个项目失去可读性。
- 替换外部实现时检查能力契约、数据格式和结果兼容性，不承诺不同 3D/渲染引擎无损替换。

视频创作的难点主要在底层建模、动作、布料、场景、镜头、渲染和生成技术；WEX 节点流负责组织和调度这些工作。前期可连接成熟工具，长期逐步掌握关键能力和数据迁移路径。

共享创作预览属于后续能力：镜头节点可引用人物、服装、动作和场景资产，以粗模/低渲染质量实时预览镜头轨迹，调整后再高质量渲染。相关节点共享同一创作资产及明确版本，不复制互相漂移的场景副本。该能力暂不进入基础阶段。

## 7. 当前实现路线

当前推荐自研 WEX 专用轻量画布，不把完整图形编辑器框架作为产品核心依赖。

候选实现组合：

- React + HTML DOM：渲染矩形节点和节点内部通用 UI。
- SVG：渲染连接线、箭头、选中状态和交互辅助线。
- 自有画布控制：平移、缩放、拖动、选择、调整大小和坐标变换。
- 自有基础正交路由：先支持简单直角路径和基础避障。
- 自有基础自动布局：先支持简单分层、横向/纵向和分支排列。
- 复杂路由或布局算法库可后续隔离引入，但不能接管工作流业务数据和调度。

这是实现方向，不冻结具体组件库、坐标单位、路由算法或自动布局算法。成熟算法库可以单独评估和替换。

现有 React Flow 原型保留为历史交互实验和比较样本，不自动升级为正式产品画布，也不要求立即删除或重写。

## 8. 分阶段边界

| 阶段 | 建设范围 |
|---|---|
| 基础阶段 | WEX 工作流数据与调度核心；轻量自由画布；矩形节点；正交连接；手动布局；基础自动整理；状态/任务统计；通用对话和代码工作界面 |
| 后续完善 | 复杂路由、局部布局优化、大型画布性能、撤销/重做完善、多视图布局与更多通用节点内容 |
| 专业扩展阶段 | 3D/视频/音频专业节点工作界面、共享实时预览、创作资产版本与专业工具深度连接 |

该表表达能力演进边界，不是已批准的 0.1.1/0.3/0.5 版本排期。

## 9. 尚未冻结的事项

正式 Workflow/Node/Edge Schema、稳定 ID 和版本策略；节点端口类型、数据边与控制边的表达；条件分支、并行汇合、循环及嵌套工作流的完整执行语义；正交连线避障/交叉/端口算法；自动布局与人工布局保护规则；布局持久化和冲突策略；通用节点工作界面契约；Context 工具、环境依赖和资源关联的细粒度 owner；共享专业预览的数据协议与性能边界。

## 10. 基础画布验收方向

1. 节点可自由摆放、移动、缩放，横向/纵向布局均可表达。
2. 连线只出现水平、垂直和 90° 转角，方向清晰。
3. 节点移动只影响布局，不改变执行依赖。
4. 调整连线路径只影响视图，不改变业务边。
5. 修改执行关系必须经过 workflows 受控编辑与版本校验。
6. 自动整理只修改布局，可预览、应用、撤销；局部整理不重排无关节点。
7. 节点状态和任务统计来自 workflows 权威数据。
8. 点击普通对话/代码节点可以进入正确的 Conversation/通用工作界面。
9. 关闭画布、切换 Context 或改变布局不隐式取消工作流运行。
10. 更换画布实现后，工作流定义、运行历史和任务记录仍可读取。
