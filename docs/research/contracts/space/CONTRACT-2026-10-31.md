# space 业务契约（第四批设计稿）

## A：owner 与非职责

space 唯一维护类别、Space 工作区、可选 Group、独立 Context 本体/自身配置/定位、放置关系及 Context 组合引用（包括资源、角色、连接、其他 Context）。Context 无需 Space、项目、模板或任务。多个放置指向同一本体；索引只是定位。AI 职责关联归 AI/roles，会话背景归 conversations，授权归 permissions，任务归 workflows；本域不复制这些事实、不搬迁被引用资源、不执行工具。

解除放置/组合引用不删本体、不撤权、不停止任务、不移动文件；删除本体是独立请求。角色选择由本域写，职责绑定由 AI 写，不建双向可写成员表。

## B：共同请求与观察语义

以下是业务信息，不要求固定字段名。可信调用事实必须由宿主绑定：当前主体（实际执行身份及来源）、入口（本地交互/独立对话/任务/受控回调的实际实例与代次）、适用职责事实及其来源修订、目标资源身份与动作。外部文本、模型输出、UI 自报 role/Context/administrator 不构成可信事实。宿主不能仅转签未经核对的外部声明。

Context 可空，含义仅为“本次没有 Context 范围”，不代表全局、不代表默认项目、不继承上一次入口。非空 Context 也不自动授权；入口不同不求权限并集。对象引用以领域身份与来源定位，显示名/路径不是独立身份；资源范围须说明单对象/集合及动作，不能以自然语言名称推导递归范围。

修改请求具有调用意图标识、期望修订和规范化目标；同一主体/入口/能力/意图标识重送相同内容返回原结果，不重复写；相同标识不同内容拒绝。去重保留期限、跨重启保证与意图查询需在实现契约证明，不能假设无限期。删除/解除与新建必须是不同意图。只读可重试但须重新判可见性。

结果至少区分：已确认提交（有权威修订/证据引用）、业务拒绝（未提交）、依赖不可用、确定失败（已证实未提交）、结果未知（无法确认是否提交）。超时/断连不是业务失败。保存返回不明确时先按意图查询或回读权威修订，未知期间不换新意图盲重试。取消在提交前可确认未提交；提交后返回已提交；无法确认则未知，取消不回滚事实。失败/未知不得伪造成功通知。

每次写入以期望修订检查本域对象/关系；旧修订返回冲突与获准可见的当前依据，不最后写入获胜、不自动合并。跨域变化不宣称全局事务；依赖读取提供来源修订，提交时需失效则拒绝/重验。历史证据记录当时依据，当前查询重新检查授权；撤权后历史记录仍保存但不得继续向无权者披露。

## B：提供、消费、私有与装配通知分面

提供面仅 SPC-01…05；对外查询不返回存储句柄。消费 permissions 的可见性/写入判定、shared 的提交确认/定位诊断、宿主注入的目标最小投影和删除影响事实。目标最小投影必须区分“可见存在”“可见已失效”“无法查询”，无权时不给元数据；不会回写本域关系。存储需支持期望修订冲突、意图结果回读、明确未提交/未知，不能以异常统一解释未提交。删除影响端口需提供来源修订/完整性/观察时刻，缺任一则阻止删除；这些仅说明快照质量，不构成跨域锁。实际删除须另证检查到提交之间的竞争控制与恢复，在C关闭前延期。

私有：对象索引、关系表示、路径实现、缓存和关系提交策略。app 绑定可信身份/入口与上述窄端口；space 不 import AI/conversations/workflows 的私有数据，也不要求这些域反向调用 space。变化通知仅“本域已提交对象/关系及修订”的失效提示，订阅者必须重查且重判权；不携全Context，不要求总线、可靠广播或通知驱动授权。通知丢失用权威查询修复。

## A/B/C/D 与准备度门槛

A：上述唯一权威、独立Context、多处引用、不隐删/扩权。B：本稿能力粒度、去重/结果分类/删除阻止策略和样例。C：多目录重启、身份复制冲突、重定位/跨存储一致性及删除竞态。D：强制删除/回收站与保留期限、引用目标删除后的用户呈现细节。

准备度：可供消费者审阅的业务草稿；不是可施工正式接口。进入实现接口前，SPC消费者需确认最小投影/影响端口及无权呈现，B获批准并关闭删除策略D或明确延期；实际删除在跨域引用/在途工作竞争与检查—提交一致性C关闭前延期；进入实际删除/重定位施工前须以故障实验关闭对应C。未达门槛只做已明确范围，不用猜测补全。

### SPC-03/04：跨Context共享与外部版本（F03/F07）

同一资料/AI/连接可被多个Context引用，但关系只表组织用途；目标领域拥有正文/版本/来源限制，space只提供获准引用及定位。解析引用不递归展开其他Context全部资料，不把同一本体的放置范围合为权限范围。向另一Context共享生成产物是目标引用/披露动作，不是复制原许可；由实际内容owner提供来源限制，permissions判断传播。

外部文件改写不改Context本体身份；对应连接适配报告资源观察，workflows判核验适用性，space仅更新可见定位/可用性。断言：C1/C2引用X后C2仍可无权读X；解除C1不取消C2任务；X内容变更不凭路径相同显示旧验收适用于新内容。非软件小说/资料/表格目录均可直接关联，不要求Git、模式或Task。

## G1/G5 与跨对话持续工作补充（2026-10-31）

本节把基础能力完整性审查中的资源引用、内部检索和持续上下文要求归回本域；具体能力成熟度与跨域组合验收见[基础能力落地映射](../docs/planning/FOUNDATION-CAPABILITY-IMPLEMENTATION-MAP-2026-10-31.md)。

**G1：Context 资源引用。** Space 维护 Context 对资源的组合关系和获准定位，不接管文件正文、远端对象或操作结果。引用至少在语义上区分：
- 外部关联：原文件/目录/仓库/远端对象仍由原来源拥有；保留来源与定位观察，路径字符串不作为永久身份。
- WEX 管理资料：用户明确导入后形成的持久资料对象，存放于用户选择的数据根；Space 只关联该对象，不把文件字节塞入关系记录。导入/复制必须是显式动作，来源和新对象身份可追溯。
- 会话临时附件：只作为某次输入/生成的来源，不因曾在对话出现就自动成为 Context 长期资料。
- 工作产物：由 Workflows/对应资源 owner 维护，Context 仅保存引用，不将产物复制成第二份权威。

引用记录须允许消费者获知目标 owner、来源类型、定位/版本观察及引用用途；实际内容读取、导入、外发和写入仍由对应 owner 与 permissions 控制。解除引用不删除资源、不撤权、不停止 Task。

**G5：本域查询。** Space 提供获准的 Space、Group、Context、组合关系及资源引用查询。查询结果是可重建投影，不成为跨模块内容索引；不得遍历无权目标、泄露无权名称/数量或将 Context 关联当作资源读取许可。UI 聚合搜索时按当前入口筛选，打开结果重新查询并判权。

**跨对话持续性。** Context 是长期工作资料和组合关系的稳定入口，不是某一轮对话摘要，也不保存可复用的永久授权。新 Conversation 可以重新解析同一 Context 的当前获准引用；源版本变化、失联、复制冲突必须保留诊断，不静默回退到缓存或创建空对象。Context 可以没有 Task；Task 也可以没有 Context。

本补充不建立 Resource Center、公共知识库或全局记忆账本，不冻结资源字段/URI/附件协议。持久导入的具体存储 owner、身份和迁移方式在实现契约中明确后再施工。


## SPC-06：Context 资源引用条目管理（模块编号 SPACE-RESOURCE）

Space 拥有 Context 与资源之间的引用关系及其 Context 侧描述信息；资源正文、真实身份、内容版本、访问能力和操作结果仍由对应资源 owner 拥有。每个 Context 可维护多条独立引用，不以单一“项目地址/目录地址”字段代替资源集合。

### SPACE-RESOURCE-001/002：多条引用与描述信息

每条资源引用至少具有独立关系身份，并在获准范围内保存/返回：
- **名称**：供用户识别该条引用的显示名称。
- **地址/定位**：用户提供的路径、URL、仓库定位或来源系统对象定位；原始定位与 owner 解析出的真实资源身份分开。
- **备注**：用户对该引用用途、范围或注意事项的说明。
- **类型与来源**：如文件、目录、仓库、网页/远端对象、WEX 管理资料、工作产物、会话临时附件；具体类型由可用 owner 能力决定。
- **引用用途与来源修订观察**：供消费者理解为何关联及其依据；不能据此取得内容读取或外发许可。

允许同一 Context 保存多条引用，也允许不同 Context 引用同一真实资源。显示名称、地址字符串和 Context ID 均不是资源身份。资源引用是关系记录，不把文件字节、远端正文或工作产物复制为第二份权威。

### SPACE-RESOURCE-003/004：新增、编辑与解除

新增、编辑、解除均为独立业务意图，写入须携带可信主体/入口、目标 Context、引用身份、预期修订和本次变更。旧修订拒绝并返回获准的冲突依据；提交未知时按原意图查询/回读，不创建新意图盲重试。

修改名称、备注、用途不改变目标身份。修改地址/定位时，资源 owner 必须解析真实目标：
- 仍指向同一真实资源：按重定位/定位修订处理，并保留旧定位观察。
- 指向另一真实资源：不得静默重定向原引用；必须明确作为新引用，或按经授权的解除旧引用后新增处理。
- 无法解析或身份冲突：保持未决/阻塞，不猜测目标身份。

解除引用只移除该 Context 的关系；不得删除文件、仓库、远端对象或 WEX 管理资料，不撤销其他 Context 的引用/权限，不取消引用目标正在执行的 Task/Operation。删除资源必须由其真实 owner 提供独立删除能力并单独判权。

### SPACE-RESOURCE-005/006/007：状态、重复与来源变化

Space 提供引用状态的获准投影，并保留观察时间和来源：
- 未验证：尚未向来源 owner 验证定位。
- 可用：来源 owner 在记录的观察时间确认可定位；不代表内容读取或执行已获权。
- 不可用/失联：来源当前无法定位；不等于资源已删除。
- 来源变化/观察过期：定位或版本依据已变化；旧观察不能冒充当前事实。
- 身份冲突/可能重复：来源 owner 无法确认身份，或发现候选别名；不得自动合并。
- 无权查询：不泄露目标是否存在、名称、数量或反向引用。

真实身份、别名解析、版本/修订和可访问性由对应资源 owner 提供；Space 不通过比较字符串自行认定两个路径/URL 一定是同一资源。对同一资源的多条引用可以因用途不同而并存。来源变化只使投影/观察需要刷新；旧工作产物是否仍适用由 workflows 判断。

### SPC-06 验收样例

1. 同一 Context 添加多个不同类型资源引用，每条均可独立显示名称、地址和备注。
2. 修改一条引用的备注不影响其他引用；修改定位时保留预期修订检查。
3. 地址变化且解析为另一资源时不得静默改指；无法解析时保持阻塞。
4. 解除其中一条引用不删除目标资源、不影响其他引用或其他 Context。
5. 两个路径被来源 owner 证明是同一资源时可报告别名；未证明时不得自动合并。
6. 来源失联、无权和已删除不能被统一显示成“引用不存在”；无权主体不能通过数量/名称探测目标。

## SPC-07：Context 工具组合管理（模块编号 SPACE-TOOL）

Space 拥有 Context 对工具/连接器能力的选择关系及 Context 级组合配置。工具或 Capability 的安装、注册、全局启停和真实可用性由 app/connections 提供；AI 对工具的资格由 AI owner 管理；全局访问和本次操作判权由 permissions 管理；工作流节点许可由 workflows 管理。

### SPACE-TOOL-001：工具选择、加入、启用、停用与移除

- 用户或获准的配置主体可从 connections 提供的已发现能力中选择工具/连接器加入指定 Context。
- 每个 Context 独立保存工具关系；一个 Context 的启停不改变其他 Context。
- 启用/停用是 Context 范围内的选择状态；移除是解除该 Context 与工具的关系。
- Context 未启用某工具时，该工具不能进入该 Context 的有效候选集合，即使全局模块已启用或 Agent 已具备工具资格。
- 停用/移除不卸载全局模块或 Connection，不撤销全局凭证，不假称停止已派发的外部 Operation。

### SPACE-TOOL-002：Context 级工具配置

Context 可以保存工具特定的局部参数、配置档案引用和明确允许的覆盖项，并记录配置修订。它不得静默修改全局 Connection 配置或其他 Context 的配置；秘密值不写入 Space，凭证只使用 shared/credentials 的安全引用。配置缺失、过期、冲突或与 Capability 版本不兼容时必须明确报告，不静默退回旧配置。

### SPACE-TOOL-003：Context 工具集解析

Space 只返回本 Context 的工具关联、启停状态、局部配置修订及其获准的最小投影。解析结果须区分已启用、已停用、目标不可用、配置无效/冲突和未验证；不得将“Context 已启用”解释成“当前 AI 有资格”或“本次操作已授权”。

最终调用必须重新满足既定资格链：能力/模块可用、全局访问未关闭、AI 工具资格成立、Context 工具启用、当前执行位置/对话模式许可成立，并由 permissions 对真实主体、入口、资源、动作和目标进行本次操作判权。任一条件缺失、拒绝或不可判定均不得派发。

### SPC-07 验收样例

1. Context A 启用工具 X，Context B 未启用 X；A 的设置不得使 B 获得 X。
2. 全局模块或 Connection 停用时，Context 的旧启用关系仍可保留但解析为不可用，不得调用。
3. Agent 不具备 X 的工具资格时，Context 启用 X 不能补足 AI 资格。
4. Context 启用 X 不授予任意文件、Git、网络或远端资源访问；实际操作仍逐次判权。
5. 修改 Context 局部配置不改变全局 Connection 或其他 Context；凭证明文不进入 Space。
6. 停用/移除 X 阻止新调用，但不伪称已取消在途外部操作。

## D01：Context 工具组合开关（2026-11-01）

本节保留用户确认的 D01 决策摘要；具体模块能力、数据归属、增删改查及验收样例以本文件 SPC-07（SPACE-TOOL-001～003）为准。

Context 可以保存本 Context 纳入/启用的工具或连接器组合关系及其修订。该设置用于限定工具在当前 Context 是否可被考虑使用，不等同于授予目标资源读取、写入、外发或执行权限。Context 为空不代表全局 Context，不继承最近一次 Context；多个 Context 的工具开关与资源权限不合并。

详细判定见[ D01–D02 权限矩阵 ](../docs/product/PRD-D01-D02-PERMISSION-DECISION-MATRIX-2026-11-01.md)。
