# D01–D02 权限判定矩阵与执行模式（2026-11-01）

- 仓库：owla19s-ux/WEXPCeasy
- 范围：PRD-D01 分层工具授权与入口准入；PRD-D02 工作流/对话双模式及高风险确认。
- 文档性质：产品业务规则与模块协作矩阵；不是函数签名、IPC、数据库 schema、权限 UI 或实现报告。
- 决策状态：
  - **A 已确认**：不同入口独立授权、默认拒绝未授权入口；工具资格逐层收敛；工作流位置权限与对话四级权限分离；高风险确认独立叠加；角色/Context/Task/工具发现均不自动授予权限。
  - **B 本文建议**：四级对话权限的具体含义、操作风险分类、节点预授权粒度、审批绑定规则与判定顺序，供用户审阅；未确认前不得当成已批准政策。
  - **C 待验证**：可信入口绑定、执行前撤权竞态、跨进程回调认证/重放、Windows 真实资源与进程限制。
- 依据：当前 main 的 permissions、AI、space、conversations、workflows、connections 业务契约及第七/八批实际实现记录。

## 1. 先固定核心语义

**授权不是“AI 有这个工具”，而是“这个可信主体在这个入口、这个范围内，可以对这个真实目标执行这个具体动作”。**

必须分开以下五件事：

1. **能力存在/可用**：WEX 是否装载并启用了工具或连接器，提供方是否真实支持该能力。
2. **AI 工具资格**：当前 Agent/AI 配置是否允许把该工具作为自己的可用能力。
3. **Context 工具启用**：当前 Context 是否把该工具纳入自己的工作范围。
4. **执行位置许可**：本次调用发生在工作流的哪个节点/位置，或发生在对话模式的哪个权限等级。
5. **操作授权**：permissions 对本次真实主体、入口、资源、动作、目标、来源和当前授权修订作出的最终判定。

前四项决定工具能否进入当前工作范围；第五项决定这一次操作能不能发生。前四项任何一项通过，都不等于第五项自动通过。

### 1.1 分层授权链

\[
工具/模块启用
\rightarrow AI使用资格
\rightarrow Context工具启用
\rightarrow 执行位置许可
\rightarrow 本次操作判权
\]

| 层级 | 维护模块 | 判断内容 | 通过后意味着什么 | 不意味着什么 |
|---|---|---|---|---|
| 1. 工具/模块启用 | app 装配与模块启停；connections 提供能力可用性 | 工具/连接器是否安装、启用、可用，模块是否允许工作 | 能力可被系统识别 | 不代表任何 AI、Context 或入口获权 |
| 全局访问约束（独立总闸） | permissions | 用户是否关闭了该类全局访问，或策略是否禁止此类访问 | 该能力没有被全局策略关闭 | 不替代后续层级；不得与模块启用合并成一个含糊开关 |
| 2. AI 使用资格 | AI | 当前 Agent 配置是否把该工具列入可用能力集合 | AI 可以看到/提出该工具调用意图 | 工具列表、角色名称、模型输出不构成执行许可 |
| 3. Context 工具启用 | space | 当前明确绑定的 Context 是否启用/引用该工具 | 工具可在该 Context 范围内被考虑使用 | Context 引用不授予文件、Git、网络或其他资源权限 |
| 4A. 工作流位置许可 | workflows | 当前工作流定义修订中的具体节点是否声明该工具、动作类型、资源/目标范围及执行策略 | 该节点可以在声明范围内请求调用 | 不授权相邻节点、其他工作流、普通对话或其他 Context |
| 4B. 对话等级许可 | permissions（消费 conversations 的可信会话身份与 AI 的主体/职责事实） | 当前对话中这个 AI/Agent 被设置为哪一级工具执行权限 | 该 AI 在本对话范围内获得相应自动化等级 | 不改变工作流节点授权；不授予其他对话、其他 AI 或其他入口权限 |
| 5. 本次操作判权 | permissions | 主体、入口、Context、真实资源、动作、外发目标、来源限制、授权修订与风险规则 | 形成一次性、可复核的 allow / deny / indeterminate / needs-approval 业务结果 | 不成为永久授权 token；不保证 OS 或外部服务一定允许执行 |

**全局访问约束是既有权限基线中的独立总闸，不额外改变用户提出的四层资格链。** 任一层明确关闭，最终不得放行。能力可见性与实际执行授权必须分开：模型即使自行编造工具名或连接器返回了能力清单，也不能绕过 permissions。

### 1.2 Context 为空时的规则

- 有 Context：必须使用本次明确绑定的 Context；该 Context 未启用目标工具，则拒绝。
- 无 Context：context = null 只表示本次没有 Context 范围，**不表示全局范围、不继承上次 Context，也不自动跳过授权**。
- 普通独立对话如需使用工具，必须具有独立对话入口授权和明确的资源范围；不能借空 Context 获得全局文件或连接访问。
- 同一资源被多个 Context 引用，不合并这些 Context 的许可；跨 Context 读取/披露重新判权。

## 2. 入口独立授权矩阵（D01）

| 入口 | 必须绑定的可信事实 | 使用哪套执行策略 | 不允许的继承/伪造 |
|---|---|---|---|
| 普通对话工具调用 | 真实 Conversation、当前 AI/Agent 主体、当前角色职责来源、Context（可空）、工具与目标 | 对话四级权限 + 工具资格链 + 本次操作判权 | 不继承其他对话或工作流的权限；模型自报主 AI/秘书身份无效 |
| 工作流/Task 派发 | 真实 Task、工作流定义修订、稳定节点身份、当前执行主体、Context、资源/动作范围 | 对应节点/位置权限 + 工具资格链 + 本次操作判权 | 创建 Task、分配角色、由对话发起工作流都不自动授权节点副作用；不继承发起对话的四级等级 |
| 用户直接 UI 操作 | 可信宿主确认的实际用户、窗口/入口实例、目标资源、动作 | 独立 UI 入口策略与用户操作授权 | 不能伪造 Conversation ID；Renderer 自报用户/管理员字段不可信 |
| 外部 Agent/插件回调 | 已认证的连接器实例、回调来源、原 Operation/attempt、回调代次、实际目标和动作 | 回调入口独立策略；每次取数/写入重新判权 | 外部自报 Context、Task、角色或权限标签不可信；原派发许可不自动授权任意回调动作 |
| 查询/恢复入口 | 当前可信主体、原 Task/Operation/Session 定位、查询或控制动作 | 查询只读许可与继续/重派/停止等动作分别判权 | 查询权不等于重派权；历史允许只是历史证据，不复活当前许可 |
| 权限管理入口 | 可信用户身份、精确许可/策略对象、预期修订与管理范围 | permissions 的管理/审批/撤销策略 | AI 不得给自己授权；执行主体、受益主体和审批者不能混同 |

特别规则：

1. 对话中点击“创建 Task/启动工作流”，只授权这项明确的启动意图；真正进入工作流后，按工作流节点政策重新判权。
2. Task 的职责分配只说明“谁负责”，不说明“谁可以对什么资源做什么”。
3. 外部 Agent 的 OS 权限和自主执行能力不受 WEX 权限引擎自动收缩；WEX 只约束 WEX 自己控制的派发、资料出口和回调入口。无法兑现的限制必须明确展示。
4. 入口身份、实例代次、来源或目标无法核实时，返回拒绝/不可判定，不得通过“默认主 AI”“默认当前 Context”等推断补齐。

## 3. D02：对话模式四级权限（B 候选）

四级只用于**主 AI、秘书 AI 在真实用户对话中的工具执行自主程度**。建议按下表定义。它不是角色等级，也不是高风险分类；主 AI 与秘书 AI 可以分别配置，但角色名称不自动获得任何等级。

| 对话级别 | 建议名称 | 自动执行范围 | 默认询问范围 | 明确禁止/额外门槛 |
|---|---|---|---|---|
| I | 工具关闭 | 不自动调用工具；只可提出建议、解释需要什么能力 | 用户明确开启工具/提升对话等级后，才进入可调用状态 | 当前对话不得直接发起工具操作 |
| II | 逐次确认 | 无自动工具执行 | 每次工具调用都先向用户展示动作与目标，得到本次确认后才可继续 | 高风险动作仍执行额外确认；硬拒绝规则不能被确认覆盖 |
| III | 只读自动 | 对已授权、低风险、范围明确的只读操作自动执行 | 写入、外发、敏感读取、远端副作用、执行命令等默认逐次询问 | 来源不明、目标不明、越权、危险操作仍拒绝或进入高风险确认 |
| IV | 限定自动 | 在明确范围内自动执行低风险只读；用户事先明确预授权的、可逆且有边界的低风险写入可自动执行 | 未列入预授权范围的写入、对外发送、远端变更等仍逐次询问 | 删除、覆盖、Shell/代码执行、安装插件、权限/凭证变更等高风险动作不能因 IV 级而静默执行 |

补充约束：

- **未配置对话等级 = 默认拒绝工具执行**，不是自动落入 II 级，也不是“先按最低级试试”。
- I 级是用户明确设置的“关闭工具”；它与“尚未配置策略”是不同状态。
- II/III/IV 都不能扩大工具启用、AI 资格、Context 工具启用、来源限制或资源范围。
- IV 级预授权必须由用户明确设置，且限定工具、动作、资源/目录、目标、有效范围/期限及必要的数量限制；不能只写“允许 AI 自动操作”。
- IV 级的自动写入仅是**明确预授权的有限例外**。未被明确列出的写入仍须询问。若最终产品政策要求所有写入都逐次确认，则将 IV 级收窄为“允许用户一次确认一个明确操作批次”，不保留自动写入例外。
- 等级变化只影响后续判定；已经排队但尚未执行的动作必须按最新授权重新检查。已派发的外部副作用不能被等级变化自动撤回。

## 4. 工作流模式：节点/位置权限矩阵（B 候选）

工作流模式不使用对话四级。工作流定义中的每个执行节点拥有自己的权限声明；这里的“位置”是**工作流语义节点及其运行步骤**，不是画布坐标、节点颜色或 UI 排列位置。

| 节点授权维度 | 必须明确的内容 | 运行时要求 |
|---|---|---|
| 能力 | 允许调用的具体工具/连接器能力 | 未声明的能力不因同一工作流其他节点使用过而继承 |
| 动作 | read、write、delete、execute、send/publish 等实际动作类别 | 读、写、删除、Shell、外发分别判权；不能以“允许 Git”概括全部 Git 动作 |
| 资源 | 允许的目录、仓库、文件集合或其他资源身份 | 资源需由真实提供方规范化；路径/名称不能代替资源身份 |
| 目标 | 写入位置、Provider、远端仓库、接收方或服务端点 | 目标改变后原授权不适用 |
| 执行策略 | 自动只读、逐次询问、明确预授权的有限写入、强制确认 | 未设置时按拒绝/需要审批处理，不默认自动 |
| 限制 | 可写范围、可覆盖对象、数据量/次数/有效期等边界 | 超出任一边界重新询问或拒绝 |
| 定义修订 | 工作流版本、稳定节点 ID、节点配置修订 | 运行绑定启动时的定义修订；编辑新版本不静默改变在途运行 |
| 撤权/复核 | 当前权限代次、资源版本、来源限制 | 排队后及实际派发前重新判权；旧批准不抵消撤权 |

节点级规则：

1. 每个节点只对自己的工具、动作和目标范围有效；相邻节点、分支、循环下一轮不得隐式继承。
2. 工作流节点可以在用户明确配置时，预授权精确范围内的可逆写入；不能仅凭“工作流已经启动”自动授权全部节点。
3. 进入高风险动作时，节点预授权不替代高风险确认。
4. 工作流版本固定的是本轮业务依据，不是永久权限。运行期间撤权、Context 工具关闭、全局开关关闭或来源策略变化，均须在执行前复核并阻止新的派发。
5. 编辑器保存定义、拖动节点、连线、复制节点均不触发工具调用或授权；节点身份不能由数组下标/画布坐标推断。

## 5. 动作类型与风险分类矩阵（B 候选）

**只读不等于天然低风险。** 读取敏感文件、把文件内容发送给模型、跨 Context 披露、查询其他用户资源，虽然没有修改原文件，也可能形成不可逆的信息外发。

| 类别 | 典型动作 | 默认处理 | 可自动执行的条件 |
|---|---|---|---|
| R0 受限低风险读取 | 已授权目录内列目录、读取非敏感文件、Git status/diff、读取本次 Task 的获准状态 | 可按对话 III/IV 或工作流节点授权自动执行 | 主体/入口/资源身份可信；范围明确；无敏感内容外发；来源策略允许 |
| R1 敏感读取/数据披露 | 读取凭证/密钥/私人资料；把本地文件、上下文或摘要发送给外部模型/Agent；跨 Context 分享；向外部端点提交数据 | 默认逐次询问；来源缺失、混合且无法判断时阻断自动出口 | 必须分别具备读取许可和针对实际接收方/Provider/Context 的披露许可；读取权不包含外发权 |
| W1 有界可逆写入 | 在明确输出目录创建新文件、写入草稿、更新可恢复的工作副本 | 默认询问 | 只有对话 IV 或工作流节点已明确预授权精确动作、资源和边界时才可自动；否则逐次确认 |
| W2 外部/远端副作用 | Git push/merge、发送消息、发布内容、修改远端记录、触发外部服务操作 | 默认逐次确认 | 必须明确实际目标与副作用；不得仅凭本地写权限或连接可用性自动执行 |
| H1 高风险动作 | 删除/覆盖既有数据、清空目录、强制 Git 操作、Shell/任意代码执行、安装/启用插件、修改凭证/权限/安全设置、公开发布、财务或不可逆外部操作 | 强制额外确认；部分动作限定为可信用户操作 | 必须提供准确目标、影响预览、来源和版本；确认后仍须通过所有普通授权。不能由 IV 级或工作流节点静默放行 |
| H2 强制拒绝条件 | 伪造身份/入口、越权资源、路径逃逸、来源无法核实、未知目标、策略/授权存储不可用、AI 自我授权、未通过信任门槛的插件访问宿主秘密 | 直接拒绝或不可判定 | 普通用户确认不能覆盖；只能修复可信事实/策略/能力条件后重新请求 |

### 5.1 典型工具的动作拆分

| 工具/连接器 | 低风险读取示例 | 写入/外部副作用示例 | 高风险边界 |
|---|---|---|---|
| 本地文件 | 获准目录内读取、列目录、读取版本 | 创建文件、更新草稿 | 覆盖既有文件、递归删除、路径越界 |
| 终端 | 受限环境信息查询（仍需明确命令能力） | 执行构建/测试命令 | 任意 Shell、脚本执行、安装软件、提权 |
| Git | status、diff、log | 创建分支、commit | push/merge 到受保护分支、force push、reset --hard |
| GitHub | 读取公开/获准仓库状态 | 创建 Issue/PR、更新文件 | 合并、删除仓库/分支、修改权限或秘密 |
| API/模型 | 发送本轮用户明确提交的对话输入 | 发送本地资料、调用外部写 API | 将敏感资料发往未批准 Provider/接收方 |
| DSH/外部 Agent | 查询已授权会话状态、读取本次允许的产物 | 派发任务、要求其修改文件/远端资源 | 外部 Agent 的广权限、未知运行状态、无法证明的停止/回滚 |
| 插件 | 读取获准的能力描述/健康状态 | 安装、启用、更新、卸载 | 未验证第三方代码接触主进程、凭证或用户文件 |

连接器负责声明其真实能力、副作用和可观察限制；permissions 依据真实目标、动作、来源和用户策略作最终判断。连接器不能通过把动作标为“只读”自行获得自动执行资格。

## 6. 高风险确认：独立叠加门

高风险确认不是第五级对话权限，也不是工作流节点的一个普通勾选项。它是覆盖两种执行模式的额外安全门。

### 6.1 确认内容

确认界面/业务请求至少要让用户看清：

- 谁在请求：实际 AI/Agent、职责、入口与来源。
- 要做什么：规范化后的具体动作，而不是模型生成的任意自然语言描述。
- 对什么做：资源身份、文件/仓库/远端对象、接收方或 Provider。
- 使用什么数据：来源、版本、敏感性/传播限制及实际外发内容范围。
- 会造成什么影响：将创建、修改、删除、发送或公开的对象；可预览时展示差异。
- 授权范围：一次性还是有限批次、有效时间、适用节点/对话及边界。
- 风险与可恢复性：是否可撤销、是否可能不可逆、外部是否支持停止/撤回。

### 6.2 确认有效性

1. 只有可信用户/有权审批主体可以确认；AI、插件、外部 Agent 不能代替用户点击或伪造批准。
2. 确认绑定精确动作、资源、目标、来源/版本和本次意图；目标或内容变化后必须重新确认。
3. 确认是授权，不是执行成功回执；执行仍须通过连接器和领域入口。
4. 确认提交超时/结果未知时先查询原审批意图，不重复创建更宽许可。
5. 用户拒绝后不派发；不能通过换 Agent、换 Context、换入口或重建 Task 再次绕过。
6. 高风险确认不能覆盖 H2 强制拒绝、来源限制、模块关闭、Context 未启用、AI 无工具资格或可信身份缺失。

## 7. 统一判定顺序与冲突优先级

### 7.1 判定流程

1. **可信入口建立**：宿主绑定实际主体、入口实例/代次、AI/职责来源、Context、真实目标及动作。缺失/伪造时拒绝或不可判定。
2. **能力检查**：工具/模块已启用且提供方确实具备该能力。
3. **全局策略检查**：全局访问开关和强制策略允许。
4. **AI 资格检查**：当前 Agent 的工具能力配置允许该工具。
5. **Context 检查**：若本次使用 Context，该 Context 明确启用工具；空 Context 不扩大范围。
6. **入口模式检查**：工作流读取当前节点策略；对话读取当前 AI/Agent 的四级对话策略；其他入口读取各自独立策略。
7. **精确操作判定**：对实际资源、动作、目标、来源版本和传播限制重新判权；读取与外发分别判断。
8. **风险与审批判定**：识别低风险自动、需要逐次批准、高风险额外确认或强制拒绝。
9. **资源/运行前置检查**：按需检查资源冲突、版本、容量与执行条件；这些检查不代替权限判定。
10. **派发前复核**：在 connections 真正开始外部副作用前，按最新权限修订、入口代次、资源版本和批准依据重新检查；先保存 Operation attempt，再派发。
11. **结果留证**：权限决定归 permissions；Operation/attempt/回执归 connections；Task/节点状态和最终验收归 workflows。不得相互复制权威状态。

### 7.2 结果语义与优先级

| 结果 | 适用条件 | 执行行为 |
|---|---|---|
| deny | 命中明确关闭、强制拒绝、无有效许可或超出授权范围 | 不取数、不排队副作用、不派发 |
| indeterminate | 可信事实缺失、策略/存储不可用、来源/目标/资源身份无法判断 | 按拒绝处理，不猜测、不自动降级、不派发 |
| needs-approval | 请求本身允许，但当前策略要求用户对精确动作批准 | 展示确认；批准前零副作用 |
| allow | 所有层级与本次操作均明确允许，风险规则满足 | 仅允许本次精确范围内的调用；仍需执行前复核 |

冲突优先级：

**强制拒绝 > 明确拒绝/关闭 > 不可判定 > 需要批准 > 允许。**

- 不同 Context、入口、角色、节点或授权记录不求并集；采用最窄的有效范围。
- 任一上层关闭，下层不能重新开启。
- 一个入口的 allow 不能转移到另一个入口；一个节点的 allow 不能转移到另一个节点。
- 高风险确认是 allow 之外的额外条件；needs-approval 未完成前不产生 allow。
- 权限判定超时、断连、回执保存失败或授权代次变化，不得按“没有拒绝”推断为允许。

## 8. 典型业务判定案例

| 案例 | 预期结果 | 关键原因 |
|---|---|---|
| 模块已启用，但 Agent 未配置该工具 | deny | 能力可用不等于 AI 有使用资格 |
| Agent 配置了 Git 工具，但当前 Context 未启用 Git | deny | AI 配置不能越过 Context 开关 |
| Context 启用了 Git，但当前工作流节点未声明 Git | deny/needs-approval（按节点策略） | 不继承其他节点的工具资格 |
| 主 AI 在对话 III 级读取 Context 授权目录内非敏感文件 | 可 allow | 低风险只读且所有范围条件满足 |
| 读取文件后准备把全文发送到外部模型 | 单独判披露权限 | 本地读取许可不等于向 Provider 外发许可 |
| 秘书 AI 与主 AI 共用模型，但秘书没有该工具资格 | deny | 模型相同不合并主体权限 |
| 用户在对话中创建 Task，Task 随后进入工作流 | 重新按节点判权 | 对话等级不继承为工作流授权 |
| 工作流节点 A 获准写目录 X，节点 B 尝试写目录 X | 按 B 独立判定 | 节点权限不横向继承 |
| 节点获准写文件，但 AI 改用 Shell 命令完成 | 重新判定 execute/shell | 文件写权限不包含命令执行权 |
| 读取 Git diff 后准备 push | push 单独确认 | 本地只读不授权远端副作用 |
| 用户撤权发生在排队之后、派发之前 | recheck 拒绝，派发次数为 0 | 旧 allow 不能抵消撤权 |
| 高风险删除命中工作流节点预授权 | 仍需额外确认或拒绝 | 高风险门独立叠加 |
| 来源混合或来源不明，AI 声称已脱敏 | 自动外发阻断 | 模型自述不能降低来源安全等级 |
| Context 为空的独立聊天请求读取任意磁盘 | deny/indeterminate | 空 Context 不是全局授权 |
| 外部 Agent 回调自报“主 AI 已授权” | deny | 外部声明不是可信授权事实 |
| AI 请求把自己的对话等级提升到 IV | deny | 授权管理只能由有权用户/管理入口完成 |
| 恢复旧 Operation 时查询状态 | 按只读查询许可判定 | 查询和继续/重派是不同动作 |
| 恢复流程准备重新提交远端写操作 | 新操作重新判权并确认 | 历史 allow 不复活当前许可 |

### 8.1 完整链路验收样本

用户在 Space 的 Context 中关联 Git 仓库，在工作流编辑器放置 AI 节点并配置 DSH 连接器，节点要求外部 Agent 修改指定目录。

必须依次满足：

1. connections 确认 DSH 能力真实可用。
2. app/全局策略允许该模块和入口。
3. AI 配置允许该执行主体使用 DSH 能力。
4. Context 明确启用该连接器及目标资源引用。
5. 当前工作流节点明确声明 DSH 派发、允许动作、目标目录和执行策略。
6. permissions 核对实际主体、入口、Context、来源、目标目录和具体写入动作。
7. 写入动作未被节点精确预授权时先询问；高风险动作额外确认。
8. connections 在派发前重新判权、检查资源协调并保存 Operation attempt。
9. DSH 返回 completed 仅作为外部观察；WEX 仍需核对真实目录身份、文件版本/diff 和验证证据。
10. workflows 根据独立证据推进 Review/Verification/Acceptance；外部 Agent 不能自批最终验收。

任一权限层失败，外部派发次数必须为 0。外部执行已开始后撤权，只能阻止后续受控动作并请求执行方停止；不能谎称已停止、回滚或遗忘。

## 9. 模块职责与实现差距

| 模块 | 本矩阵要求的责任 | 不得承担的责任 |
|---|---|---|
| app | 绑定可信用户/窗口/IPC/进程身份与入口实例，装配模块，呈现可信确认 | 不保存权限策略或替 AI 自报身份背书 |
| connections | 声明真实工具能力、动作副作用、目标解析、Operation/attempt/receipt；在外部副作用前调用 permissions 并复核 | 不自行批准，不以能力发现替代授权 |
| AI | 保存 Agent/角色的工具能力配置、主体与职责来源修订 | 不保存权限账本；工具列表不授予执行权 |
| space | 保存 Context 的工具/连接组合启用关系和修订 | 不保存权限决定，不因引用资源扩大权限 |
| workflows | 保存工作流节点的工具/动作/目标范围与执行策略，绑定定义修订 | 不复制权限账本；Task/角色分配不授权 |
| conversations | 保存真实会话身份、对话背景及当前生成关联，提供本次对话入口事实 | 不把消息内容或用户口头指令直接转为永久许可 |
| permissions | 独占策略、授权、审批、撤销、判定及依据；消费可信事实并执行 fail-closed 决策 | 不读取各域私有数据库来猜身份/资源，不执行外部副作用 |
| shared | 提供提交/回读/CAS/时间等技术原语 | 不拥有业务权限状态或全局业务数据库 |

### 9.1 当前实现与本矩阵的差距

截至本文件基线，permissions/src/service.ts 的事实结构包含 subject、entry、conversation、可空 context、resource、action、target、relationship 及其代次，并接收 moduleEnabled、globalEnabled、conversationEnabled、sourceAllowed。当前 evaluate 对非 conversation 入口返回 entry_policy_unresolved；现有实现尚未表达：

- AI/Agent 工具资格；
- Context 工具启用；
- 工作流定义修订、节点身份及节点授权；
- 对话四级策略；
- 风险分类与高风险额外确认；
- needs-approval 的完整业务流；
- 可信 Windows IPC/OS 主体认证与执行前竞态屏障。

因此本文件是后续契约收敛目标，不代表上述能力已经实现。现有非对话入口拒绝行为必须保留，直到相应事实来源、策略和真实消费者测试全部接通。

## 10. 验收矩阵与施工顺序

### 10.1 最小验收矩阵

| ID | 验收点 | 预期 |
|---|---|---|
| PM-01 | 模块关闭但其他层均允许 | deny，连接调用 0 |
| PM-02 | AI 未配置工具但 Context 已启用 | deny，模型工具意图不触发连接 |
| PM-03 | Context 未启用工具但 AI 已配置 | deny |
| PM-04 | 工作流节点未声明工具，其他节点已声明 | 当前节点 deny |
| PM-05 | 对话等级未配置 | deny，不自动落入 II |
| PM-06 | 对话 II 级请求只读工具 | needs-approval，批准前调用 0 |
| PM-07 | 对话 III 级读取授权目录内非敏感文件 | allow；越界资源 deny |
| PM-08 | III 级读取后向外部 Provider 发送资料 | 读取与披露分开判定；无披露许可时调用 0 |
| PM-09 | IV 级对精确目录预授权可逆写入 | 范围内可执行；超出目录/动作/期限 deny 或询问 |
| PM-10 | IV 级执行删除、任意 Shell、安装插件 | 不得静默执行；高风险确认或硬拒绝 |
| PM-11 | 工作流节点预授权写入但全局访问关闭 | deny |
| PM-12 | 工作流运行期间定义发布新修订 | 在途运行仍绑定原定义；新运行使用新修订 |
| PM-13 | 节点 A 授权不扩展到节点 B/循环下一轮 | B/下一轮独立判定 |
| PM-14 | 排队后撤权，派发前复核 | deny，外部派发计数 0 |
| PM-15 | 审批后目标/版本/外发接收方变化 | 旧审批失效，重新确认 |
| PM-16 | 来源缺失/混合，模型声称已脱敏 | 自动外发阻断 |
| PM-17 | 外部回调伪造主体/Context/Task | deny，资料输出/写入 0 |
| PM-18 | 空 Context 请求任意本地资源 | deny/indeterminate，不得全局放行 |
| PM-19 | AI 试图授予或提升自己的权限 | deny |
| PM-20 | 恢复时只读查询与继续/重派分开 | 查询单独判权；新副作用重新授权 |
| PM-21 | 主 AI 与秘书 AI 使用同一模型但不同资格/等级 | 各自判定，不合并权限 |
| PM-22 | 权限服务/可信事实源/策略存储超时 | indeterminate，连接调用 0 |

### 10.2 分阶段施工

1. **先收敛业务契约**：确认四级对话权限含义、W1 有界写入是否允许预授权、高风险动作目录及强制拒绝范围。
2. **补齐可信事实提供方**：app、AI、space、workflows、conversations 分别提供窄且可核验的主体/配置/Context/节点/会话修订；不让 permissions 导入各域私库。
3. **扩展 permissions 业务判定**：将入口模式、层级资格、动作风险、审批与执行前复核表达为明确业务结果；不先冻结函数签名或 schema。
4. **接入真实消费者**：conversations、workflows、connections 使用同一行为样例；替身和真实 permissions 必须给出相同结果。
5. **故障与安全验证**：覆盖撤权竞态、回调重放、审批目标漂移、策略存储失联、Windows 主体认证与资源边界。
6. **最后 UI 验收**：将当前决策原因、需要确认、拒绝和不可判定呈现清楚；UI 不成为权限权威。

### 10.3 本轮尚待用户最终确认的具体选项

- 对话 IV 级是否允许用户对精确范围内的可逆写入作一次预授权，使其后续自动执行；还是所有写入无论级别都必须逐次询问。
- 高风险目录中，Shell/任意代码执行、插件安装、权限/凭证修改等是“每次强制确认”还是“仅可信用户可操作/默认拒绝”。
- 工作流节点是否允许在定义/启动时预授权精确范围内的可逆写入；若允许，是否需要运行开始时再确认一次。
- 主 AI 与秘书 AI 的四级策略是否分别设置；本稿建议分别配置、互不继承，默认均不授予工具执行权。

在这些选项确认前，安全默认是：未配置即拒绝；低风险只读仅在范围明确且已授权时自动；写入逐次询问；高风险额外确认；硬拒绝不可由普通确认覆盖。
