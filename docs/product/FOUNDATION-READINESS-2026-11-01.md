# WEX 基础功能模块施工准备度审查（第二轮）

## 1. 分级标准

| 级别 | 含义 | 准入要求 |
|---|---|---|
| G0 可直接施工 | owner唯一、业务I/O与失败语义足够清楚，无C/D阻塞 | 模块独立实现、正反例测试、公开契约测试 |
| G1 补契约后施工 | 方向明确，但缺稳定锚点、I/O、生命周期或异常细节 | 先补模块CONTRACT，再施工 |
| G2 实验前置 | 依赖Windows、并发、外部Agent、存储故障或真实服务证据 | 隔离实验通过后，只开放已证明范围 |
| G3 用户决策前置 | 涉及权限政策、后台策略、数据保留、自动验收、费用和生态 | 用户明确裁决后才能实现对应政策 |
| Gx 复合owner阻塞 | 一个F项横跨多个业务owner或没有现有owner | 先拆分功能/确定唯一主责，不得把它分配给万能shared/app |

同一功能可同时受G1/G2/G3阻塞；绿色只表示限定子集可施工，不代表整个功能域完成。

## 3. 当前可进入施工的范围（不等于版本纳入）

### 3.1 已有产品源码，继续按模块修复/增强

- **shared**：SQLite技术存储、根身份/路径检查、CAS/技术诊断；不得扩展成业务状态总管。
- **permissions**：基础授权/撤销/历史/CAS和执行前复核；非对话入口不能默认允许。
- **app**：可信装配、生命周期释放/重试、诊断接入；不拥有业务数据和授权策略。

第八批报告记录：根npm ci成功；typecheck通过；npm test 50通过/0失败/0跳过；shared 13、permissions 5、app 17测试通过；边界检查15个正反例通过；Electron隔离实验3个进程exit0。以上是2026-10-31 Linux/E2证据，**不是本轮重跑结果，也不是Windows E4**。

### 3.2 可从业务契约进入独立模块施工的限定子集

1. **space：** SPC-01～04，先不做不可逆删除和跨目录物理搬迁。
2. **AI/roles：** AIC-01～04配置/职责/工作依据；不把角色配置当Runtime。
3. **views：** 布局、筛选、获准投影和编辑转交；不把React Flow Draft变正式schema。
4. **workflows：** W01/W02基础定义、Task和轮次；真实副作用派发先经过connections。
5. **conversations：** 无Context/Task普通会话的本域输入/消息/历史行为；真实Provider/工具闭环需连接器组合。
6. **connections：** 先完成C01–C03受控宿主基本行为；各具体适配器按独立契约/证据进入。
7. **F06文件能力：** 先从授权目录读取/写入最小能力开始，必须先补LOCAL契约；终端/Git/Android工具链不能从文件读写测试外推。

### 3.3 暂不进入产品施工的范围

- WEX完整动态插件平台、插件市场、账号/云身份平台。
- 自动最终Acceptance、未裁决的非对话入口权限、有限次数授权。
- 未经实验证明的全局安全并发、恰好一次外部副作用、取消即回滚。
- 未经用户决定的后台常驻、自动更新、硬预算封顶/超额处置。
- 公共策略/经验库，直到owner和数据政策确定。

## 5. 用户决策门槛

PRD-D01非对话入口授权；D02自动/询问/拦截；D03 Acceptance；D04关窗/退出/后台；D05强审计/数据保留；D06外发与来源降级；D07自动更新；D08账号/跨设备；D09 WEX插件生态；D10 Agent记忆共享；D11预算/配额。

## 6. 施工与验收顺序

1. 补齐缺失/未编号的模块业务契约和复合owner功能拆分。
2. 按模块独立施工：输入输出、正例、拒绝、失败、unknown、取消、重试、恢复、并发与修订。
3. 提供方与消费者运行同一契约样例；替身只证明本域行为，不冒充真实集成。
4. 组合验收复用H01–H30，优先H14普通对话工具往返、H11 Space→Git→DSH→验收、H15本地Git→GitHub、H21日志诊断、H30安装恢复。
5. 基础模块及组合达到门槛后才做UI接线与真实用户操作验收。
6. 完整需求、D项和施工准备度经确认后，再推导0.1.1版本表。

**当前结论：基础模块可以分批施工，但不是216项全部绿灯。优先补API/local/conversations/modes/views/AI-memory/shared-logging/app-ops契约，以及F10/F15复合owner。**
