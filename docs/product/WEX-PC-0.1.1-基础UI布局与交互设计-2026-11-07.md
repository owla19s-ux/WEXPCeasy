## 0. 使用规则：空间结构与功能映射分离

**四列只规定空间结构，功能还需要一层独立 UI 映射。** 本文负责列、面板、导航、布局与可用空间的组合规则；[0.1.1 UI 功能映射与设计收口](WEX-PC-0.1.1-UI功能映射与设计收口-2026-11-07.md)负责每个用户功能如何被发现、操作、判权、反馈和恢复。两者互补，不替代产品功能表、I 交互语义、正式版本计划或模块 owner 契约。

**以后每个 0.1.1 用户可操作功能都必须明确六件事**：
1. 入口在哪里（列、视图、设置、菜单或可信弹窗）；
2. 用户怎么操作（具体行为与业务意图）；
3. 调用哪个模块（唯一 owner 及公开接口/受控 app IPC）；
4. 权限怎么确认（可信主体、入口、目标、动作和范围）；
5. 结果在哪里显示（成功、失败、拒绝、取消、过期或未知）；
6. 失败如何恢复（保留输入、重读修订、追查原回执及安全重试）。

**约束施工 AI**：不得看到一个功能名就自行新增页面、模块、业务数据结构、对象实体或权限政策；UI 负责呈现和交互，不能把视图状态当作领域事实。功能缺乏真实公开能力时应明确不可用，不能假装已实现。

## 1. 定位与版本边界

0.1.1 采用**四列横向布局**：① Space / Context 与全局导航；②当前视图的结构/列表；③**通用主操作区**（文件、对象、配置或完整对话）；④可配置的纵向辅助窗口。底部另设可向下收起的扩展区。

- 四列分隔线可调整宽度；第四列内部窗口可调整高度；必要时隐藏/恢复辅助列，布局配置可保存与恢复。
- 固定列结构、内容类型切换和基础多视图属于本草案；**任意自由拖拽重排、完整自由格子工作流、正式调度器等不在 0.1.1**，仍按计划后置。
- **显示工作流内容不等于启用工作流引擎**：如有已有、获准的节点或阶段资料，可提供只读展示；没有真实状态时不得显示伪造的“运行/成功”。
- 图形结构为桌面宽屏优先的起点，列宽百分比和像素最小值尚未冻结，需在真实 Windows 窗口和不同 DPI 上验证。

## 3. 第一列：Space 类别与 Context 导航

- **Space** 下默认纵向显示“个人 / 工作 / 公开”三项。这三项是**Space 类别**，而不是 Group，也不是三个具体 Space；点击类别直接切换，不展开成分类文件树。
- Space 类别支持添加、重命名、修改、删除；类别下具体 Space、可选 Group、Context 仍遵守已有独立业务概念。删除带有对象的类别时如何迁移/阻止删除按 Space 正式规则，不由 UI 猜测。
- 下方 **Context** 导航展示当前选中范围和关联的多视图入口。可添加、移除、命名视图；移除视图不删除 Context、地址、实际文件或 Conversation。
- **普通对话必须有独立全局入口**，即使用户尚未创建 Space、Context 或 Task 也能开始聊天；其历史可通过第二列会话列表定位，第三列可承载完整对话。对话的身份仍归 conversations，不把 Conversation 强制变成 Context 子对象。
- **第一列最左下角**是「独立设置控制区 + 角色展示窗」：设置按钮位于角色展示区上方，导航滚动不影响该控制区。两者视觉上组合、功能上独立；角色隐藏或移出 WEX 时仍可进入设置。具体显示、轮播、列折叠规则见第 3.1 节。
- 具体 Space 和 Group 的呈现需与现有 Space 模型一致；本草案不引入 Placement 实体，也不把类别直接当 Context 父对象。

### 3.1 左下角角色展示窗与设置控制区（2026-11-07 补充确认）

**位置与独立性**

- 第一列展开时，**设置按钮在上、角色展示窗在下**，整体位于最左下角。设置控制区不随角色媒体播放或显示状态消失。
- 角色窗是轻量 UI 媒体展示区，**不是 Agent 身份、角色配置、秘书业务或设置模块的权威数据容器**；设置按钮仍调用独立设置页面。
- 设置控制区随第一列布局调整位置：第一列收起后依然保持可见、可点；角色被用户隐藏时设置入口也仍可用。角色未来允许弹到 Windows 桌面时，设置入口须保留在 WEX 内，不强制跟随角色离开主界面。
- 不增加角色窗旁的快捷键按钮；**快捷键系统留待后续版本研究，未来管理入口放在「设置」页面内**，0.1.1 不设计键位体系。

**0.1.1 最小可用范围**

- 用户可添加、移除、排序角色展示素材；支持常见静态图片 PNG/JPG/WebP 和动态 GIF，显示模式优先完整展示、不粗暴裁脸。
- 支持多素材顺序/循环轮播，自动轮播间隔、手动上一张/下一张、暂停或关闭自动轮播；GIF 在当前展示期间正常播放。配置变化及用户可见性选择随界面状态保存与恢复。
- 用户可主动**显示 / 隐藏角色窗**；无素材时显示轻量空态，不影响 WEX 正常使用。
- 媒体经受控资源读取，不让渲染层借素材选择任意读取文件；隐藏/最小化时应避免无谓的播放消耗。
- 0.1.1 **不要求**短视频、动作调度、状态驱动表情、Live2D、桌面宠物行为或独立 Windows 桌面悬浮窗口。

**第一列折叠时的重新安置**

- 折叠第一列**不等于缩成头像，也不等于必须弹出系统级悬浮窗**。默认保持角色窗在 WEX **主窗口内部**，利用第二列底部角落或已有底部区域的相邻空间重新安置；可与左下控制区域处于同一底部高度。
- 角色展示区域应维持合理的小尺寸/默认尺寸，**不能因第二列变宽就自动放得很大**；不应覆盖目录项、文件内容、第二列底部视图切换按钮或第四列对话输入。
- 第一列重新展开后，默认回到最左下角内嵌位置。用户主动隐藏的状态优先：折叠/展开都**不能强行重现**隐藏的角色。
- 角色窗改为 Windows 桌面独立悬浮属于**后续扩展方向**；其主窗口返回、桌面位置、置顶策略与焦点规则以后再设计。0.1.1 当前仅需支持主窗口内重排与主动开关。
- 两种底部安置方案（第二列角落 vs 横跨相邻底部预留区域）及精确宽高留给真实 Windows UI 试排；不新增数据层、不过早冻结像素尺寸。

**交互状态验收**：第一列展开时设置按钮在角色上方；折叠时设置保持可用且角色不遮挡目录/底栏；恢复展开时角色回到原位；用户隐藏后折叠不会自动恢复；图片/GIF 轮播与配置恢复可实际操作。

## 4. 第二列：随视图切换的结构、列表与状态

- 根据当前工作视图切换结构内容：文件/源码或设计资料视图显示目录树；普通对话视图显示会话列表；Context/对象视图显示获准的对象与关联结构。**第二列不固定为文件树**，不得为了展示会话列表新造第二套会话业务表。
- 展开/折叠子目录、选中文件、搜索、筛选、刷新；目录数据必须经获授权资源连接器读取，不让 Renderer 直接任意访问磁盘。
- 第二列下方有**多视图快速切换栏**，对应当前 Context 中实际配置的视图，允许添加/移除/切换。新建“设计资料”视图时，从 Context 已有的“名称、地址、备注”多地址条目中选择目录绑定；不强制创建单独资料系统或把设计文件搬进源码仓库。
- 文件/目录状态标记使用绿、黄、橙、红、灰/黑五种颜色，但**颜色必须有状态维度和来源**：建议绿=该维度通过，黄=进行中/待确认，橙=需核查，红=失败/阻塞，灰/黑=未设置/未知。Git 工作树变化、人工工作状态、测试/验证结论、正式验收互不等价；不能用一次 Git 提交推断文件通过验收。
- 显示标记时应有文字或图标辅助；悬停/点击能看到状态类型、来源、更新时间、关联证据。目录汇总必须提示重要子项风险，不简单平均为绿色。
- 文件状态可手工设置，但手工状态与真实工具/测试结果需有可辨识来源。0.1.1 的完整状态模型和数据 owner 须与现有正式契约核对，不在 UI 中私建业务权威账本。

## 5. 第三列：通用主操作区及文件修改同步（重点）

**第三列是通用主操作区，不是永远固定的文件编辑器。** 随当前选中视图与对象，第三列可承载 Context 详情/地址与工具组合、Agent/角色配置、API Provider/模型配置、完整 Conversation、受控 GitHub/Local 操作，以及文件查看与编辑。具体入口和六问交互见独立 UI 功能映射文档；模块专属表单归原 owner，第三列只负责显示与路由。

当第三列显示文件视图时，支持文本查看、选中、查找、文件标签、用户编辑与保存、复制路径、选区引用。源码、设计资料和施工文档可以复用编辑交互，但各文件的存放地址、权限和用途保持独立。

**必须保证：用户正在看的文件与 AI 经授权修改的实际文件不能长期显示两个互相矛盾的版本。**

### 5.1 状态场景

| 场景 | 界面行为与保护 |
| --- | --- |
| 用户只读查看，AI 修改并成功落盘 | 监听或收到变更提示后重新核对真实内容版本；更新展示并提示“文件已更新”，可打开 Diff；尽量保持滚动/选择位置 |
| 用户正在输入，存在未保存的编辑缓冲区 | **不能无条件热重载覆盖用户内容**；提供磁盘新版、用户草稿、差异比较，以及保留/重新加载/合并入口 |
| AI 与用户同时请求写同一文件 | 写入侧仍按文件版本和有效授权防覆盖；“编辑不同段落”不自动等于安全合并 |
| AI 操作报告成功，磁盘未核对 | 不标作已更新且已验证；重新读取实际状态，再决定显示 |
| AI 请求失败、超时或结果未知 | 保留原 Operation/回执，文件实际状态单独核对，不能因失败回复就断言磁盘未变 |
| 外部编辑器或 Git 操作变更文件 | 同样应检测，避免只监听 WEX 内部操作；丢失监听事件时可主动刷新核对 |
| 文件删除、移动、权限撤销、路径失联 | 清晰提示，不覆盖草稿、不读取未授权内容，保留可恢复的当前 UI 信息 |

### 5.2 实现与验收建议

- 组合使用文件监听、内部受控写入通知、版本/哈希校验、主动刷新、Diff 与冲突处理；文件监听不是唯一可信事实源。
- 原始文件身份/路径、已载入磁盘版本、编辑缓冲版本、当前真实版本和最后操作回执应可区分。
- UI 反馈区分**已读取最新文件**、**AI 操作已报告成功**、**测试通过**和**人工验收**。
- 接线必须通过 Local/Connections、App/IPC、Permissions 的正式边界，不用 React 直接改业务文件，不因页面打开授予 AI 写权限。
- 自动合并、跨工具占用协同及复杂冲突解决尚需细化；0.1.1 至少做到：检测变化、禁止静默覆盖、明确冲突与手动恢复入口。编辑器是否采取自动刷新、何时合并需用真实文件场景验证。

## 6. 第四列：可增减、可选内容的纵向辅助窗口

### 6.1 默认位置（本轮已明确）

1. **上窗口：Context / 当前对象信息**
2. **中窗口：执行记录 / 输出 / 回执**
3. **下窗口：AI 对话**（默认位于**最下面**，不默认在中间）

用户可以通过每个窗口顶部的内容选择框，将其换为“文件信息、引用资料、对话、执行记录、Context 信息、空白”等已有受支持的内容，亦可交换中下窗口用途。

### 6.2 窗口操作

- `+`：在指定位置增加窗口；`−`/`×`：移除选定显示窗口，而不是删除业务对象。
- 每个窗口可折叠、展开，分隔线可调整高度；窗口顺序可调整，数量不固定为 3。
- 对话窗口可点击**展开/最大化**，**临时占满整个第四列**；其他辅助窗口仅临时收起/隐藏，返回后恢复原来的次序、高度、内容和滚动状态。
- 对话单独切换为主视图时应允许更大内容空间；第四列中的同一对话不因此复制 Conversation。
- 窗口多于可容纳高度时提供合理的折叠、滚动或最小高度保护；防止操作入口被挤没。
- 关闭/切换辅助窗口不停止后台网络或工具执行、不删除原始 Conversation/Operation，也不擅自丢弃输入草稿；UI 须处理未保存输入的提示。
- 布局配置持久化并支持恢复默认值，不能把显示配置误当作授权。

## 7. 辅助对话：身份切换、输入操作与语音

### 7.1 主对话与对象对话

0.1.1 先用**对话标题 + 关联目录/文件地址**作为可读识别：主对话标注 Context 名称，对象对话显示标题及对应地址。真正的记录关联仍靠稳定 Conversation ID，同地址可以关联多场对话。

- 可从下拉列表切换，恢复各自消息历史、滚动位置和输入草稿（以真实可支持状态为准）。
- 打开不同文件时，可以提示“打开该对象对话”；**不默认每点一个文件就新建对话**，也不应无提示切换打断当前输入。
- 新对象对话不自动继承主对话全部聊天历史；需要的 Context 文档通过获准引用/读取。Provider Prompt Cache 是性能优化，不是 WEX 持久知识权威。
- 同一个 Conversation 的辅助显示与主视图显示共享业务身份，不各自持有不一致的消息副本。

### 7.2 对话输入栏

必须预留以下明确入口：

- **文本输入、发送、停止/取消当前生成**；展示流式状态与失败/未知。
- **`+` 添加文件/附件**：调用受信任文件选择、支持来源和预览、移除、必要时拖入/粘贴；临时附件不自动成为 Context 长期资料。用户已选择的本地路径不等于 AI 可自由读取或上传，提交前仍需按权限与范围核对。
- **`@` 引用**：选择当前文件、选中文本、Context 已关联资料、目录/对象等可引用目标；插入可见引用标记，用户能删除或检查。引用对象的元数据与真正发送给模型的内容需区分；不能绕过权限自动传出整份文件。
- **语音对话入口**：输入栏显示麦克风按钮，支持开始/结束、识别中、识别结果确认/编辑和发送状态；权限拒绝、麦克风不可用或识别失败有明确反馈。
- 语音的实际识别 Provider、TTS、实时双向语音和持续收音能力**不在本文中擅自定为 0.1.1 已实现或必需全部能力**；0.1.1 应至少在 UI/IPC 层保留清晰入口与禁用/不可用说明，真实语音输入深度对照版本计划及技术验证再定。
- 对话输入同时支持模型/Agent 切换入口，但选择不自动提升权限、修改已派发请求的身份。

### 7.3 对话展开行为

对话从第四列下窗口展开占满第四列时：
- 同一个 Conversation ID、同一生成状态、同一草稿、附件与引用；
- 输入栏仍位于对话区域底部，消息列表独立滚动；
- 收起后恢复原第四列三段或用户自定义布局；
- 不把展开误当成新建主对话，不触发重发或自动重新执行工具。

## 7.4 PC 设置页面：左侧两级导航、右侧详细配置（已确认）

- **充分利用 PC 页面横向宽度**：打开设置后，在主操作区域显示**左侧导航 / 右侧详情**。左侧按“大类 → 小类”展开和选择，右侧显示所选小类的完整设置、添加、编辑、连接测试和错误提示。左侧与右侧**各自纵向滚动**；右侧滚动不带着左侧导航移动。无需沿用 Android 的整页上下折叠手风琴。
- 一级大类**继承原 WEX 已确认的四组**：**连接与服务 / 权限 / 验证 / 系统**，而非历史八组并列一级菜单。左侧点击大类展开/收起小类，点击小类在右侧切换详情；右侧表单较长时可继续纵向滚动。
- **连接与服务**小类候选：API/Provider/模型、Agent/角色配置、GitHub、Local/工具与连接状态；**权限**：模块启用、全局访问、对话/具体操作授权；**验证**：可用性检查、实际连接测试与诊断（不冒充 Task Verification）；**系统**：程序与数据目录、工具环境目录、界面/角色展示、日志/故障诊断、版本/运行状态。小类只展示已获批准且具备真实配置能力的项，不为分类而新建业务模块。
- 每个设置小类的专属表单、配置权威和校验仍归原 owner，`UI/settings` 只提供导航/面板挂载；复杂字段可在右侧详情内部按组折叠，不需要强制新开独立 Windows 窗口。
- API Key 必须走受信录入，不进入可回读的 Renderer 状态；真实连接测试区分“配置保存”和“实际联网测试”。审批展示可信主体、入口、动作、目标与范围；第四列可展示待决提醒，但最终由 app 可信入口和 permissions 确认。
- 设置按钮始终在第一列左下角色窗上方且可用；角色隐藏不影响设置。未来快捷键系统统一归设置内管理，**0.1.1 不开发快捷键系统或额外入口**。

### 7.4.1 主内容与窗口切换的最小行为

- **第一列切工作范围**（Space/Context 或独立普通对话）；**第二列切选中的目录/会话/对象**；**第三列顶部轻量标签**在已打开的文件、详情、配置或完整对话之间切换；**第四列**在各自辅助面板中切换类型、折叠、展开和调整高度。
- 切换标签只改变当前展示，不创建新的 Context 或 Conversation、不取消正在生成的 AI 回复；关闭标签只关闭对应视图，不等于删除对象、关闭会话、撤销操作或停止外部任务。
- 第三列保持合理的未保存输入保护和原视图回返；切换 Context 后不得把旧异步响应写入新对象。多 Windows 顶层窗口的组织策略与任意拖拽分屏仍属后续研究，不在 0.1.1 预造窗口体系。
- 设置可由第一列进入，返回主工作时恢复先前可用的工作焦点/标签；精确标签上限、默认打开策略等属于试排/实现选择，不得据此制造新业务对象。

## 7.5 状态反馈与失败恢复的跨列原则

- 操作发生处就近显示反馈，第四列提供必要的连接器 Operation/执行记录和状态摘要；较长诊断输出可放底部区域。
- **确认提交、明确未提交、取消、拒绝、结果未知必须区别表达**；提交未知保留原 intent/Operation，提供查询/回读入口，不能默认再次发起具有副作用的请求。
- 来源失联、撤权、过期、部分读取和版本冲突有对应空态/警示；保护输入草稿，防止旧异步响应污染已切换的 Context/Conversation。
- 现阶段 Workflows 尚未正式提供的任务/核验状态不可在第四列伪造“运行成功/验收通过”。

## 8. 底部扩展区

- 红框对应区域采用**默认收起、可向下收起/向上展开**的底部辅助区域；支持展开高度调整与状态恢复。
- 适合搜索结果、日志、临时输出与引用检查等辅助内容；不应把核心导航或主要 Conversation 强制塞入此处。
- 第二列底部多视图快速切换与第三列文件状态/操作栏各有明确职责；是否将底部扩展区横跨第 2～4 列、与各列底栏如何衔接，需按正式屏幕宽度实验，不先写死跨列占用。
- 底部收起不影响任务/工具运行。

## 9. Context 地址、资料和界面映射

- 复用 Context 既有主地址及多个附加地址（名称、地址、备注）；这些地址可以对应本地目录、GitHub 主仓、参考文档、产出地址等，不能强行合并为唯一工作目录。
- 用户选择其中一个目录，在 Context 多视图中添加“设计资料”，即可浏览/编辑资料。**不要求现在建设独立资料管理系统**。
- 设计/研究草案与源码施工资料逻辑分离；以 WEXPCeasy 现有源码/模块文档为参考，但不强制把探索性设计资料放入源码目录。
- 用户可以直接编辑资料；AI 可提出更新建议并在有效授权下写入。未经确认的猜测不得无标注地写成正式设计；文件不是聊天的自动副本。
- 视图只是某目录/对象的呈现，移除视图不得移动或删除真实资源。

## 10. 持久化、异常与可用性

建议保存并恢复：四列宽度、隐藏状态、当前 Space 类别/Context、视图配置、第二列展开状态、第三列打开文件和编辑草稿、第四列窗口数量/顺序/类型/高度/折叠/最大化状态、当前 Conversation ID 与输入草稿、底部扩展区状态，以及**角色窗显示/隐藏、素材与排序、轮播间隔、第一列折叠后的界面内安置状态**。具体数据 owner 与持久化结构按现有模块契约核对，不在此冻结 schema。

异常覆盖：
- 重启后资源失联、地址变化、撤权；
- 变更事件丢失、异步回执迟到、重复通知；
- 用户草稿与 AI/外部写入冲突；
- 多列缩到极窄、窗口 DPI/分辨率变化；
- 关闭/切换对话但生成仍进行；
- 语音设备不可用、上传/引用失败、Context 引用无读取许可；
- 视图所引用的工作流数据不存在时只显示空态，不假报状态。

## 10.1 Windows 安装、目录选择与崩溃后外部排查（历史要求回收）

参考既有[源码与 Windows 数据存放要求](../architecture/SOURCE-LAYOUT-AND-WINDOWS-DATA-2026-10-30.md)、[Windows 生命周期研究](../research/WINDOWS-LIFECYCLE-2026-10-31.md)。这不是新增 0.1.1 模块。

- **不做欢迎教程/功能介绍式首次引导**。正常安装后直接进入主界面；**必要的安装目录与数据根选择/验证不能省**，目录不存在、无权、已占用、格式不兼容时只展示最小必要选择/修复入口。
- **程序安装目录**：用户在安装 EXE 时选择；主程序/发行依赖/内置资源可独立定位，程序升级或卸载不能默认清空用户资料。
- **WEX 公共用户数据根**：独立于安装目录，由用户选择或接回已有目录；保存公共配置、索引、应用必要状态、技术日志和可控缓存等，不强制容纳所有 Context/Space 的实际资料。
- **工具与开发环境目录**：作为与安装、公共数据、Space 实物分开的**用户可配置工具资源位置**，在设置→系统中显示、选择和检查；可以关联既有编译器、SDK、工具链/外部工具，不强制首启配置、不默认下载工具，不将其等同插件机制或新增业务 owner。具体环境安装/迁移机制依 tools/Local 正式范围核定。
- **Space 工作区 / 独立 Context / 其他外部资源**：用户按实际位置单独选择或关联；源码仓库、资料、产物可位于其他盘符与路径；添加引用不自动迁移、复制或赋权。
- **尽量少写 C 盘**：受控缓存、日志、Chromium profile/session、可控临时文件应按验证过的路径策略优先进入选定数据根；不能承诺系统盘零写入。必须审核 Electron `userData`、`sessionData` 在启动早期的时序与实际安装器/更新缓存位置，Windows 凭证/系统注册项等必要例外可追踪。
- **崩溃/无法启动时不依赖 WEX UI 才能排查**：让用户或外部维护工具能够从已知的安装、数据和工具环境位置找到**实际安装文件、版本/模块信息、日志、崩溃诊断及必要数据路径说明**；不因主程序崩溃丢失唯一索引。支持脱敏日志/诊断的离线定位与读取，避免将 Key/Token 泄露到普通文件。
- **“可查安装文件”不等于可直接改产品源码**：Electron 的 ASAR/打包构建不保证保留原始 TS/React 源码；如要崩溃现场直接检查可读源码/源码映射，需独立确定发行包的诊断素材或开发版方案。0.1.1 不据此承诺可热改源码或自动重建。
- **重装/恢复**：公共根内有可识别的非秘密定位/格式信息，重装系统后可重新选择原根、重连外部目录；正常重启与重装的凭证/权限规则不同，**重装不能自动恢复旧有效授权或凭证绑定**；旧 Operation 结果未知时不能自动重复操作。
- **安装器/Windows E4 验收**：实际选盘、独立用户数据根、少量系统盘例外清单、目录权限、中文路径、失联/占用、崩溃后的离线诊断定位、卸载留数据和重装接回均须真实验证，不能只凭“EXE 能启动”宣布通过。

## 11. 与仓库分工及实施安排

- `UI/`：四列容器、视图装载、状态展示、辅助窗口、布局交互；不负责实现文件系统、权限、聊天或任务业务。
- `views/`：视图配置/映射等既定职责；UI 不另建同一份业务事实。
- `space/`：Space 类别、Space、Group、Context、地址关联权威规则。
- `conversations/`：Conversation、消息与生成事实；UI 只呈现、编辑入口与当前选择。
- `connections/api`、`connections/local`、`connections/github`：各自协议/能力和资源操作；`connections` 维护通用 Operation；`permissions` 负责有效授权；`app` 提供受控桌面 IPC 和平台能力。
- **工程时序**：本文件属于 B3 UI 细化设计输入，不视为 B1/B2 已完成证据。施工前以最新 main、正式 B3 任务、模块 README、真实代码和测试为准；没有明确接口支持时先留下界面能力的不可用状态，不能用假的成功结果冒充功能闭环。

## 12. 初步验收清单（待纳入正式 B3 任务时逐项核对）

1. Space 类别以纵向按钮切换；用户自定义类别；Group 与 Space 类别不混淆。
2. Context 添加源码、设计资料和对话视图；切换后第二列/第三列对应变化；移除视图不丢文件。
3. 拖动三条竖向分隔线、第四列横向分隔线，重启恢复合理尺寸。
4. 第三列只读打开的文件被获准 AI 修改后出现更新反馈和最新内容；可看差异。
5. 第三列有本地未保存编辑时，AI/外部修改不能静默覆盖草稿。
6. 真实文件状态与 AI 操作回执失败/未知分别呈现。
7. 文件颜色标记有状态维度、文字、来源，不能把 Git 修改等同验收。
8. 第四列默认：上 Context、中执行记录、下对话；用户可换内容、`+`/`−`窗口、折叠和重排。
9. 第四列对话展开占满该列，再收回原布局；消息和草稿不断裂。
10. 主对话和文件对话用标题+地址区分，仍靠稳定 Conversation ID 恢复历史。
11. 对话输入支持 `+` 附件入口和 `@` 引用目标选择，发送时验证来源和授权。
12. 语音输入入口及不可用/失败状态清晰；真实语音实现深度单独验收，不以按钮存在视为语音可用。
13. 底部扩展区展开/向下收起；UI 收起/关闭不能删除 Conversation 或终止执行。
14. Windows 窄窗口、高清缩放、重启、失联、撤权、编辑冲突、异步变更至少有明确可复现反馈。
15. 第一列最左下角显示上方设置按钮和下方角色窗；图片/GIF 可增删排序、轮播、暂停与恢复，重启保留配置。
16. 第一列折叠后角色可在主窗口第二列底部/相邻底部区域合理安置，不遮挡目录或按钮；设置入口仍可见，用户主动隐藏角色后不被折叠事件强制恢复。
17. 不创建 Context 也能进入普通对话；切换对话时第二列列表与第三列完整消息同步，且旧异步结果不污染新会话。
18. 第三列可在文件、Context 详情、模块配置和完整对话之间切换；不复制各模块业务事实，不以假表单宣称底层可用。
19. API/Agent/权限/Connections 从设置或明确对象入口到达，能操作/拒绝/显示原因；授权 UI 明示真实范围且不会因对象选择自动授予权限。
20. 首次数据根选择与重启接回显示实际状态；失败/未知保留原关联及草稿，不自动重复高风险写入。
