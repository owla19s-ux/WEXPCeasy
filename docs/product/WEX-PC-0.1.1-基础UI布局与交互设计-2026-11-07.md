## 1. 定位与版本边界

0.1.1 采用**四列横向布局**：① Space / Context 导航；② 当前视图的结构/目录；③内容展示与编辑；④可配置的纵向辅助窗口。底部另设可向下收起的扩展区。

- 四列分隔线可调整宽度；第四列内部窗口可调整高度；必要时隐藏/恢复辅助列，布局配置可保存与恢复。
- 固定列结构、内容类型切换和基础多视图属于本草案；**任意自由拖拽重排、完整自由格子工作流、正式调度器等不在 0.1.1**，仍按计划后置。
- **显示工作流内容不等于启用工作流引擎**：如有已有、获准的节点或阶段资料，可提供只读展示；没有真实状态时不得显示伪造的“运行/成功”。
- 图形结构为桌面宽屏优先的起点，列宽百分比和像素最小值尚未冻结，需在真实 Windows 窗口和不同 DPI 上验证。

## 2. 基础结构

```text
┌──────────────┬────────────────────┬─────────────────────────┬──────────────────────────┐
│ ① Space      │ ② 当前视图结构区    │ ③ 文件/对象内容区        │ ④ 辅助区（纵向窗口）      │
│   个人       │ 源码/资料目录树     │ 当前文件内容、编辑器      │ 上：Context/当前对象      │
│   工作       │ 搜索/状态筛选       │ AI 修改的同步反馈         ├──────────────────────────┤
│   公开       │                    │ 文件标签、Diff           │ 中：执行/输出/回执        │
│              │                    │                         ├──────────────────────────┤
│ Context      │                    │                         │ 下：对话（默认）          │
│  视图列表    │                    │                         │ 可展开占满整个第四列      │
│              │                    │                         │ + / − / 内容下拉选择      │
│ 设置（底部） │ 底部快捷视图切换   │ 文件状态/操作栏          │                          │
├──────────────┴────────────────────┴─────────────────────────┴──────────────────────────┤
│ 底部可折叠扩展区（默认收起，范围/内容与具体接线方式后续实测）                         │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 第一列：Space 类别与 Context 导航

- **Space** 下默认纵向显示“个人 / 工作 / 公开”三项。这三项是**Space 类别**，而不是 Group，也不是三个具体 Space；点击类别直接切换，不展开成分类文件树。
- Space 类别支持添加、重命名、修改、删除；类别下具体 Space、可选 Group、Context 仍遵守已有独立业务概念。删除带有对象的类别时如何迁移/阻止删除按 Space 正式规则，不由 UI 猜测。
- 下方 **Context** 导航展示当前选中范围和关联的多视图入口。可添加、移除、命名视图；移除视图不删除 Context、地址、实际文件或 Conversation。
- 左下角固定**设置**，不随内容滚动消失。
- 具体 Space 和 Group 的呈现需与现有 Space 模型一致；本草案不引入 Placement 实体，也不把类别直接当 Context 父对象。

## 4. 第二列：视图结构、目录树与状态

- 根据当前 Context 视图切换结构内容：源码目录树、设计资料目录树、必要的对象列表等。
- 展开/折叠子目录、选中文件、搜索、筛选、刷新；目录数据必须经获授权资源连接器读取，不让 Renderer 直接任意访问磁盘。
- 第二列下方有**多视图快速切换栏**，对应当前 Context 中实际配置的视图，允许添加/移除/切换。新建“设计资料”视图时，从 Context 已有的“名称、地址、备注”多地址条目中选择目录绑定；不强制创建单独资料系统或把设计文件搬进源码仓库。
- 文件/目录状态标记使用绿、黄、橙、红、灰/黑五种颜色，但**颜色必须有状态维度和来源**：建议绿=该维度通过，黄=进行中/待确认，橙=需核查，红=失败/阻塞，灰/黑=未设置/未知。Git 工作树变化、人工工作状态、测试/验证结论、正式验收互不等价；不能用一次 Git 提交推断文件通过验收。
- 显示标记时应有文字或图标辅助；悬停/点击能看到状态类型、来源、更新时间、关联证据。目录汇总必须提示重要子项风险，不简单平均为绿色。
- 文件状态可手工设置，但手工状态与真实工具/测试结果需有可辨识来源。0.1.1 的完整状态模型和数据 owner 须与现有正式契约核对，不在 UI 中私建业务权威账本。

## 5. 第三列：内容浏览、用户编辑与 AI 文件修改同步（重点）

第三列显示第二列选中的文件/对象内容，支持文本查看、选中、查找、文件标签、用户编辑与保存、复制路径、选区引用。源码、设计资料和施工文档可以复用编辑交互，但各文件的存放地址、权限和用途保持独立。

**必须保证：用户正在看的文件与 AI 经授权修改的实际文件不能长期显示两个互相矛盾的版本。**

### 5.1 状态场景

| 场景 | 界面行为与保护 |
| --- | --- |
| 用户只读查看，AI 修改并成功落盘 | 监听或收到变更提示后重新核对真实内容版本；更新展示并提示“文件已更新”，可打开 Diff；尽量保持滚动/选择位置 |
| 用户正在输入，存在未保存的编辑缓冲区 | **不能无条件热重载覆盖用户内容**；提供磁盘新版、用户草稿、差异比较，以及保留/重新加载/合并入口 |
| AI 与用户同时请求写同一文件 | 写入侧仍按文件版本和有效授权防覆盖；“编辑不同段落”不自动等于安全合并 |
| AI 操作报告成功，磁盘未核对 | 不标作已更新且已验证；重新读取实际状态，再决定显示 |
| AI 请求失败、超时或结果未知 | 保留原 Operation/回执，文件实际状态单独核对，不能因失败回复就断言磁盘未变 |
| 外部编辑器或 Git 操作变更文件 | 同样应检测，避免只监听 WEX 内部操作；丢失监听事件时可主动刷新核对 |
| 文件删除、移动、权限撤销、路径失联 | 清晰提示，不覆盖草稿、不读取未授权内容，保留可恢复的当前 UI 信息 |

### 5.2 实现与验收建议

- 组合使用文件监听、内部受控写入通知、版本/哈希校验、主动刷新、Diff 与冲突处理；文件监听不是唯一可信事实源。
- 原始文件身份/路径、已载入磁盘版本、编辑缓冲版本、当前真实版本和最后操作回执应可区分。
- UI 反馈区分**已读取最新文件**、**AI 操作已报告成功**、**测试通过**和**人工验收**。
- 接线必须通过 Local/Connections、App/IPC、Permissions 的正式边界，不用 React 直接改业务文件，不因页面打开授予 AI 写权限。
- 自动合并、跨工具占用协同及复杂冲突解决尚需细化；0.1.1 至少做到：检测变化、禁止静默覆盖、明确冲突与手动恢复入口。编辑器是否采取自动刷新、何时合并需用真实文件场景验证。

## 6. 第四列：可增减、可选内容的纵向辅助窗口

### 6.1 默认位置（本轮已明确）

1. **上窗口：Context / 当前对象信息**
2. **中窗口：执行记录 / 输出 / 回执**
3. **下窗口：AI 对话**（默认位于**最下面**，不默认在中间）

用户可以通过每个窗口顶部的内容选择框，将其换为“文件信息、引用资料、对话、执行记录、Context 信息、空白”等已有受支持的内容，亦可交换中下窗口用途。

### 6.2 窗口操作

- `+`：在指定位置增加窗口；`−`/`×`：移除选定显示窗口，而不是删除业务对象。
- 每个窗口可折叠、展开，分隔线可调整高度；窗口顺序可调整，数量不固定为 3。
- 对话窗口可点击**展开/最大化**，**临时占满整个第四列**；其他辅助窗口仅临时收起/隐藏，返回后恢复原来的次序、高度、内容和滚动状态。
- 对话单独切换为主视图时应允许更大内容空间；第四列中的同一对话不因此复制 Conversation。
- 窗口多于可容纳高度时提供合理的折叠、滚动或最小高度保护；防止操作入口被挤没。
- 关闭/切换辅助窗口不停止后台网络或工具执行、不删除原始 Conversation/Operation，也不擅自丢弃输入草稿；UI 须处理未保存输入的提示。
- 布局配置持久化并支持恢复默认值，不能把显示配置误当作授权。

## 7. 辅助对话：身份切换、输入操作与语音

### 7.1 主对话与对象对话

0.1.1 先用**对话标题 + 关联目录/文件地址**作为可读识别：主对话标注 Context 名称，对象对话显示标题及对应地址。真正的记录关联仍靠稳定 Conversation ID，同地址可以关联多场对话。

- 可从下拉列表切换，恢复各自消息历史、滚动位置和输入草稿（以真实可支持状态为准）。
- 打开不同文件时，可以提示“打开该对象对话”；**不默认每点一个文件就新建对话**，也不应无提示切换打断当前输入。
- 新对象对话不自动继承主对话全部聊天历史；需要的 Context 文档通过获准引用/读取。Provider Prompt Cache 是性能优化，不是 WEX 持久知识权威。
- 同一个 Conversation 的辅助显示与主视图显示共享业务身份，不各自持有不一致的消息副本。

### 7.2 对话输入栏

必须预留以下明确入口：

- **文本输入、发送、停止/取消当前生成**；展示流式状态与失败/未知。
- **`+` 添加文件/附件**：调用受信任文件选择、支持来源和预览、移除、必要时拖入/粘贴；临时附件不自动成为 Context 长期资料。用户已选择的本地路径不等于 AI 可自由读取或上传，提交前仍需按权限与范围核对。
- **`@` 引用**：选择当前文件、选中文本、Context 已关联资料、目录/对象等可引用目标；插入可见引用标记，用户能删除或检查。引用对象的元数据与真正发送给模型的内容需区分；不能绕过权限自动传出整份文件。
- **语音对话入口**：输入栏显示麦克风按钮，支持开始/结束、识别中、识别结果确认/编辑和发送状态；权限拒绝、麦克风不可用或识别失败有明确反馈。
- 语音的实际识别 Provider、TTS、实时双向语音和持续收音能力**不在本文中擅自定为 0.1.1 已实现或必需全部能力**；0.1.1 应至少在 UI/IPC 层保留清晰入口与禁用/不可用说明，真实语音输入深度对照版本计划及技术验证再定。
- 对话输入同时支持模型/Agent 切换入口，但选择不自动提升权限、修改已派发请求的身份。

### 7.3 对话展开行为

对话从第四列下窗口展开占满第四列时：
- 同一个 Conversation ID、同一生成状态、同一草稿、附件与引用；
- 输入栏仍位于对话区域底部，消息列表独立滚动；
- 收起后恢复原第四列三段或用户自定义布局；
- 不把展开误当成新建主对话，不触发重发或自动重新执行工具。

## 8. 底部扩展区

- 红框对应区域采用**默认收起、可向下收起/向上展开**的底部辅助区域；支持展开高度调整与状态恢复。
- 适合搜索结果、日志、临时输出与引用检查等辅助内容；不应把核心导航或主要 Conversation 强制塞入此处。
- 第二列底部多视图快速切换与第三列文件状态/操作栏各有明确职责；是否将底部扩展区横跨第 2～4 列、与各列底栏如何衔接，需按正式屏幕宽度实验，不先写死跨列占用。
- 底部收起不影响任务/工具运行。

## 9. Context 地址、资料和界面映射

- 复用 Context 既有主地址及多个附加地址（名称、地址、备注）；这些地址可以对应本地目录、GitHub 主仓、参考文档、产出地址等，不能强行合并为唯一工作目录。
- 用户选择其中一个目录，在 Context 多视图中添加“设计资料”，即可浏览/编辑资料。**不要求现在建设独立资料管理系统**。
- 设计/研究草案与源码施工资料逻辑分离；以 WEXPCeasy 现有源码/模块文档为参考，但不强制把探索性设计资料放入源码目录。
- 用户可以直接编辑资料；AI 可提出更新建议并在有效授权下写入。未经确认的猜测不得无标注地写成正式设计；文件不是聊天的自动副本。
- 视图只是某目录/对象的呈现，移除视图不得移动或删除真实资源。

## 10. 持久化、异常与可用性

建议保存并恢复：四列宽度、隐藏状态、当前 Space 类别/Context、视图配置、第二列展开状态、第三列打开文件和编辑草稿、第四列窗口数量/顺序/类型/高度/折叠/最大化状态、当前 Conversation ID 与输入草稿、底部扩展区状态。具体数据 owner 与持久化结构按现有模块契约核对，不在此冻结 schema。

异常覆盖：
- 重启后资源失联、地址变化、撤权；
- 变更事件丢失、异步回执迟到、重复通知；
- 用户草稿与 AI/外部写入冲突；
- 多列缩到极窄、窗口 DPI/分辨率变化；
- 关闭/切换对话但生成仍进行；
- 语音设备不可用、上传/引用失败、Context 引用无读取许可；
- 视图所引用的工作流数据不存在时只显示空态，不假报状态。

## 11. 与仓库分工及实施安排

- `UI/`：四列容器、视图装载、状态展示、辅助窗口、布局交互；不负责实现文件系统、权限、聊天或任务业务。
- `views/`：视图配置/映射等既定职责；UI 不另建同一份业务事实。
- `space/`：Space 类别、Space、Group、Context、地址关联权威规则。
- `conversations/`：Conversation、消息与生成事实；UI 只呈现、编辑入口与当前选择。
- `connections/api`、`connections/local`、`connections/github`：各自协议/能力和资源操作；`connections` 维护通用 Operation；`permissions` 负责有效授权；`app` 提供受控桌面 IPC 和平台能力。
- **工程时序**：本文件属于 B3 UI 细化设计输入，不视为 B1/B2 已完成证据。施工前以最新 main、正式 B3 任务、模块 README、真实代码和测试为准；没有明确接口支持时先留下界面能力的不可用状态，不能用假的成功结果冒充功能闭环。

## 12. 初步验收清单（待纳入正式 B3 任务时逐项核对）

1. Space 类别以纵向按钮切换；用户自定义类别；Group 与 Space 类别不混淆。
2. Context 添加源码、设计资料和对话视图；切换后第二列/第三列对应变化；移除视图不丢文件。
3. 拖动三条竖向分隔线、第四列横向分隔线，重启恢复合理尺寸。
4. 第三列只读打开的文件被获准 AI 修改后出现更新反馈和最新内容；可看差异。
5. 第三列有本地未保存编辑时，AI/外部修改不能静默覆盖草稿。
6. 真实文件状态与 AI 操作回执失败/未知分别呈现。
7. 文件颜色标记有状态维度、文字、来源，不能把 Git 修改等同验收。
8. 第四列默认：上 Context、中执行记录、下对话；用户可换内容、`+`/`−`窗口、折叠和重排。
9. 第四列对话展开占满该列，再收回原布局；消息和草稿不断裂。
10. 主对话和文件对话用标题+地址区分，仍靠稳定 Conversation ID 恢复历史。
11. 对话输入支持 `+` 附件入口和 `@` 引用目标选择，发送时验证来源和授权。
12. 语音输入入口及不可用/失败状态清晰；真实语音实现深度单独验收，不以按钮存在视为语音可用。
13. 底部扩展区展开/向下收起；UI 收起/关闭不能删除 Conversation 或终止执行。
14. Windows 窄窗口、高清缩放、重启、失联、撤权、编辑冲突、异步变更至少有明确可复现反馈。

## 13. 尚未冻结的事项

- 底部扩展区的最终跨列范围及与第二/三列底栏的衔接方式。
- 文件编辑器选型、可验证的监听/冲突合并实现及跨进程改写协调方案。
- 对象对话“选中文件后自动切换”是否作为用户可选偏好。
