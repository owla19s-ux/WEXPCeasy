## 0. 2026-11-07 UI 结构更正（优先级最高）

本文件为**底层业务能力 → 公开接口/受控 IPC 与 UI 适配 → 用户 UI 入口**的功能映射跟踪文档；不能将结构草案中的未来功能直接认定为当前实现。完整结构见 [基础 UI 布局与交互设计 V0.4](WEX-PC-0.1.1-基础UI布局与交互设计-2026-11-07.md)。

本轮结构已经调整，旧表中“始终独立第二列/第三列”“第四列默认三段展开”“角色内嵌第一列”“底部固定扩展区”等旧描述**不再有效**。映射表里的 U 项仍用于跟踪业务入口，不等于旧空间布局被批准。

- ① Space 类别顶部三个**横向并排的竖形按钮**，下方 Space/Group?/Context 与独立普通对话；导航可窄化或完全隐藏。
- ②＋③ 是**一个共享工作窗口**：默认显示完整当前视图，第三列**不默认独立出现**；打开文件等具体对象时旁侧分出预览/编辑区，当前视图及其目录状态保留，关闭预览后恢复完整视图。用户主动双视图并排/展开与默认点击不同。
- 当前 Context 的**浏览器式视图标签栏位于第二列视图区域底部**，默认首项 **Context 配置/项目配置**（基本信息、Context ID、主地址及命名附加地址、能力关联等由真实 owner 供给）；用户可管理其他视图。首项能否移动/移除待确定。
- ④ 右侧辅助区**默认收起，具体内容暂不施工**，旧版“默认上 Context、中回执、下对话”仅是过时方案；对话入口不能依赖该区域。
- **交互栏**与**虚拟形象**独立但联动：栏收起形象自由悬浮；点击形象展开栏并回到栏内相对位置；栏内可连续拖动形象；自由悬浮位置与栏内位置分别保存。底栏与视图标签栏不是一回事。
- 桌面级虚拟形象悬浮模式为**后续独立设计**，点击不默认恢复完整主窗口；栏未来可换上/左/右，但本轮不实现全部方向。
- 未来功能表、架构树、功能状态高亮、跨视图关联/双视图布局作为**兼容性方向**；不能把未来场景塞进 0.1.1，也不能将 UI 状态冒充真实测试或验收结果。

### 工作节奏

先收口 UI 基础交互，再逐页接入和验收；不要求此刻展开 216 项全量功能核验，也不因为设计一项未来场景而扩展正式版本范围。后续每页对照 owner、接口/IPC、UI 操作和测试证据增量审查，避免出现有 UI 无能力或有能力无入口。

## 0.1 Windows 窗口、尺寸与交互适配（2026-11-07 增补）

- 顶层窗口优先采用 Electron/Windows 原生标题栏和边框，提供最小化、最大化/还原、关闭、移动、缩放及 Windows Snap；不把 Win+方向键、Win+Z 分屏当作 WEX 自造功能。
- 内部布局自主实现。②＋③ 默认完整视图、打开文件按需出现预览；宽度不足时按实际空间调整/降级，不让旧四列永久最小宽度逼出不可访问内容。
- **保留既有可拖动列分隔线**：导航/工作区、动态预览分栏；第四列将来展开后亦能调整。键盘调节、边界、恢复默认与保存偏好要验证。
- 视图与布局偏好分离于实时的可用宽度计算；系统缩放、高 DPI、Windows 仅放大文字、双显示器及设备拔插后不得丢失草稿或把窗口恢复到不可见位置。
- 普通窗口、最大化、半屏/四分屏、不同 DPI、文字增大、分隔线拖动与恢复、焦点/菜单边界和异步切换需分级实测；完整矩阵见 [布局设计 V0.6 §15](WEX-PC-0.1.1-基础UI布局与交互设计-2026-11-07.md#15-windows-原生窗口自适应与分隔线验收补充2026-11-07)。
- 这是 B3 的必要 UI/Windows 兼容验收约束，**不授权**提前开发复杂双视图 Docking、独立桌面级虚拟形象或第四列完整辅助功能。

## 1. 两层分离与六问强制规则

**四列只规定空间结构，功能还需要一层独立 UI 映射。** 不得拿四列图直接替代每个 0.1.1 功能的界面需求。任何新 UI 功能都要从正式 F 功能与 I 交互语义回溯到唯一业务 owner，不能仅凭界面构想制造模块、页面、实体、表或权限。

对于每个进入 0.1.1 B3 施工的**用户可操作功能**，UI 映射必须明确六件事：

1. **入口在哪里**：列/面板/设置页/菜单/弹窗、从哪个对象到达；普通对话等独立入口须能脱离 Context 访问。
2. **用户怎么操作**：新建、查看、编辑、选择、关联、确认、撤回等准确的交互意图，区分引用与执行。
3. **调用哪个模块**：唯一权威 owner、公开端口与必要的 app 可信 IPC；模块专属表单随 owner，UI 容器负责挂载。
4. **权限怎么确认**：真实可信入口、当前主体/资源/动作/范围；审批由 permissions 决定，选择或可见不等于获权。
5. **结果在哪里显示**：就近反馈及必要的第四列状态/Operation 回执，区分已提交、失败、取消、未知、过期。
6. **失败如何恢复**：保留用户输入、重读当前修订/原 Operation、撤权或失联空态、谨慎重试；未知副作用不得直接重复发起。

非用户直接操作的内部能力，标记“内部，无直接按钮”，仍在相应流程显示必要状态；未来能力标“延期，不创建假入口”。映射是 **F → I → U → Owner → 权限 → 证据/恢复**，不等于 F 与按钮一一对应。

**验收门槛**：每项至少有正向操作、拒绝/无权、失败/未知或中断恢复的可重现交互断言；未接入业务端口时明确不可用，不能用假数据/纯 UI 成功冒充功能实现。

| U20 全局操作反馈（横跨 F01–F15；I02/13/16） | 发起操作处就近反馈 + 必要全局轻量通知/第四列详情 | 看成功/拒绝/取消/超时/提交未知、查看详情与恢复 | UI 展示；原领域 owner 提供事实；app IPC | 通知点击重新判权，不泄漏撤权内容 | 提交确认≠等待确认；异常保留关联、草稿和追查入口 |

### 3.1 不提供独立按钮的内部能力

- 模型流式片段拼装、参数协议映射、凭证加密、权限决策引擎、CAS、文件监听、Operation 去重、日志轮转、恢复一致性检查等归各 owner；**UI 仅呈现必要观察及失败动作**。
- 自动路由、成本/限额、备用模型、网络代理等 F04/F05 条目若 0.1.1 正式范围或 owner 未确认完整能力，不自动生成可用开关；可以在已确认的配置页提供真实可用字段或显式禁用状态。
- F07/F08/F12/F13 中的完整工作流、正式任务调度/验证账本、插件及复杂审批链不因第四列已有“执行/回执”窗口而视为首版可运行。
- 需求树、功能树、架构网图、多 Context 多窗口自由重排、复杂对话分支、语音结构操作、桌面宠物动作、独立系统悬浮窗、快捷键系统均按原定后续研究。未来快捷键配置位置在设置，不增角色旁快捷键入口。
- **历史总表的 F01-007 “多处放置”不授权创建 Placement 业务实体**；以当前 Space/Context 正式契约、用户已确定的组织关系为准。不能用旧词自行设计新增实体。

## 4. 页面/面板信息架构收口

### 4.1 第一列：全局入口和空间组织

- 三个初始 Space 类别是顶部横向并排的三个竖形按钮；导航下方 Space → 可选 Group → Context。普通对话独立可访问。
- 第一列可窄化或完全隐藏；虚拟形象不内嵌本列，不因隐藏本列而消失。设置入口独立于媒体展示和交互栏。

### 4.2 第二、第三列：共享工作窗口与按需预览

- 默认以完整空间显示当前选中的 Context 视图；底部浏览器式视图标签栏首项为 **Context 配置**，其余视图按真实能力可配置。
- 源码/资料视图点击具体文件 → 旁侧出现文件预览或编辑子窗，原视图目录、导航状态不被替换；关闭预览恢复完整空间。
- 视图标签管理**视图**；第三列可能存在的文件/对象标签管理**打开的内容对象**。两类标签、关闭语义及状态持久化彼此独立。
- 用户主动并排两个完整视图、展开视图、关联定位是未来布局扩展；无须此刻施工复杂多窗格。
- Context 配置默认页及其真实地址/工具/Agent 关联入口不可遗漏，不等于在 UI 创建新的领域对象或权限。

### 4.3 第四列：默认收起的辅助容器

- 目前仅保留展开能力与布局预留，不指定上中下三段内容。原三段辅助窗是历史讨论，不是本版施工任务。
- 主工作区/独立普通对话需在第四列关闭时完整可用。

### 4.4 虚拟形象与交互栏：两个独立对象

- 页面内交互栏收起时，形象在窗口内部自由拖动；点击可展开栏并回位；展开时形象在栏内**连续移动**；保存两个位置。
- 栏未来可由底部移到上/左/右，但本轮不要求四方向实现。形象与交互栏都不占用第二列底部浏览器式视图标签身份。
- 主窗口最小化后仍存在的 Windows 桌面级形象悬浮属于独立未来模式；点击后**不默认打开整个工作页面**，行为另行设计。

### 4.5 PC 设置页：左侧大类/小类、右侧详细设置（已确认）

**PC 版不是手机整页上下折叠列表**。设置由第一列左下独立按钮进入，在主操作区使用双区结构：**左侧可展开的两级分类导航，右侧当前小类完整配置、添加和编辑**；左右各自纵向滚动。点击左侧大类展开/收起其小类，点小类更新右侧详情；右侧复杂表单可以自行分组折叠，不强制跳转独立 Windows 窗口。返回主工作区保留有效的原视图焦点与未提交草稿保护。

**沿用旧 WEX 已明确的四个一级分类**（参照 [WEX 历史设置页](https://github.com/owla19s-ux/WEX/blob/main/docs/UI/WEX-ANDROID-SETTINGS-BASELINE.md)）；历史八组只是旧阶段表现，不再把文件、外观、执行、日志当作新的一级分类：

| 左侧大类 | 左侧小类建议（按已确认能力展示） | 右侧实际配置 / owner |
| --- | --- | --- |
| 连接与服务 | API/模型、Agent/角色、GitHub、Local/工具、连接状态 | 各模块专属连接配置/Agent 角色组合、凭证受信录入、测试、启停；由 connections/api、AI、github/local 等 owner 负责 |
| 权限 | 模块启用、全局访问、对话权限与操作审批 | 当前有效作用域、授权/撤权/拒绝；由 permissions 与可信 app 入口负责 |
| 验证 | 能力测试、连接诊断、可用性核查 | 展示检测范围、真实结果和来源；不把连接测试当 Task Verification 或 Acceptance |
| 系统 | **程序/用户数据目录**、**工具环境目录**、显示与角色窗、日志与故障诊断、版本与应用状态 | app/shared 的技术路径与生命周期、UI 布局/媒体、按 owner 脱敏诊断 |

- 小类是 **UI 导航** 而非新模块；没有实际能力不显示假成功开关。接口仍依[F/I/U 六问](#1-两层分离与六问强制规则)对齐。
- 凭证与操作审批不能因处于同一设置页而混为一项权限；对话已选择模型不能因更改全局默认值被静默覆盖。
- 快捷键系统只保留后续统一纳入设置的方向；**0.1.1 不开发、不加独立快捷键按钮**。

### 4.6 内容与面板切换最小方案

| 切换层次 | 用户行为 | 不应触发 |
| --- | --- | --- |
| 第一列工作范围 | 切换 Space/Context 或进入独立普通对话 | 新建/删除业务实体、隐式改变许可 |
| 第二列对象 | 切换目录、文件、对话或获准对象 | 文件写入、启动任务 |
| 第三列主内容 | 用轻量标签切换已打开文件、对象详情、配置和完整对话；关闭当前标签 | 删除 Context/Conversation、停止 AI 生成 |
| 第四列辅助面板 | 每个面板单独切内容类型、折叠/展开和高度；对话可占满再恢复 | 新建 Windows 顶层窗口、覆盖其它业务状态 |

在标签与视图切换时保护未保存编辑、清理过期订阅；迟到的旧请求不能覆盖新 Context/Conversation。0.1.1 不要求 VS Code 式编辑器分组、自由拖拽、独立多窗口组织或复杂浮动系统。

### 4.7 Windows 目录与离线维护 UI（历史需求恢复）

依据 [Windows 数据与安装要求](../architecture/SOURCE-LAYOUT-AND-WINDOWS-DATA-2026-10-30.md)及[Windows 生命周期研究](../research/WINDOWS-LIFECYCLE-2026-10-31.md)：

| 管理对象 | 用户入口与操作 | 安装/恢复原则 |
| --- | --- | --- |
| 程序安装目录 | EXE 安装时选择；设置→系统查看已安装位置 | 与用户数据分开；更新/卸载不默认删除用户数据 |
| 公共用户数据根 | 安装/首次必要初始化时选择或接回；设置→系统查看、受控迁移 | 配置/索引/日志与可控缓存优先归此；目录内有非秘密识别信息，不依赖 C 盘唯一索引 |
| 工具与开发环境目录 | 设置→系统→工具环境位置，选择/关联现有工具链、SDK 与工具资源 | **独立可配置位置**，不强制首次配置或自动安装；具体环境部署能力依工具模块的正式范围核验 |
| Space/独立 Context 实物目录 | 创建或关联时使用受控目录选择 | 可在任意获准位置，主地址、附加地址、产出、参考资源不强制搬到公共根 |
| 外部代码/资料/仓库 | Context 资源及对应连接器入口 | 保留原位置和真实 owner；引用不等于复制/授权 |
| 崩溃日志与诊断 | 设置→系统→日志与故障诊断；**WEX 无法启动时允许外部工具按已知路径离线定位** | 可读取必要安装文件、版本/模块信息、脱敏日志、崩溃诊断及路径说明；不能把普通日志当权威 Operation |

**尽量减少 C 盘占用，不承诺系统盘零写入。** Electron 的 `userData/sessionData`、崩溃转储、缓存、更新 staging、Windows 凭证/系统集成例外必须列实际写入清单并以 Windows 实机验收。启动前数据根定位要解决 Electron `ready` 时序，不能假设运行后随时修改 sessionData 即生效。

**“程序坏了还可以看文件”不等于打包后自动可修改 TypeScript/React 源码**。正式包可能采用 ASAR；原始源代码/Source Map/开发诊断包、外部修复/热更新属于需另行评估的可维护性机制，0.1.1 仅保证有可检查、可定位的安装产物和诊断依据，不凭空承诺源码热改。

**不做欢迎页/教程/演示类首次引导**。但安装目录选择、必要数据根选择与路径/权限/兼容错误的最小修复必须存在；工具环境目录可随后在设置配置。正常重启/升级与系统重装必须分别处理，重装不能继承旧有效授权及凭证；卸载默认保留用户数据，未知外部副作用不自动重复派发。

## 5. 跨页面状态反馈的统一设计约束

| 业务结果 | UI 应如何表达 | 禁止 |
| --- | --- | --- |
| 本地输入未提交 | 草稿/待保存，允许取消编辑 | 仅因点击按钮显示“已保存” |
| owner 确认提交 | 显示已保存及新修订/可读回证 | 以表单局部 state 充当正式权威 |
| 被拒绝 / 撤权 | 提示无权与允许的配置/重新申请入口 | 缓存继续展示撤权后的敏感内容 |
| 已取消 | 区分请求取消与真实外部停止 | 把取消当外部操作已回滚 |
| 未派发 / 明确失败 | 精确错误并保留输入 | 自动继续重试高风险副作用 |
| 已派发但结果未知 | 标“待核对”，保留 Operation/intent 原关联，允许查询 | 点击重试自动发第二次写入/提交 |
| 来源失联/过期/部分读取 | 显示来源、观察时间、可用范围及重新连接入口 | 把旧缓存写成最新成功 |
| 版本冲突/外部修改 | 展示磁盘版与用户草稿、Diff/人工处理 | 自动覆盖未保存用户编辑 |
| 切换 Context/Conversation/视图 | 取消过期 UI 订阅，保留未完成请求的真实归属 | 把晚到旧请求显示为新对象的结果 |

审批、保存、撤销、重试/恢复、日志与真实验收分别受其 owner 约束；全局提示是导航线索，不是新的事实来源。

## 7. 必须收口的设计决策与不需要现在决策的事项

**本节历史条目如与 §0/§2/§4 冲突，以本轮更正为准。UI 行为已明确，可作为设计基线（不代表实现完成）**
1. 第一列为导航；第二、第三列为**共享工作窗口**，默认完整当前视图、打开对象才出现旁侧预览/编辑；第四列默认收起。
2. 普通对话独立于 Context/Task；对象选择、引用、采纳、授权、真实执行和验收是不同动作。
3. 设置入口独立可达，PC 设置左侧大类/小类、右侧详细配置；虚拟形象独立悬浮并可联动交互栏，不内嵌第一列。
4. UI 不保存业务权威状态；任何状态展示必须有来源、修订或可回读依据，未知状态不自动重派。

**需真实 UI 试排/用户另议，不得擅自冻结**
1. 虚拟形象自由悬浮和交互栏相对位置的默认尺寸、位置约束及动画细节；桌面级悬浮交互另行设计。
2. 第二列对象就近菜单的具体交互方式、第三列配置页返回与草稿保存细节。
3. **欢迎/教程式首次引导已明确不做**；保留安装与必要数据根选择、异常修复。设置左侧两级、右侧详细配置已确定，小类精确排序/内部路由与安装器技术仍待真实验证。
4. 轻量主内容标签与第四列独立面板切换已明确；对象对话自动切换、同时打开多个 Context 的 Windows 顶层窗口组织、右侧最多面板数、语音接入深度仍待定。
5. 未确认的资源导入/删除策略、高危操作授权边界、文件自动合并规则仍由正式 owner/用户决策，不因 UI 评审默认批准。

**明确非本轮施工**
- 0.1.2 的自由格子工作流、正式调度器、DSH 插件/连接器；高级桌面角色、独立 Windows 悬浮、快捷键系统、完整跨对象分支与复杂多 Agent 并发工作台，均不增加到 0.1.1。

## 8. 给 B3 施工和验收的最小检查规程

1. 从当前 owner 的 README/公开端口核对真实可用能力，再定位本映射表 U 项；本表**不能代替正式 B3 任务**。
2. 每个 U 项至少记：F/I 依据、入口、用户交互、owner/公开 IPC、授权方式、成功/失败/未知反馈与恢复、当前实现位置、真实测试证据、是否延期。
3. 状态使用：**已接线并验收 / 有代码未完整接线 / UI 设计已定未实现 / 未冻结待决 / 正式延期**，不混淆模块单测与 Windows E4。

6. 不因为映射表建议某个按钮/窗口，就自行创建新页面层级、数据结构、业务模块、Placement 实体、权限等级或未确认版本能力。
