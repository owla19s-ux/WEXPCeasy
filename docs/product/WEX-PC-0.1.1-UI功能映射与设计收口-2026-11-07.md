## 1. 两层分离与六问强制规则

**四列只规定空间结构，功能还需要一层独立 UI 映射。** 不得拿四列图直接替代每个 0.1.1 功能的界面需求。任何新 UI 功能都要从正式 F 功能与 I 交互语义回溯到唯一业务 owner，不能仅凭界面构想制造模块、页面、实体、表或权限。

对于每个进入 0.1.1 B3 施工的**用户可操作功能**，UI 映射必须明确六件事：

1. **入口在哪里**：列/面板/设置页/菜单/弹窗、从哪个对象到达；普通对话等独立入口须能脱离 Context 访问。
2. **用户怎么操作**：新建、查看、编辑、选择、关联、确认、撤回等准确的交互意图，区分引用与执行。
3. **调用哪个模块**：唯一权威 owner、公开端口与必要的 app 可信 IPC；模块专属表单随 owner，UI 容器负责挂载。
4. **权限怎么确认**：真实可信入口、当前主体/资源/动作/范围；审批由 permissions 决定，选择或可见不等于获权。
5. **结果在哪里显示**：就近反馈及必要的第四列状态/Operation 回执，区分已提交、失败、取消、未知、过期。
6. **失败如何恢复**：保留用户输入、重读当前修订/原 Operation、撤权或失联空态、谨慎重试；未知副作用不得直接重复发起。

非用户直接操作的内部能力，标记“内部，无直接按钮”，仍在相应流程显示必要状态；未来能力标“延期，不创建假入口”。映射是 **F → I → U → Owner → 权限 → 证据/恢复**，不等于 F 与按钮一一对应。

**验收门槛**：每项至少有正向操作、拒绝/无权、失败/未知或中断恢复的可重现交互断言；未接入业务端口时明确不可用，不能用假数据/纯 UI 成功冒充功能实现。

## 2. 四列的职责收口

| 区域 | 职责 | 可承载的内容 | 不应成为 |
| --- | --- | --- | --- |
| 第一列：全局与 Space/Context 导航 | 稳定全局入口、类别/Space/Group/Context 及视图入口；底部独立设置控制区与图片/GIF 角色窗 | Space 类别和对象导航、**不依赖 Context 的普通对话入口**、进入设置 | 业务数据总管；仅有角色窗才能进入设置 |
| 第二列：当前视图结构/列表 | 随选定视图呈现其对象导航，允许搜索/筛选/选择 | 文件/目录树、对话列表、对象列表、已有获准视图结构 | 永远固定为文件树；跨 owner 无权全局检索 |
| 第三列：通用主操作区 | 当前选中对象或工作视图的主要阅读、编辑、配置与操作位置 | 文件编辑与 Diff、Context 详情与关联、API/Agent 配置、完整对话、必要的连接器操作 | 永远只能显示文件；自己保存模块业务事实 |
| 第四列：可组合辅助区 | 可换内容、调高宽、折叠与扩展；默认上对象信息、中执行回执、下对话 | 来源摘要、当前 Agent/模型与权限摘要、Operation/诊断、轻量对话/审批提示 | 全部复杂表单的唯一住所；第二套审批或 Operation 账本 |
| 底部扩展区 | 补充输出、诊断/日志、较长结果等 | 大段输出与补充视图 | 正式运行事实/会话状态的唯一来源 |

**重要修正**：第三列原称“文件/对象内容区”，在功能映射中具体定为**通用主操作区**；文件编辑是一个视图类型。第二列不强制所有视图必须是目录树。第四列不因增加业务能力而无限堆叠各种全尺寸表单。

**窗口/Context 原则**：同一 Context 可有多个视图且布局可保存；“一个窗口管理多个 Context / 多窗口 / 混合”的最终方案未冻结。0.1.1 的基本导航不得把业务 Context 与 Windows 窗口 ID 绑死。

### 3.1 不提供独立按钮的内部能力

- 模型流式片段拼装、参数协议映射、凭证加密、权限决策引擎、CAS、文件监听、Operation 去重、日志轮转、恢复一致性检查等归各 owner；**UI 仅呈现必要观察及失败动作**。
- 自动路由、成本/限额、备用模型、网络代理等 F04/F05 条目若 0.1.1 正式范围或 owner 未确认完整能力，不自动生成可用开关；可以在已确认的配置页提供真实可用字段或显式禁用状态。
- F07/F08/F12/F13 中的完整工作流、正式任务调度/验证账本、插件及复杂审批链不因第四列已有“执行/回执”窗口而视为首版可运行。
- 需求树、功能树、架构网图、多 Context 多窗口自由重排、复杂对话分支、语音结构操作、桌面宠物动作、独立系统悬浮窗、快捷键系统均按原定后续研究。未来快捷键配置位置在设置，不增角色旁快捷键入口。
- **历史总表的 F01-007 “多处放置”不授权创建 Placement 业务实体**；以当前 Space/Context 正式契约、用户已确定的组织关系为准。不能用旧词自行设计新增实体。

## 4. 页面/面板信息架构收口

### 4.1 第一列：全局入口和空间组织

- Space 类别（个人/工作/公开为初始类别，不等于具体 Space）→ 选择 Space → 可选 Group → Context；独立普通对话拥有可发现入口，不要求 Context 先存在。
- 对象操作可用“就近菜单 + 第三列详情编辑”承载；不得强制所有创建编辑共用一个巨大操作类型选择器。控件形态属于设计建议，保留现有已接通业务调用。
- 底部设置键必须可访问；角色窗展示图/GIF；用户隐藏角色不隐藏设置。第一列折叠时角色在第二列底部角落或底部等高区域内部重排，**不得因折叠强制弹出桌面系统窗口**。具体尺寸仍待试排。

### 4.2 第二列：随视图切换结构

- 文件视图→目录/文件树；对话视图→会话列表；对象视图→当前 Context 的受权资源/关联结构；其他视图以实际 owner 支持为准。
- “搜索”首先指当前视图可获权数据的筛选；跨域内部检索是单独能力，不得把局部搜索框说成全库检索完成。
- 在第二列进行选择→第三列出现主要内容，第四列按用户设置展示摘要/讨论/回执；点击只是定位，不能隐式执行文件写入。

### 4.3 第三列：通用主操作区

- 一处主操作容器依据路由/当前视图挂载：Context 详情、编辑器、独立对话、Agent/角色配置、API/连接器专属配置、必要的 GitHub/本地对象操作。
- 文件内容保护原草稿与磁盘版本，AI 修改同步只从真实受权资源读取；编辑器选型/自动合并算法不由设计稿自行冻结。
- 配置页可以在第三列临时成为主内容，返回时保存工作焦点/草稿（若实际 owner 支持）；不强制建立新全局业务路由对象。

### 4.4 第四列：默认辅助及面板切换

- 默认上 Context/当前对象信息、中执行/Operation 观察、下对话；可增减/切换类型、调整高度、收起，**对话可临时占满第四列**并恢复。
- 当前模型/Agent 与授权摘要可选为辅助内容；**审批决定必须通过可信授权入口**，第四列展示待审批状态不代替真实确认。
- 当前数据尚无 Workflows 正式执行源时，执行区只可展示已实现的 Connection/Operation 真实回执或“不可用”；不冒充 Task 进度与 Verification 结论。
- 上下文/模型选择变化不自动重写历史 Conversation 或已派发请求。

### 4.5 设置页分区（信息架构建议）

| 分区 | 内容 / owner | 0.1.1 收口要求 |
| --- | --- | --- |
| AI / 模型与 API | connections/api、凭证 owner | Provider、端点、Key 受信录入、模型、参数、测试与可用性 |

各分区是**导航组织，不是新的业务模块**；某底层能力未实现时显示明确未接入或不呈现，不能伪造设置项。

## 5. 跨页面状态反馈的统一设计约束

| 业务结果 | UI 应如何表达 | 禁止 |
| --- | --- | --- |
| 本地输入未提交 | 草稿/待保存，允许取消编辑 | 仅因点击按钮显示“已保存” |
| owner 确认提交 | 显示已保存及新修订/可读回证 | 以表单局部 state 充当正式权威 |
| 被拒绝 / 撤权 | 提示无权与允许的配置/重新申请入口 | 缓存继续展示撤权后的敏感内容 |
| 已取消 | 区分请求取消与真实外部停止 | 把取消当外部操作已回滚 |
| 未派发 / 明确失败 | 精确错误并保留输入 | 自动继续重试高风险副作用 |
| 已派发但结果未知 | 标“待核对”，保留 Operation/intent 原关联，允许查询 | 点击重试自动发第二次写入/提交 |
| 来源失联/过期/部分读取 | 显示来源、观察时间、可用范围及重新连接入口 | 把旧缓存写成最新成功 |
| 版本冲突/外部修改 | 展示磁盘版与用户草稿、Diff/人工处理 | 自动覆盖未保存用户编辑 |
| 切换 Context/Conversation/视图 | 取消过期 UI 订阅，保留未完成请求的真实归属 | 把晚到旧请求显示为新对象的结果 |

审批、保存、撤销、重试/恢复、日志与真实验收分别受其 owner 约束；全局提示是导航线索，不是新的事实来源。
