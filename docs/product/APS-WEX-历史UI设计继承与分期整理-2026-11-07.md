# APS / WEX 历史 UI 设计继承与分期整理（WEX PC）

> 日期：2026-11-07  
> 状态：历史设计复核与产品规划参考；不作为立即施工授权、正式版本计划变更或新业务契约。  
> 目标：把 APS 与 WEX 早期可用 UI 设计、长远交互思想和过时表现形式分开，供 WEXPCeasy 现行动态共享工作窗口及未来版本参考。  
> 当前依据：[0.1.1 PC 基础 UI V0.6](WEX-PC-0.1.1-基础UI布局与交互设计-2026-11-07.md)；[正式版本计划](../versions/0.1.1/PLAN.md)。

## 1. 结论：继承交互与语义，不复刻旧布局

- **历史四列方案已被当前设计覆盖**：旧方案曾将第二列固定为树、第三列固定为编辑、第四六列默认上下分段并放置对话；**这些均不能再作当前 B3 施工要求**。现行方案：第一列 Space/Context 导航；②＋③ 是默认完整、打开对象才分出预览的共享工作窗口；④ 辅助区默认收起、内容未冻结；底部视图标签与独立交互栏/虚拟形象为不同对象。当前权威以 [PC 基础 UI V0.6](WEX-PC-0.1.1-基础UI布局与交互设计-2026-11-07.md) 为准。
- **保留设计思想**：围绕工作对象而不是围绕聊天窗口；用户与 AI 共用对象与真实状态；鼠标指向/编辑、语音表达、对话补充；一份业务事实，多种视图投影；资源引用不等于权限或文件复制。
- **分期看能力**：已纳入 0.1.1 的基础行为按现有业务契约施工；旧文档中称作“正式/已确认”的历史功能不自动成为新版 0.1.1 必做；长远设计单独保留。
- **证据优先**：旧 UI 设计不等于源代码已实现，不等于测试通过。是否可交付以 WEXPCeasy 最新 main、模块公开能力和实际 Windows 验收为准。

## 4. 近中期深化：机制值得保留，但不可默认为 0.1.1 已具备

| ID | 历史方案 | 建议演进 | 为什么有价值 | 风险/依赖 |
| --- | --- | --- | --- | --- |
| HUI-13 | 每段 AI 回复序列有独立确认/不采纳按钮 | 先核对 Conversations 的 Segment 身份与已确认操作；完善逐段状态与可视反馈 | 用户不必对整段回复做二元取舍 | 勾选确认≠工具授权≠Verify |

| HUI-20 | 独立 AI 秘书理解多视图与已确认事实 | 作为长期协作交互研究 | 可主动指出冲突，减少反复人工组织资料 | 不暗中写文件、授权或伪造用户确认 |

## 5. 长期保留：不因短期施工而删除的设计思想

### 5.1 身份 / 层级 / 关系三层正交

APS 明确提出：**ID 是身份，parent_id 是结构归属，关系边是关联**。稳定对象身份不由名称、路径或显示位置反推。适用于 Context、Conversation、文件引用、Task、UI/功能/架构节点、验证证据及跨视图跳转。当前实现只复用已有对象 ID/引用机制；不因此立即新建“统一对象图”或全域关系数据库。

### 5.2 一份事实，多个视图

结构树、施工表、验证视图、文件树、执行回执可以呈现同一真实对象的不同方面；视图不是第二套业务权威。以后可扩展专业视图、架构树/功能树、看板、自由格子工作流及表格关系视图；多视图不能把 Task 完成、用户认可和 Verify 自动同步为同一状态。

### 5.3 对话只是交互形式，不是整个工作对象

Conversation 可以关联资源、当前对象、文件修改、执行记录和确认；不能让一条文本消息替代真实文件、运行记录或用户决策。当前第四列对话与第三列编辑器配合就是简化起点。

### 5.4 鼠标 + 语音 + AI 共用工作对象

用户通过鼠标定位、直接编辑；语音/文本负责意图与判断；AI 在授权范围内读取对象、提出修改或执行，结果在原工作对象同步呈现。画布只是未来一种更丰富的对象视图，**不应成为 0.1.1 基础 UI 的前置依赖**。

### 5.5 AI 建议 / 用户确认 / 真实执行 / 技术验证分开

方案被采纳不表示实际写入；工具调用完成不表示测试通过；测试通过不等于最终用户验收。UI 状态、文件颜色和回执需要携带明确维度与证据，而不是“万能完成状态”。

### 5.6 Context 是组合宿主，不是巨大固定页面

同一个 Context 可以只做资料管理，也可以组合源码、GitHub、AI、对话、任务。模板提供初始组合，不能改变 Context 本质或擅自回写既有对象。设计资料区可通过现有多地址及多视图实现，无需额外固定业务类型。

### 5.7 Reference / Permission / Capability / Execution 独立

能看到地址不等于有权访问；有权访问不代表已拿到能力；AI 建议不等于已执行。把连接配置、资源权限、会话有效授权及操作审批区分；不因为 UI 多选或 Context 共享资源就扩权。

## 6. 不直接继承或要纠正的旧表现形式

| 旧表现 | 处理 | 原因 |
| --- | --- | --- |
| APS Android 固定“空间/对话/设置”三整页排版 | 保留功能入口，不复制版式 | PC 已确定四列工作区 |
| WEX Android V0.2 左项目/右任务/顶部近全屏面板 | 只借鉴快切、状态、展开详情 | 后续 Android V0.3 等有调整，不是 PC 定稿 |
| 早期 WEX PC“自由画布默认占中央” | 长期保留画布视图，不替换当前第三列 | 自由格子工作流/调度器在 0.1.2 |
| APS 旧权限三级 AI Code 作为当前 WEX 权限 | 不直接照搬 | 现有 WEX 权限分层与用户已确认规则优先 |
| APS 特定 GitHub 只读入口及 5 文件/32 KiB 限制 | 只继承明确资源选择与授权语义 | 不把旧 Android 实现上限变成 PC 永久契约 |
| 把 Context/Task/Conversation 固定捆绑 | 不继承 | Context 能力按需组合；无 Task 仍能正常聊天 |
| Context 多地址自动同步为本地镜像 | 不继承 | Address 指向位置，Resource 才是实际内容 |
| 将复杂全域实体/关系/能力系统一次施工 | 保留边界思考，不实施庞大基础设施 | 避免重演历史过度设计 |

## 7. 落到当前四列 UI 的具体路径

1. **第一列**：Space 类别纵向按钮、Context 视图与快速切换；借鉴 Context 列表独立可点击、状态不改变条目位置的原则。
2. **第二列**：目录/资料结构和状态投影。未来可以替换成结构树、对象树或任务列表，不要求现在建立统一图引擎。
3. **第三列**：当前文件/资料的真实内容，共用查看与编辑状态；AI 文件改动后同步，存在本地草稿则保护与 Diff。未来可扩展多对象结构编辑、建议接受/拒绝。
4. **第四列**：默认上 Context 信息、中执行记录、下对话；窗口可增减/换类型，底部对话临时占满第四列。对话输入 `+` 附件、`@` 引用、麦克风；未来增加选段/分支、对象批选、语音指向、秘书操作。
5. **底部扩展区**：只承担补充输出/日志等，不重复主对话或第二列导航。
6. **跨列交互**：点选文件→第三列显示→第四列主动引用/讨论→AI 给出修改→受控写入→第三列刷新与回执核验；这是验证旧理念能否落地的最小样本。

## 8. 建议的阶段衔接（不是版本范围变更）

- **0.1.1**：验证四列容器、Context 多视图、真实文件编辑同步、对话输入与引用、窗口保存恢复、必要的基础段落操作；真实语音程度以正式计划和技术证据裁定。
- **0.1.2 候选**：自由格子工作流/正式调度器（现有正式延期项），以及经独立评审后适合并入的对象级引用增强、分段细粒度交互和多对象协作；**不默认将所有候选都加入 0.1.2**。
- **0.1.3 或更后续候选**：多 Context/多窗口自由布局、复杂讨论分支/关系视图、语音驱动结构操作、跨对象 AI 秘书、专业模板和更完整的跨设备协作；未定版本的功能可以继续处于研究状态。

## 9. 后续审查重点

- 对照最新 Conversations 代码确认：段落 ID、编辑重发与追加排队已经实现哪些，而不是凭旧设计承诺。
- 对照 Local 连接器、App IPC、Permissions 确认：第三列文件同步、编辑冲突是否具备可靠接口。
- 对照 Views/Space 的现有数据模型确认：视图关联目录是否可以不复制或修改地址对象。
- 对照 Windows 实机使用确认：四列最小尺寸、折叠、语音设备、键鼠/无障碍操作。
- 对多选、分支、秘书、自由画布分别保留独立研究入口，不将未定 schema、权限或工作流提前写入 0.1.1。
