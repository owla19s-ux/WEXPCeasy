# WEX 第二轮逐项需求对冲与遗漏审查

- 日期：2026-11-01
- 基线：96efc908ad0bb75b91a01bb929237f3b5a27af88
- 审查对象：F01–F15共216项基础功能、模块README/CONTRACT、全局契约索引、G1–G7、H01–H30、batch6准备度和第八批交付证据。
- 性质：静态需求/契约对冲；不代表代码运行测试，不批准B/C/D，不推导0.1.1。

## 1. 结论

**F01–F15的主骨架可保留，但当前还不能宣布216项已经全部具备模块施工规格。**

首轮解决了功能域遗漏、基础功能与UI区分和主要owner分配。第二轮发现：

1. F编号与模块契约之间没有逐项可追踪的稳定映射；本轮已建立独立映射表。
2. conversations、views、modes有公开能力但没有稳定能力编号；API/local缺少适配器级业务契约。
3. F10与F15若干横向功能本身跨多个业务owner，当前粒度无法满足“一个功能一个唯一主责模块”。
4. 部分依赖只写模块名称，没有明确依赖输入、输出证据、生命周期和不可用行为。
5. 取消、重试、恢复、删除、配置切换和退出等规则，仍有部分只在跨模块章节提及，尚未落实到对应F项。
6. C/D风险已被列出，但必须与具体F功能保持阻塞关系，不能用“模块准备度绿色”整体覆盖。

本轮不增加顶层模块，不重排F编号，不做UI，不推导版本。先补契约和复合owner，再进入基础模块独立施工。

## 4. 隐藏依赖与必须保留的调用顺序

### 4.1 普通对话与工具往返

输入持久化 → 逻辑生成关联 → Provider请求 → 结构化工具意图 → permissions当前判定 → connections保存attempt → 资源协调复核 → 真实派发 → Operation观察/回执 → 结果回注 → 消息定稿。

- Context、Task、Workflow均可为空。
- 工具意图不是执行结果；模型文本不直接运行命令。
- 输入/派发/定稿提交未知时按原关联回读，不重调模型或重复副作用。
- 模型请求重试与工具Operation重试是两套规则。

### 4.2 Space / Context组合

Context本体 → 放置关系 → 组合引用 → 各目标owner返回获准最小投影 → AI/Workflow解析本次配置依据 → 当前入口重新判权 → 执行。

- Context关联不授予读取/外发权限。
- 多个Context指向同一真实目录时，资源身份由local适配器核验，不能按Context ID去重。
- 解除引用不删除本体；删除必须检查引用/在途工作并处理竞争。

### 4.3 Workflow / Task / Operation

定义修订 → 运行绑定定义版本 → Task/轮次 → 计划预检 → 权限/资源复核 → 保存Operation attempt → 派发 → 观察 → Artifact/Evidence → Review/Verification → Acceptance。

- Workflow定义、Run、Task、Execution、Operation分离。
- Workflows不写Operation状态；Connections不写Task状态。
- 资源预检与最终派发使用同一Operation意图和协调引用，避免双重占用/死锁。
- unknown占用不能被普通超时或进程退出自动释放。

### 4.4 数据/配置/宿主恢复

数据根身份检查 → 模块迁移/格式校验 → 各owner恢复业务事实 → credentials重新确认 → permissions重新判定 → connections查询原Operation → workflows恢复Task/轮次 → views重建投影。

- 数据根可接回不代表凭证和有效授权恢复。
- 恢复旧备份不能覆盖当前Git/远端服务事实。
- app只协调，不替领域owner把状态批量改成ready。

## 5. 生命周期与异常规则最低要求

每项可持久化能力必须明确：创建去重、读取判权、更新预期修订、确定未提交/确认提交/提交未知、归档/删除差异、在途引用、重定位/迁移、恢复与历史版本。

每项外部调用必须明确：准备、判权、资源解析、attempt持久化、派发、观察、回执、取消能力、超时/断连、unknown、查询与重试边界。

每项持续服务必须明确：定义与实例、启动/就绪、配置代次、连接绑定、能力可用性、停用/卸载、迟到事件和残留进程。

每项投影必须明确：来源owner、来源修订/时间、缓存范围、撤权失效、乱序/重复事件、查询重建和投影不可用状态。

每项备份/迁移必须明确：范围清单、跨域一致点、外部资源排除、凭证排除、部分成功、失败回退、恢复后核对和原数据保留。
