# WEX 工作流画布与节点工作界面方向决策（2026-11-01）

> 状态：用户已确认的高层产品/架构方向；不是代码实现、正式 Schema、函数签名、IPC 或版本排期。

## A. 已确认方向

1. **自由画布格子**：工作流节点使用可编辑矩形格子，在二维自由画布中摆放；不固定为纵向列表、横向流水线或固定表格。
2. **正交连接**：节点关系使用带方向的水平/垂直直线及 90° 转角；不采用任意自由曲线或手绘线。
3. **手动与自动布局并存**：用户可自行移动节点；系统可按依赖关系进行横向、纵向或局部自动整理。自动整理不改变业务执行关系。
4. **表层 UI 与底层分离**：自由画布只是工作流的展示和交互工具，不是工作流数据模型或执行引擎。
5. **WEX 自主掌握核心**：工作流定义、节点业务身份、执行依赖、运行记录和节点调度由 WEX 自己维护；不把外部图形库或 Agent 平台的节点结构作为权威数据。
6. **布局归 views**：节点坐标、大小、视口和连线视觉路径属于视图布局；工作流节点、执行依赖和运行状态仍归 workflows。
7. **前期通用节点界面**：节点卡片展示名称、详情、颜色状态和任务数据；点击后优先打开普通任务、AI 对话、代码编辑、代码审查、文件/数据等通用工作界面。
8. **专业工作界面后置**：3D、视频、音频等复杂专业工作台以后作为独立扩展，前期不建设。
9. **Context 连接环境**：工具、连接器、运行环境和项目资源按需关联到 Context；节点引用能力，WEX 负责组织调度。
10. **视频不另造工作流**：视频创作沿用同一套 WEX 工作流；困难主要在底层专业生产能力。未来可以用低精度共享预览支持镜头、动作、服装和场景调整。
11. **外部能力可替换**：外部工具可以提供执行能力，但不能控制 WEX 工作流的业务语义、数据和历史；外部节点/插件失效时保留定义、运行记录和产物证据。

## B. 当前推荐但仍可调整的技术路线

- 使用 React + HTML DOM 呈现节点，SVG 呈现正交连接和箭头，自研轻量画布控制。
- 自行实现基础节点交互、正交连线、简单避障和基础自动布局。
- 不采用完整 React Flow/X6/Rete/JointJS 框架作为 WEX 工作流核心依赖。
- 复杂布局/路由算法可以独立引入 ELK 等算法库，但必须保持可替换，不能反向拥有业务数据。
- 现有 React Flow 原型保留为历史实验和技术比较样本。

总体方向已收敛为“自研轻量画布”，但 React 组件组织、SVG 实现细节、算法库选择和性能策略仍需通过原型验证。

## C. 后续需要实验或设计收敛的事项

正交连线避障、多边交叉、端口分配和路径手动调整；自动整理与局部布局；循环、条件分支、并行、汇合和嵌套结构；画布与业务定义分离后的持久化、修订冲突和多窗口行为；通用节点工作界面与对话/代码状态关联；Context 工具连接、环境依赖、项目资源版本和失效恢复；专业节点界面、共享实时预览及创作资产版本体系。

## 明确不代表

- 不代表自由画布、调度器或节点工作界面已经实现。
- 不代表当前 React Flow 原型已通过真实浏览器或 Windows Electron 产品验收。
- 不代表正式工作流 Schema、运行状态机、路由算法或自动布局算法已经冻结。
- 不代表 3D/视频专业工具链已完成选型。
- 不自动改变 0.1.1 或其他版本范围。
