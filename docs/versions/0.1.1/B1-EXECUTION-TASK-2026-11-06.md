>
> **任务性质**：一次授权覆盖第一批 B1 的连续模块施工与验收准备。按模块 owner 逐个完成，**不因单个文件、单个函数、一次提交或一次回复暂停要求用户“继续”**。不授权修改产品需求/权限政策/架构边界，代码施工阶段禁止改 README/CONTRACT/计划类文档。

> **2026-11-07 当前事实校正（不改原任务编号与范围）**：本任务最初按 11 月 6 日的待施工状态编写。最新模块 README 和公开源码已显示 AI、Conversations、GitHub、Local 存在正式产品代码及测试；原下文“阶段 B：缺失核心模块”“GitHub/Local 无正式 src/tests”不再是当前事实。执行时只核验和修复真实缺口，不得根据历史描述重新创建这些模块。当前阶段施工导航以 [根 README](../../../README.md)、[正式计划](PLAN.md)和 [B3 任务](B3-DESKTOP-DELIVERY-TASK-2026-11-07.md)为准；本任务保留 B1 验收职责，不自动宣告 B1 已通过。

## 一、目标与完成定义

使 B1-01～B1-07 的 0.1.1 **已确认且可实施**部分具备产品源码、公开接口、真实持久化/恢复以及独立测试，产出 B1-08 全量验收依据。以模块完成为单位持续施工，不以单条跨模块业务链路代替模块实现。完整跨模块业务闭环是 B2，Electron/React 与 Windows 产品交付是 B3。

B1 不以“所有 WEX 长期功能完成”作为退出条件，也不能因为 CI 绿灯而假定 B1 完成。若某个阻塞来自用户未确认的高风险权限、删除策略、结构性架构冲突或无法提供的真实凭证，应记录具体行为和证据，继续其他已确定的能力；不能虚构默认政策。

## 二、开工基线和证据

1. 读取远端最新 `main` HEAD、检查是否存在同期写入或未完成更改；不得将 2026-11-06 的 `c7f1c827` 状态快照作为实际施工 HEAD。
2. 先读根 README → 当前模块 README → 该模块的真实 `src/`、`tests/` 与公开入口；仅对具体争议再查版本计划、产品总表及归档契约。不得把过时的“没有产品代码”说明当成施工依据。
3. 先查看 [Actions 总运行列表](https://github.com/owla19s-ux/WEXPCeasy/actions/runs)，核对运行集合与 SHA；执行仓库实际可用的构建、类型检查、模块测试与边界检查，保存基线。
4. 每个条目分类为：**已实现并有测试证据 / 已实现但证据不足 / 缺失 / 不阻塞本版的延期 / 被真实未决事项阻塞**。不填主观百分比；不能重复施工已验证能力。
5. 本任务允许必要的构建、测试和 Actions；不可进行未经授权的真实付费 Provider 调用，也不可暴露 API Key。

## 三、实施顺序（保持原 B1 编号）

### 阶段 A：已有模块收尾

- **B1-02 Space / Context**：核对 `space/src/`、`space/tests/`、公开 API、真实数据位置/恢复、权限与引用生命周期；对照 Space README 的稳定范围和 S01～S20，补齐真实缺口。用户产品设计没有 Placement 独立层级；旧 Placement 文字或现存内部关系不能成为扩增产品数据结构的授权。未决删除/迁移政策继续阻塞受影响行为，不阻断基础创建、组织与引用。
- **B1-03 API**：核对已有 API 源码、测试和宿主组合。收口本版必需的 Provider/Connection/Model 配置、凭证引用、参数、模型观察、请求准备和真实派发、非流式/SSE、取消与超时、错误处理、工具提议/必要受控续接、保存与恢复；仅修实际缺口与回归。高级 Provider 特性独立列候选，不无限拉长 B1。不得将模型工具提议直接执行，不得将 Pi AI 实验作为无退化整体替换依据。
- **B1-01 shared/permissions/app**：检查已有存储、权限、宿主生命周期与停机重试，只针对真实问题修复；不重建公共底座。

### 阶段 B：AI 与 Conversations 已有实现的核验和补缺

- **B1-04 AI / Agent**：复核现有 `AI/src/` 与测试，按本版已确认要求补齐 Agent/角色配置、岗位/职责与模型/连接引用、修订、持久化的真实缺口。岗位、角色、Agent、Provider/Model 是不同对象，不复制密钥/权限事实；本版不建 Agent 自主循环、长记忆平台或调度器。
- **B1-05 Conversations**：复核现有 `conversations/src/` 与测试，补齐对话与消息身份、多轮记录、段落及已确定的选择/编辑/追加/修改重发、生成状态、取消、历史持久化与恢复方面的实际缺口，验证并发/重复/中断/失败边界。Conversations 协调调用 API 的公开端口，但不自行实现 Provider 协议、权限引擎或 Operation 账本。遇具体交互语义未决时标记并先实施稳定子集。

### 阶段 C：基础连接和数据收口

- **B1-06 Connections**：复验现有配置、Operation 账本、准入/派发与恢复；`connections/github/src/`、`connections/local/src/` 及独立测试已存在，按当前代码及其能力边界复核。按 0.1.1 确认的基础读写、受控调用、必要适配能力逐个施工并测试；不可用外部服务应明确隔离替身证据与真实服务证据。DSH 连接器、插件机制、外部 Agent 执行闭环仍属于 0.1.2，不引入正式调度器。
- **B1-07 Data / Logs**：围绕已存在的 shared 路径、SQLite、诊断与各模块 owner 检查公共数据根和 Context 数据目录分离、配置/索引/日志、明确的异常结果、旧数据兼容边界、重启与损坏拒绝。按 owner 补能力，不把所有业务事实复制到 shared，不把安装目录当用户数据目录。

### 阶段 D：B1-08 独立验收

对每个 B1 owner 检查实际代码、公开出口、独立测试、提供方/消费方契约、版本门槛、权限与数据安全；对照 `npm run build`、`npm run typecheck`、`npm test`、`npm run check:boundaries` 和模块测试及完整 CI 运行集合。仅将真实执行通过的项标为通过。整理 B1 模块状态表、接口清单、未验证项、阻塞及 0.1.2 延期项，再提出 B2 的明确接线入口。

## 四、施工纪律与提交

- **每次只有一个正在施工的模块 owner**。允许按依赖读取其他模块公开接口、加入必要的消费方契约测试；不越界重构其他领域私有实现。完成前不因短暂空档切换到不相关功能。
- **连续推进**：在当前授权的可执行范围内自行查缺补漏、写代码、补测试、运行回归、修复失败；以模块验收标准而不是回复频率作为停点。模块完成后可依此计划进入下一模块，但必须先记录回执和实际基线。
- **提交可追踪**：按可独立验证的合理功能批次提交，不要求每个函数一个 commit。写入前核对 HEAD，避免覆盖同期提交；高风险隔离才建短分支。不能用未经复核的历史 SHA 覆盖 `main`。
- **代码施工不得修改施工文档**：README、CONTRACT、计划和研究记录由普通对话/验收模式核对并维护；发现冲突在回执报告。用户另行明确授权的文档专项任务除外。
- **不擅自扩权**：默认拒绝未授权入口；角色名、Context 工具选择、API 返回的工具提议均不构成授权。执行真实外部副作用动作必须走明确权限检查、必要确认及 Operation 记录；不得静默重试未知副作用。
- **范围纪律**：本 B1 任务不得借本域施工提前开发 B2 完整组合架构、B3 UI 或 0.1.2 的自由格子工作流、调度器、DSH 连接器/插件系统。

## 五、每个模块必须交付的回执

每完成一个模块，记录以下实证；不需要用户反复发“继续”：

1. 执行前后 `main` SHA、变更文件与 Commit、公开接口变更与兼容影响。
2. 原需求/验收编号逐条状态，以及代码与测试的对应证据；明确“未验证”与“通过”的区别。
3. 实际执行的模块测试、根测试、边界检查与 Actions 运行 URL、SHA、结论；失败与修复记录。
4. 真实持久化、重启恢复、权限拒绝、异常/重复/取消/未知结果的覆盖证据。
5. 尚未实施、阻塞、延期项目及其原因；下一模块的可施工前置条件。

**最终输出**：B1-01～B1-08 汇总表 + 产品源码/测试提交清单 + 可复核验证证据 + 未决事项/延期列表 + B2-01～B2-08 的接口准备度。只有这份完整回执和独立复核之后，才可以称为第一批验收通过。
