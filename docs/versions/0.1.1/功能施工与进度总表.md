## 0. 如何使用这份表

1. **用户指定本版施工范围后，Codex 从本文件进入**，再读[根 README](../../../README.md)的全局纪律、目标模块 README、必要的 CONTRACT/公开接口、实际源码和测试。不要通过 A0 研究材料自动增加施工项。
2. 本文件是 **0.1.1 唯一的当前版本施工导航与状态汇总入口**。原 `PLAN.md`、B1/B3 任务书和 [跨版本 216 项总索引](../统一模块功能与施工进度总表.md)保留完整资料与细则；它们**不是平行的“当前施工进度事实源”**。若有差异，开工时先依据最新用户确认、真实源码与 CI 记录冲突，由验收/文档维护者修正本表，施工 AI 不自行改动正式文档。
3. 表格里的“存在正式源码”只来自文件树观察，不等于完整功能实现；“待核验”不是“未施工”。**状态按功能分项，不拿大模块的一次绿色测试给所有子功能盖章**。
4. **施工与文档维护分离**：Codex 在用户授权的代码任务内修改源码/测试、提交与回执；普通对话/验收角色复核后回填本表的状态与证据。发现冲突只暂停受影响子项，其余已确认功能持续推进。
5. **后续 0.1.2 建立自己的版本主表**（例如 `docs/versions/0.1.2/功能施工与进度总表.md`）；当前文档作为 0.1.1 的历史交付账本保留，不直接更名覆盖，也不把长期产品候选自动排入 0.1.2。
6. **范围红线**：本版不做自由格子工作流、正式调度器、DSH 产品化插件、DSH 外部连接器/派发闭环；环境管理完整下载/安装/升级/卸载、语音/音频与未定高级 UI 均不得凭旧 Excel 或研究稿擅自加入。F01-007 历史 Placement 条目冻结，不建立 Placement 产品实体。

### 4A.2 防遗漏与验收口径

- **设置页面不是“已经有框架就完成”**：四个一级分类（连接与服务、权限、验证、系统）已出现导航骨架，但服务按钮禁用、权限仅说明、系统缺少目录配置。各一级分类下的小类行为必须分别核验，不能合并为一个 B3-05“通过”。
- **多视图不是通用文件编辑器**：目前可读预览/摘要与有限视图标签已有代码，文件保存/冲突/草稿仍需独立落实。高级双完整视图、多个 Windows WEX 窗口组织、任意类型视图扩展不是已批准的本版范围。
- **虚拟形象与交互栏属于两套 UI 状态**：已观察到基础位置与开关逻辑；入口尚未连真实 AI，不得把占位测试算成产品使用成功。
- **跨模块页面不应制造第二个业务 owner**：UI 专管展示与交互，Space/API/AI/Conversations/Connections/Permissions 保留事实；App 提供可信 IPC。需要接口时先记录最小端口与缺失责任 owner。
- **U01～U20 不能全算本版交付承诺**：这些是现有设计的 UI 能力簇；每个簇内未确认子行为、后置版本、待硬件与高风险权限按正式 0.1.1 范围收口。先让 Codex 处理已确认且可执行的子功能。
- **更新总表时必须回填同一 U 行的真实状态、对应源码与测试、最新 SHA/Actions、未通过的行为**；不得仅修改“已完成”字样而不提供证据。其它模块将按同法逐域审查，此次仅做 UI。

## 6. Codex 连续施工要求与交接回执

- **持续施工单位 = 一个可独立验收的模块或其明确功能集合**；在授权范围内连续执行：查看最新代码/契约 → 差异定位 → 实现 → 测试 → 修复 → 回归 → 提交 → 回执。除真实阻塞、已完成整单或授权/工具环境不具备外，不因每个文件或一次提交就停止要求“继续”。
- 只修改本次已授权 **源码与测试**；不可擅改 README、CONTRACT、产品功能表、版本计划、本总表和 A0。用户另行授权文档治理时按专项边界处理。
- 默认在最新 `main` 上工作；写入前核查远端新提交。需要隔离时用短期分支，绝不以本表快照 SHA 覆盖 main。
- 必须先看 Actions **运行总集合**和关联 SHA，再看 workflow/job/日志。实际运行 `package.json` 支持的构建、typecheck、单元/契约测试、`check:boundaries` 与具体 Electron/Windows workflow；失败记录命令、环境、链接，定位修复，不以 mock 替代真实服务。
- 跨 owner 改动只允许必要的公开端口/消费方测试；业务事实仍归所属 owner，权限入口必须 fail-closed，不擅自扩大未决 IV 级高风险操作。
- **每项任务结束回执格式**：`B/D/F/模块功能 ID`、源码 owner、变更路径、提交 SHA、已实现/部分/阻塞、运行命令、对应 workflow URL/运行 SHA、正例/拒绝/异常与持久化证据、未验证事项、独立验收待检查项、下一项可施工依赖。
- **仅交付回执不修改总表状态**；独立验收方复核后更新。Windows 人工 E4 项统一保持 `DEFERRED-UNTIL-HARDWARE`，不因此阻止其它可自动复验的工作。
- **验收不等于代码提交**。B1 各域、B2 真实组合、B3 正式用户交互/Windows 打包的独立退出标准分别按本表和旧细则核对；不能凭 CI 某一个 workflow 的绿灯宣布整个 0.1.1 通过。
