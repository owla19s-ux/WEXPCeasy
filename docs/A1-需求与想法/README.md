# A1｜需求与想法

> **职责：记录用户想要的产品、功能、使用场景和问题。** 本目录为需求输入层，不是正式产品需求表、版本计划或 Codex 施工授权。

## 记录原则

- 保留用户原始表达与来源（日期、讨论线索），提炼目标、期望行为和现有痛点；不得把 AI 推测写成用户已确认的意图。
- 不要求刚提出的想法一次说完整。新想法可以持续补充、更改、合并或明确否定；保留关键变更与决策依据。
- 每项至少区分：**原始想法／待讨论／用户已确认的需求意图／不再采用**。这里的「确认需求意图」**不代表**已批准技术方案或版本排期。
- 不把未讨论的想法直接写入 F01～F15、UI 正式功能表、模块 README、CONTRACT 或任务书；更不得因此让施工者直接实现。
- 有关研究问题、参考方案、技术选型，关联至 [A2｜讨论与研究](../A2-讨论与研究/README.md)，不在本层强行写结论。

## 与现有文档的关系

- 现行正式产品资料仍以 [产品功能总表及当前设计](../product/README.md) 等权威文档为准；本目录不覆盖其效力。
- 现有 `docs/research/`、`docs/decisions/`、历史研究与施工任务暂不搬迁，避免破坏引用。
- 只有在用户与 AI 完成讨论、确认具体方案以后，才考虑进入后续正式产品文档、版本规划和施工任务阶段；**不按想法提出时间自动安排“下一阶段”**。

## 当前阶段

此目录只建立第一环节的归属和入口；**不批量迁移或重写历史需求，不新增版本承诺**。
