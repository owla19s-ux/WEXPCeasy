# AI/roles｜角色与岗位设定

> 此目录负责 Role / Position 的设定语义及关联说明。现有角色、岗位实现仍在 `../src/` 中；本目录 README 不是独立的第二套配置存储。正式接口与现状见 [AI/CONTRACT.md](../CONTRACT.md)。

## 两类独立设定

- **Role（角色）**：描述行为、提示词、表达方式等角色设定；当前源码有 `name/prompt`。
- **Position（岗位）**：描述岗位及工作职责、工作定位等设定；当前源码有 `name/responsibility`。
- **职责/范围**：用于描述某项工作的职责和适用范围，不等于角色或岗位被授予操作权限。
- **API / Model**：由 `connections/api` 独立管理，不是本目录创建的模型实体；需要时以受控引用参与组合。

Role 和 Position **不是必须同时填写的一对固定依赖**。两者都是可以分别定义、保存、复用并按实际使用场景组合的设定。主 AI、秘书、研究、执行、审查和验证等称谓代表可能的角色或工作定位，不能据此固化互斥身份等级。

## 代码事实与偏差

目前 `AI/src/model.ts` 尚存名为 `agent` 的兼容配置类型，要求 `roleId`、`positionId` 和模型引用；桌面对话也通过 `agentId` 消费。这是**实现现状，不是本子域的第三类正式设定或产品前置条件**。不得仅凭这个类型要求用户必须先建立完整组合才能使用角色或岗位；也不得未经迁移测试直接删除已持久化记录。

## 归属、使用及验收

角色与岗位的定义及修订由 AI 管理；Context 对设定的选择/引用由 Space 管理；API 调用归 `connections/api`，对话历史归 `conversations`，工作流、权限与操作回执仍由各自模块管理。

验收应分别核对 Role/Position 的独立创建、读取、编辑、重启恢复、组合引用、授权/撤权和实际对话消费。当前源码中强制经旧组合类型发起对话的限制需单列为需求偏差，不能把它默认为正确设计。
