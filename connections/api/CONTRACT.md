# API 模块正式功能与接口契约

> Owner：`connections/api`；需求来源：A1 `F04-001～F04-013`；适用：长期完整能力，不代表全部纳入 0.1.1。
> 状态：2026-11-08 技术评估后建立的正式模块约束。既有已运行接口以源码与测试为准；新增协议以源码和对应 SHA 实测为准；未接通或未获真实厂商验收的能力**不宣称已实现**。
> 施工入口：[README](README.md)；版本交付及验收：[A2 0.1.1 总表](../../docs/A2-版本与工程状态/0.1.1/功能与工程状态总表.md)。

## 1. 定位、Owner 与不变量

API 是独立的模型服务连接和协议适配模块：管理非秘密 Provider/Connection/Model 配置，准备并发起获准的模型请求，解析文本/流式/工具及使用量结果，向调用方提供结构化结果与诊断。API 可独立完成一次模型请求，**不以 Conversations 作为强制前置**。

- `connections/src` 是公共受控操作、Operation/attempt/回执的唯一 Owner；API 不建立第二套账本，不以网络发送或存储成功冒充外部完成。
- `permissions` 裁决请求与撤权；`shared/credentials` 保管明文密钥；API 只保存受控凭证引用，实际解析由可信宿主注入。
- `conversations` 管消息、逻辑生成、历史与恢复；`AI` 管 Agent/角色/岗位/偏好；Space 管 Context 关联；`app/UI` 管可信入口与用户交互。
- API 只返回**工具调用提议**及合法续接格式，不自行执行 GitHub/Local、批准权限、变更 Task 或自动补发未知副作用。
- 对象身份与修订、请求快照、实际派发、取消、结果未知和恢复必须保留可追溯依据；新模型/新会话/新连接不自动继承旧授权。
- 不因单一 SDK、单一协议或当前 UI 实现范围缩减 A1 长期功能；新技术抽象须有实际协议或测试依据。

## 3. 关键实体与接口语义

- **Provider**：厂商/服务来源身份及其可发现的产品能力；不直接代表协议。
- **Protocol**：请求、响应、流事件、工具与用量的格式约定。同一 Provider 可提供多个协议，不同 Provider 可实现同类兼容协议。
- **Connection**：唯一 ID、修订、Provider、协议、端点模式/URL、凭证引用、启停和非秘密参数。多个连接独立修改；复制不复制凭证明文；删除先检查本地及外部引用。
- **Model**：属于一个 Connection 的模型 ID、显示名、修订、参数及能力观察，不能借别的 Connection 观察冒充自己的能力。
- **Observation**：能力、参数/限制、来源、来源修订、观察时间、适用连接/模型版本；支持、明确不支持、未知、待验证是不同状态。官方资料、用户声明和真实探针来源不得互相冒充。
- **Request snapshot**：本次请求的连接/模型修订、参数及来源、输入、工具、生成身份、协议目标和授权作用域；在途请求不能因默认配置修改而静默改变。
- **Result**：完整响应文本/结构化内容、可选推理摘要、工具提议、使用量及来源、完成/拒绝/截断/取消/unknown、Provider 关联 ID；不把非终态 EOF 当成功。

当前公开 API 入口保留 `src/index.ts` 对外的 `createApiService`、`createApiTransport` 和相关类型。新增协议实现**先作为模块内部适配**，不得未经调用方核对破坏既有公开端口、Operation ID 或持久化数据。

## 4. 协议适配要求（已确认方向，接口签名待验证）

- 保留现有 OpenAI Chat Completions 兼容请求、JSON/SSE、工具/usage 解码作为第一个正式适配实现；不能将其直接称为所有 Provider 的通用解析器。
- 适配层按**真实协议**处理请求映射、鉴权约定、URL、流事件、工具参数、响应终态、usage 和 Provider 错误；网络传输层负责 fetch、取消、阶段性超时、响应限制，宿主边界负责 Operation。
- Provider、Protocol、Connection、Model 必须独立表达；不要求为每个厂商复制全套 Adapter，也不默认把任何 SDK 当成完整 Provider 宿主。
- 已有 `protocols/index.ts` 显式协议选择，以及 `openai-chat.ts`、`anthropic-messages.ts` 两份独立实现。Anthropic 原生文本发送、用量、SSE、单页目录与文本探针属于当前开发中的实码能力；工具调用、推理续接、多模态和目录分页均未完成。Desktop API 已提供显式协议选择、旧调用默认 `openai-chat`，UI 已提供协议和 `max_tokens` 设置；对应最新 SHA 的 Windows 人机操作验收仍待确认。
- OpenAI Responses、Gemini 原生协议及 DeepSeek 额外语义仍须按照实际官方协议与隔离测试分批实现；**不因长期目标自动纳入全部 0.1.1**。
- 对未知模型能力不伪造“支持”。允许用户通过获准的探测路径获得证据；实际产品使用时对明确不支持的功能拒绝，对未知能力采用明确、可追踪的待验证处理，不得默默丢弃模态。
- 多模态必须区分图片输入/生成、音频输入/输出、视频/文件、结构化输出及工具能力，不以单个 `image` 布尔状态替代全部能力；数据结构迁移须独立验证重启恢复。

## 5. 参数、能力与配置规则

- 允许数值 `0`、`false`、对象、数组与显式值；明确区分未设置、Provider 默认、禁用及协议不支持，不能将 `null`、省略、禁用混为一谈。
- 连接/模型/Agent/会话/单轮覆盖**优先级在 A1 尚未全部冻结**。当前若值冲突可明确拒绝并报告来源；不得擅自设定“单轮总是优先”。明确方案后连同版本、快照和测试实施。
- `response_format` 未列在当前 `model.ts` 保留参数中，且 `service.ts` 存在结构化输出校验路径；需以真实配置和请求准备测试确认它是否具备合法参数规格、调用和响应校验闭环。不得将未经复现的冲突认定为源码缺陷。
- 推理参数、工具 Schema、结构化 JSON Schema、上下文/最大输出限制按实际协议进行显式映射和错误反馈；不要将单厂商参数作为全球通用要求。
- 本地回环端点可按现有政策支持无凭证 HTTP；远端密钥不能为兼容本地服务而默默降级为明文 HTTP。需要本地带密钥 HTTP 时先做风险及可信范围评估。

## 6. 请求生命周期、错误和恢复

1. 使用可信入口与模块公开读取能力验证 Connection/Model、修订、参数、观察及当前授权；准备不可变请求快照。
2. 解析凭证只限本次、当前目标与授权；派发前通过 Connections Operation 建立尝试记录。已有 Operation 不自动重发。
3. 适配器构造真实协议请求；通用 Transport 负责网络、断连、取消和期限。发送后失败或存储不能证实结果时保持 `unknown`。
4. 只有完整且经过格式/终态/工具 Schema 校验的响应才可作为成功结果；流式增量展示不是最终持久成功。
5. 工具提议交给调用方，经 Permissions 与相应连接器真实执行；失败、拒绝及未知工具结果按可验证的原始轮次回注，不由 API 自行执行。
6. 限流、重试和备用模型属于受控**新 attempt/新请求**；未知副作用不盲重发，原始证据、费用与来源不得覆盖。

明确区分本地取消、网络断开、远端真实停止以及结果未知。401/403、404、429、DNS、TLS、超时、格式/能力错误不得统一伪装为“模型不可用”。

## 7. 模块内部职责及调整准则

| 职责 | 当前对应源码 | 重构策略 |
|---|---|---|
| 公共入口 | `src/index.ts` | 保留对外导出稳定 |
| 配置与查询 | `service.ts`、`model.ts` | 定向拆分独立函数，保持原语义 |
| 模型能力与参数 | `model.ts`、`service.ts` | 能力/规则分离，旧数据迁移需验证 |
| 协议适配 | `protocols/index.ts`、`protocols/openai-chat.ts`、`protocols/anthropic-messages.ts`、`stream.ts`、`response.ts` | 按协议维护独立路由、编码、诊断版本和响应解析；注册表只做选择，保留旧 Chat 回归 |
| 传输/诊断 | `transport.ts` | 分离 fetch/超时与模型目录/Probe |
| 工具续接 | `tools.ts`、`continuation.ts` | 复用已验证实现，不搬入 Connections |
| Usage | `usage.ts` | 保留真实计数，成本及来源后续补齐 |

**不得机械创建七个空目录**；先以实际重复或跨协议差异形成必要文件与测试。新能力建立 → 兼容接线 → 回归 → 迁移调用方 → 删除冗余旧代码；未经迁移验证不删除既有 SDK/实现。

## 8. 验收矩阵与证据边界

- 独立模块：`npm run test:api`，覆盖配置持久化、删除保护、参数边界、模型能力、流式工具、使用量和失败状态。
- 宿主集成：`app/tests/api.test.mjs`；真实本地 HTTP 服务与模拟响应须分别标明；验证 stop、重启、Operation 防重放和撤权。
- 全仓兼容：`npm run typecheck`、`npm run build`、`npm test`、`npm run check:boundaries`；与 AI、Conversations、UI 的公开接线逐项验证。
- 真实外部验证：凭证受信引用、端点/模型、非流/流、目录/工具探针、错误和费用观察；明确服务商、协议、版本、测试时间及是否真实联网。
- Windows：真实用户设置、选择模型、发送、停止、恢复、错误展示及重装后引用策略。

每条结论至少记录功能编号、文件/测试、对应 commit SHA、结果与未覆盖项。GitHub Actions 先检查最新 [运行集合](https://github.com/owla19s-ux/WEXPCeasy/actions/runs) 并核对对应 SHA，不用旧 workflow 的绿灯替代本次验收。
