# permissions 业务契约（第四批设计稿）

## A：owner 与非职责

本域唯一维护策略、授权/审批/撤销事实、判定及其依据；不维护AI职责/角色、Context组合、任务状态、执行尝试或凭证。模块启用、全局访问、对话启用是不同约束；工具发现/选择、角色名称、任务分配、Space引用或相同外部账号均不授予权限，不跨入口求并集。账号登录不是本地权限前置。

connections宿主边界检查外部调用/回调并记录操作；内部领域保护正式入口。真实资源/进程边界兑现限制，排队前判权不替代执行前复核。撤权限制新的数据/调用，不使外部自动停止、回滚、删除资料或模型遗忘。permissions不承诺OS沙箱。

## B：共同请求与观察语义

以下是业务信息，不要求固定字段名。可信调用事实必须由宿主绑定：当前主体（实际执行身份及来源）、入口（本地交互/独立对话/任务/受控回调的实际实例与代次）、适用职责事实及其来源修订、目标资源身份与动作。外部文本、模型输出、UI 自报 role/Context/administrator 不构成可信事实。宿主不能仅转签未经核对的外部声明。

Context 可空，含义仅为“本次没有 Context 范围”，不代表全局、不代表默认项目、不继承上一次入口。非空 Context 也不自动授权；入口不同不求权限并集。对象引用以领域身份与来源定位，显示名/路径不是独立身份；资源范围须说明单对象/集合及动作，不能以自然语言名称推导递归范围。

修改请求具有调用意图标识、期望修订和规范化目标；同一主体/入口/能力/意图标识重送相同内容返回原结果，不重复写；相同标识不同内容拒绝。去重保留期限、跨重启保证与意图查询需在实现契约证明，不能假设无限期。删除/解除与新建必须是不同意图。只读可重试但须重新判可见性。

结果至少区分：已确认提交（有权威修订/证据引用）、业务拒绝（未提交）、依赖不可用、确定失败（已证实未提交）、结果未知（无法确认是否提交）。超时/断连不是业务失败。保存返回不明确时先按意图查询或回读权威修订，未知期间不换新意图盲重试。取消在提交前可确认未提交；提交后返回已提交；无法确认则未知，取消不回滚事实。失败/未知不得伪造成功通知。

每次写入以期望修订检查本域对象/关系；旧修订返回冲突与获准可见的当前依据，不最后写入获胜、不自动合并。跨域变化不宣称全局事务；依赖读取提供来源修订，提交时需失效则拒绝/重验。历史证据记录当时依据，当前查询重新检查授权；撤权后历史记录仍保存但不得继续向无权者披露。

## B：本域范围、决定与审计语义

判定请求必须表达主体、可信入口、目标资源及动作，Context可空；还必须接收宿主核验的当前本机使用关系及其代次、已有许可绑定的使用关系依据。新安装与旧许可关系不匹配、关系未知或生命周期核验未完成时，不得产生有效允许；正常重启/兼容升级能否延续由可信关系事实证明，不能仅靠路径、可解密凭证或旧配置自证。app提供事实和接入屏障，不写许可或批准状态。非对话入口由宿主提供自身入口范围，不伪造conversationId。对话启用仅适用于实际对话；对非对话声明“不适用并提供其入口限制”而不是默认为通过。B建议：任务/独立本地/受控回调分别绑定其真实入口实例，以该入口的显式启用与授权范围承担第三层限制；不伪造对话，也不永久禁用非对话。三层映射最终形态仍属D，待裁决期间可记录审批草稿与显示缺口，但缺少已批准入口策略时不颁有效许可。缺少适用范围或可信事实时拒绝/不可判定，不能宽化到全局。

本批建议决定区分允许、拒绝、需要明确批准、不可判定。允许需带判定依据引用、策略/授权修订、精确范围、评价时刻/有效限制；它是该次事实下的决定，不能被复制成永久token或转授权。强制拒绝优先，普通批准不能覆盖；具体规则算法未定。未收到允许一律不提供资料/派发动作。授权主体、操作者、请求受益主体不得混同。批准须绑定实际审批者、待批请求及规范化动作/资源/入口，不能批准一段任意工具文本。有限次数许可仅保留业务方向，本稿延期实际启用：原子领取/扣次、并发执行、派发歧义及unknown不自动归还次数的规则均属C；在上述实验和双方行为验收完成前不得签发有限次数有效许可，不以普通去重冒充次数控制。

## B：提供、消费、私有、装配与通知

提供面仅PER-01…04；策略求值、匹配/存储/审批索引私有。仅消费可信请求事实与shared技术提交/时间/恢复能力：提交需明确成功、未提交或未知；时钟可信度不足时不能延长许可；读取需提供权威修订。无需回调space/AI/workflows私有查询，故不形成所有领域相互依赖。app绑定可信身份、入口、资源规范化事实来源与存储，若无法验证回调身份则拒绝准入。事实输入需说明来源/代次/范围，领域状态可能变化时由调用边界重新核实，permissions不猜测角色和对象状态。

撤权通知仅提示某范围/许可代次失效，订阅者需重判、停止新的资料出口/调用并按自身能力处理在途。通知可迟到/重复/丢失，不能成为唯一安全机制；下一次准入必须读取当前代次。连接操作账本保存判定引用而非可修改权限副本；审计保存失败与许可提交失败需可区分，不能丢审计仍伪报完整确认。持久化/事务组合须实验，未证明前不承诺绝对无竞态。

## A/B/C/D 与准备度门槛

A：权限唯一owner、组织/职责不授权、检查与真实限制分层、撤权不遗忘/停止/回滚。B：能力拆分、决定分类、审批绑定、入口适用性、代次复核与样例。C：有限次数许可原子领取/扣次/派发unknown不自动归还及并发竞态，撤权竞态、审计提交一致性、跨进程回调身份/重放、时钟与重启、真实Windows隔离/残留进程。D：哪些动作允许自动/逐次审批、许可默认期限/次数和审计保留/删除、非对话入口产品呈现；未裁决不默认宽权。

准备度：可信事实与拒绝语义可审阅，非正式授权引擎。进入实现接口前各消费者需确认资源规范化/入口与事实时效、批准本批B，并明确D的最小默认策略或延期对应能力；对外安全承诺前必须关闭C。任何依赖缺失均保持不可判定，不通过临时全局允许赶进度。


## 第五批复杂压力审查补充（2026-10-31）

### PER-01/PER-02：来源、衍生内容与目标出口（F03）

读取、向外部服务发送、向另一Context披露、保存/导出分别是动作；共用AI配置/文档/连接不合权。推荐输入事实包含资料owner、版本、允许传播范围和实际目标（provider/实例/接收方/端点）；由可信来源绑定，模型自报“已脱敏”不使范围失效。摘要、翻译、章节改写、结构化提取与工具参数可能保留敏感信息，不能默认解除原限制。permissions消费来源事实评价动作，不能反向遍历所有领域私有库。

来源断裂、混合来源无法判定或策略未定义时不签发有效外发许可；具体来源合成、人工脱敏审查/降级/解密权限属于B/D，自动内容识别可靠性属于C。此处不承诺全量信息流追踪/DLP，不能声称拦住用户手工复制、同用户非受控进程或已合法传出的内容。已外发副本的撤回/删除仅有外部服务可证能力时报告，撤权只能约束后续受控路径。

共享策略/记忆仅为未来候选：角色配置不保存公共记忆权威，任何未来经验发布必须有来源owner、可见范围及显式发布/读取入口，不因本轮研究建数据库或默认共享。

断言：入口A可读X且向M发送，不代表入口B可读X、向N发X摘要或向Context B分享；外部回传的权限标签不能当宿主身份。撤权后新发送为0，历史已发送记录不改写为未发送。预算余量不能抵消权限拒绝。

### 第五批交叉收敛：F03传播判定最小保证（B/D/C分离，2026-10-31）

每次数据从某一获准读取环境发往**另一实际目标**（外部模型、外部Agent、另一Context、公共出口）均形成独立的披露或外发判断；入口主体、实际目标、来源依据及限制来自可信宿主/原数据owner，不因角色、Context关联、摘要文件名或生成文本宣称“公开”就放宽。可读许可、外发许可、跨Context发布许可不得简单取并集。来源缺失或混合、无法说明衍生范围时，**自动出站路径必须保守阻断**，同时提供可诊断且不泄密的原因；不是永远拒绝用户合法操作，而是等待获准的审查/来源补全流程。

人工审查/解密/降级、发布谁有权批准及审批有效范围仍属D06，未裁决不得偷偷实现默认审批；内容自动分类/追踪准确性和可信来源证明属C。permissions只对已证实的事实作决策，不承诺查遍用户复制/同用户外部进程/合法外发后的副本。要在E1/E2下证明跨出口拒绝时外部调用次数为0，并核对合法公开内容不会因无关Context受限而全部失效。

## 第七批实际实现（2026-10-31）

当前公开入口 `permissions/src/index.ts`，消费者 `app/src/foundations.ts`；仅导入 shared 公开的 Store/Json/结果类型，不读取任何其他业务私库。

`createPermissions(Store, TrustPort)` 提供 evaluate / recheck / grant / revoke / history。TrustPort 只能由可信宿主实现：current 将真实调用对象绑定为核验事实，canManage 核验精确管理请求，canReadHistory 仅用于本批受信任完整历史管理入口。外部文本、Renderer字段、Key、角色和Context自报值不实现该端口。当前无IPC/OS主体认证实现，正例事实为测试宿主注入；CLI默认全部无可信事实/无管理权。

许可按 subject、entry、conversation、可空context、resource、action、target、relationship及relationshipGeneration精确匹配；对话三层开关与来源限制任一不满足均不能允许。非对话返回 entry_policy_unresolved，不伪造对话、自动降级或跨Context发布策略。

每次授权/撤销以聚合修订CAS持久化，记录命令/原意图/精确范围/代次；撤销保留历史，重新授予必须新事实。recheck 重新读取当前授权，并核对旧决定的范围/修订/代次；旧允许、迟到旧修订和重新授予前的旧决定均不能继续使用。保守地使任一授权变更失效旧决定；当前无按资源细粒度代次优化。

提交三态原样交给调用方；重复意图核对原命令并query原提交，unknown不自动再写。失败/损坏/存储不可用返回不可判定或unknown，不放行。history当前只向受信任管理入口提供完整本域历史；普通用户按资源筛选、分页与可见性投影尚未开放，不可将布尔管理检查当成任意用户读取许可。

出口前接口是复核点，不是外部副作用的原子锁；复核与真实资源/网络发送间竞态、IPC重放、Windows主体与安装关系识别仍C。未实现有限次数、自动审批、D01分层授权链到各非对话入口的完整映射、D05强审计全局阻断或D06降级发布政策。

测试：`npm run test:permissions`。真实SQLite/共享存储替身共用本域行为；`permissions/tests/reader-contract.mjs` 被app消费者对真实权限与权限替身共同执行。历史是本域事实，不复制Operation或Task账本。

## G3 非对话入口与基础能力授权补充（2026-10-31）

本节对应基础能力 G3；跨域入口和状态矩阵见[基础能力落地映射](../docs/planning/FOUNDATION-CAPABILITY-IMPLEMENTATION-MAP-2026-10-31.md)。

当前产品实现对 Conversation 入口有真实允许路径，但对非对话入口仍返回 `entry_policy_unresolved`。该状态是明确的安全阻断，不是待绕过的临时错误。Task、本地直接操作、受控回调和外部 Agent 连接不能伪造 Conversation ID，也不能把创建 Task 时的对话授权直接继承为执行授权。

后续每种入口必须由可信宿主绑定真实主体、入口实例/代次、目标资源身份、动作及来源修订；permissions 按该入口适用的明确策略重新判定。至少分别覆盖：
- 用户在 UI 发起的直接操作（不是任意 Renderer 自报主体）；
- Task/Workflow 派发（任务引用仅说明工作范围，不自动授予资源权）；
- 外部 Agent 回调/结果提交（连接实例、回调来源和实际动作均须核验）；
- 恢复/查询入口（只读核对与重新执行是不同动作）。

PRD-D01高层方向已由用户确认：工具/模块启用 → AI获得使用资格 → Context开启工具 → 当前执行位置授权（工作流节点/位置，或对话模式四级授权）。该链条决定工具调用资格的逐层收敛，下层不能扩大上层授权；它不替代PER-01对每次真实操作的主体、入口、目标资源、动作、来源和当前授权代次判定。

Task、用户直接操作、外部Agent回调和恢复/查询入口仍需分别建立可信入口事实及映射规则；不能伪造Conversation ID，也不能把Conversation许可机械复制为Task默认允许。在相应入口映射与可信事实来源实现并测试前，保持拒绝/不可判定，不签发有效允许、不派发副作用。D02另规定工作流节点位置授权与主AI/秘书AI对话四级控制分开；IV级在用户授权范围内允许全风险自主，工作流启动时由用户对本次节点权限方案确认一次，主AI/秘书AI共享对话等级且须用户主动设置。Shell、插件信任、WEX自身权限策略和凭证的专门边界仍待确认。

G1 资源引用不产生权限；G2 工具意图不产生权限；G4 Operation 历史回执不构成永久授权；G5 搜索命中、缓存或通知不构成读取许可。真实读取、外发、写入、回调和取消分别按目标与动作判权。


## 9. PRD-D01/D02分层授权与执行模式补充（2026-11-01）

- D01工具资格链：工具/模块启用 → AI/Agent具备使用资格 → Context开启工具 → 当前执行位置授权。工作流模式检查节点/位置；直接对话模式检查主AI/秘书AI适用的四级对话权限。任何下层不得扩大上层范围。
- D01链条不是一次操作许可。PER-01仍须对每次实际调用按主体、入口、资源、动作、来源和当前授权代次判定。
- D02工作流模式读取工作流节点/位置权限；对话模式的四级控制适用于主AI/秘书AI与用户交互；两者不可互相继承或替代。
- IV级不因风险标签本身逐次确认；风险标签用于审计、影响展示和恢复策略。Shell、插件信任、WEX权限策略及凭证另设专门边界，尚待用户确认。
- 对话四级语义已由用户确认；历史L0～L3风险草案不替代当前四级自主程度定义。


## 10. PRD-D01/D02 权限判定矩阵（2026-11-01）

完整产品级矩阵见[ D01–D02 权限判定矩阵与执行模式 ](../docs/product/PRD-D01-D02-PERMISSION-DECISION-MATRIX-2026-11-01.md)。本域负责最终策略、授权、审批、撤销、判定与依据；app/AI/space/workflows/conversations 只提供各自拥有且由可信宿主绑定的窄事实，connections 在真实副作用前调用本域并复核。

执行必须满足：工具/模块启用 → AI工具资格 → Context工具启用 → 当前执行位置策略（工作流节点权限或对话四级）→ 本次真实操作判权。全局访问约束继续作为独立总闸。任何下层配置不得扩大上层范围；不同入口、Context、AI主体、工作流节点不得求权限并集。

工作流模式按稳定节点身份、工作流定义修订、工具/动作/资源/目标及节点执行策略判定；启动时由用户对本次运行的完整节点权限方案确认一次，确认后范围内自动执行。对话模式按当前 Conversation 的共享四级策略判定；主 AI 与秘书 AI 共用等级，但工具资格分别判定，且必须由用户主动设置。两种模式不互相继承。IV级允许在用户明确授权范围内执行全部风险等级操作，风险标签本身不再强制逐次确认；Shell、插件安装、WEX自身权限策略和凭证变更的专门保护边界仍待用户确认。读取许可与向模型/外部服务披露资料的许可分开；只读不自动等于低风险。

矩阵中的IV级全风险自主、工作流启动一次确认、主AI/秘书AI共享等级已由用户确认；特殊信任边界仍为B候选。本文不冻结实现字段、API或状态枚举。当前产品代码仍对非 Conversation 入口返回 entry_policy_unresolved；现有实现也未实现四级对话策略、节点策略及完整 needs-approval 流程。不得将文档设计描述成已落地能力。


### D01/D02 已确认决策补充（2026-11-01）

- IV级为全风险自主：在用户主动授予的工具、动作、Context、资源和目标范围内，可自主执行全部风险等级操作；风险标签本身不单独触发逐次确认。
- 工作流节点权限可由用户手动配置或由AI生成提案；每次启动时用户对该次运行的完整权限方案确认一次，确认绑定定义/节点配置修订和本次运行。
- 主AI与秘书AI暂时共享同一个对话四级等级；用户主动设置后生效。两者工具资格、职责和主体身份仍分别判定。
- Shell、插件信任、WEX权限策略修改和凭证变更的专门边界尚为B候选；见产品级矩阵§6。

### 11.1 已确认政策与待决边界

- **已确认 A：** 工具/模块启用 → AI 工具资格 → Context 工具启用 → 当前执行位置授权 → 本次真实操作判权；IV级在明确授权范围内允许全部风险等级操作；工作流每次启动由用户确认本次完整节点权限方案一次；主AI与秘书AI共享同一个对话等级且须用户主动设置。
- **仍为 D：** Shell 提权/系统级操作、插件来源信任、WEX 自身权限策略修改、凭证新增/替换/删除的特殊信任边界；非对话入口的完整策略映射在实现和可信事实验收前不得默认允许。
- **仍为 C/D：** 撤权与派发竞态、有限次数原子消费、并发审批、Windows主体/IPC身份、审计提交一致性；未完成实验不承诺原子撤权或 exactly-once。
- **代码状态与政策状态分开：** 当前基础授权服务已有 PER-01～04 的公开实现和真实 SQLite 消费测试；D01/D02 的四级、节点方案一次确认、AI资格/Context开关的完整落地及非对话入口映射尚未实现。文档确认不能当作代码验收通过。

### 11.2 编号映射与维护

- F09-001～014 映射本节主体/入口、模块/全局/对话约束、资源判定、策略、对话等级、工作流启动确认、Grant、撤权、复核、审计、披露、重装失效和竞态能力。
- PER-01～PER-04 是原有稳定能力锚点；PERMISSIONS-* 是细粒度施工编号，不替换旧锚点。
- 新增、拆分或调整权限功能，只在 permissions owner 范围内分配新编号；不重排 F01–F15，也不让 app/shared/AI/workflows 建立第二份授权账本。
- A/B/C/D 状态沿用产品总表、D01/D02 与 D05/D06 决策；本节不把特殊信任边界和实验门槛自动升级为 A。
