## 1. 模块职责与范围

Space 是组织、Context 本体和组合引用的唯一业务 owner，不是工作流引擎、权限服务、资源内容仓库或全局项目管理器。

| 能力 | Space 拥有 | 不得隐式执行 |
|---|---|---|
| Space 类别、工作区与可选 Group | 组织结构及工作区目录登记 | 不强制类别/Group 对应磁盘目录 |
| 独立 Context | 身份、本体配置、存储定位与修订 | 不要求预先建立 Space、Task、Agent 或模板 |
| Context 放置关系 | 一个 Context 可被多个 Space/Group 引用 | 移动或解除放置不搬目录、不删本体 |
| Context 组合关系 | 关联 Agent、连接、资源、其他 Context、可选工作流与调度能力 | 不复制外域权威数据、不自动授权或启动任务 |
| 获准查询与失效诊断 | 组织和引用的可见投影、修订与失联状态 | 不泄露无权目标，不把失联误判为已删除 |
| Context 资源引用 | 多条引用及名称、定位、备注、用途等关系信息 | 不读取/复制外部正文、不把路径当资源永久身份 |

Context 可以不属于任何 Space；同一个 Context 多处显示仍只有一份本体。公共数据根、Space 工作区目录、独立 Context 目录互不等同。引用解除不删除目标、不撤销权限、不停止外部工作。

## 3. 必须遵守的业务边界

- Space 拥有 Context 本体及本域关系；`AI/` 拥有 Agent/角色实际配置，`conversations/` 拥有消息，`connections/` 与资源 owner 拥有外部资源及操作事实，`permissions/` 判定实际访问，`scheduler/` 维护调度状态。
- 创建、编辑、关联、解除、查询均需按实际主体、入口、目标和动作判权；Context 关联或显示位置不产生权限继承，不能对多个入口求授权并集。
- 修改应检查目标修订；旧修订不得静默覆盖。超时、取消和断连不自动证明写入失败；提交结果未知时先回读/按原意图核查，不能换新意图重复创建。
- 对失联目录、无法解析的资源、重复 Context 身份或无权目标，应返回受控的失败/不可用状态；不得静默创建替代对象，也不得泄露无权名称、数量或反向关系。
- 资源引用可含显示名称、路径/URL/仓库定位、备注、类型、来源及用途；关系身份和资源真实身份须区分。变更引用目标不能静默指向另一个真实资源。
- Space 对工作流与调度器仅保存按需组合引用；工作流定义和调度执行状态由各自模块拥有。
