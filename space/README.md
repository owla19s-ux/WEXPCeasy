## 1. 本模块到底管理什么

- **Category**：Space 的分类标签。类别不是目录、权限或组织账号。
- **Space**：组织入口，具有自身 ID、名称和可选工作区目录登记。Space 不等于目录。
- **Group**：Space 内可选的组织分组；不强制每个 Context 经过 Group。
- **Context**：独立的工作对象，有不可变的 **Context ID**、自身配置、存储定位及修订。没有 Space、Agent、Task 或模板也能创建。
- **Placement**：Context 在 Space/Group 中的一个放置关系，有独立关系 ID。同一 Context 可有多条 Placement，始终只有一个 Context 本体。
- **Association / ResourceReference / ToolSelection**：Context 对其他对象、资源或工具的关系记录。关系 ID 与目标 ID 不同；关联不复制目标、不授权、不启动执行。

Space 只拥有这些对象及关系。Agent 由 `AI/` 管理，会话由 `conversations/` 管理，连接和工具真实可用性由 `connections/` 管理，授权由 `permissions/` 管理，任务与调度由其各自 owner 管理。不能在 Space 中建立第二份外域权威状态。

## 2. 数据模型的最低不变量

| 对象 | 必须具备的语义字段 | 不变量 |
|---|---|---|
| Category | categoryId、显示名称、修订 | categoryId 不由名称推导；更改类别不迁移目录 |
| Space | spaceId、名称、类别关联（可选）、工作区定位（可选）、修订 | spaceId 与路径独立；目录失联不删除 Space |
| Group | groupId、所属 spaceId、名称、排序信息、修订 | groupId 稳定；移动不搬资料 |
| Context | contextId、名称、说明（可选）、自身配置、存储定位、修订 | contextId 创建后不可修改；不因重命名/放置变化而改变 |
| Placement | placementId、contextId、spaceId、可选 groupId、修订 | 解除一条关系不删除 Context 或其他放置 |
| Association | associationId、contextId、目标 owner/目标 ID、用途、修订 | 关联不是权限，也不复制目标本体 |
| ResourceReference | referenceId、contextId、名称、原始定位、类型/来源、备注/用途、目标 owner、修订 | 原始路径/URL 不等于资源永久身份 |
| ToolSelection | selectionId、contextId、能力身份、enabled、可选局部配置引用、修订 | Context 启用不等于全局启用或实际调用授权 |

上表是**业务字段语义**，不是冻结的 TypeScript 接口声明或数据库 schema。所有 ID 必须持久稳定、不能因显示名称改变而改变，也不能把旧 ID 分配给新对象。ID 生成、内部格式和恢复算法属于工程设计，按 §4.1～4.4 实施并验证，不要求用户选择 UUID 版本或数据库算法；不可借技术选择改变数据归属、权限或删除政策。

### 2.1 Association 子类型约束（细化现有模型，不新建引用底座）

以下是 **0.1.1 最小可施工约束**。同一目标允许被不同 Context 引用；同一 Context 中能否为不同用途保留多条同目标引用，不能由显示名称推断。未确认的基数规则采用“明确返回未支持/冲突”，不得静默去重或覆盖。

| 子类型 | 目标身份来源 | 是否必填 | 同一 Context 可否多条 | 唯一性与行为边界 |
|---|---|---|---|---|
| API / Model | API/Connection owner 的稳定 ID | 否 | 可引用不同目标；同目标多用途待定 | 不保存 Key；选择模型不等于可调用 |
| Role | AI/roles owner 的 roleId | 否 | 可引用不同角色；同角色多用途待定 | 不复制角色定义；选择角色不等于 Agent 已绑定职责 |
| Agent | AI owner 的 agentId | 否 | 可引用不同 Agent；同 Agent 多用途待定 | 与 Role/API ID 分离；关联不启动 Agent |
| Resource | 资源 owner 身份与独立 referenceId | 否 | 是 | 不因路径或名称相同而合并；资源身份变化需明确操作 |
| Tool / Capability | connections 提供的能力身份与 selectionId | 否 | 可选多个不同能力；同能力重复选择待定 | enabled 属 Context 局部选择；不等于全局可用或获准执行 |
| Other Context | 目标 contextId | 否 | 可引用多个不同 Context | 不递归展开目标内容、不合并权限；循环引用处理待定 |

所有子类型仍由 **Association 或既有专用关系记录**表达；不能因为表中列出子类型就再建一份并行关联表。引用的目标身份、引用记录身份、Context 身份必须分离。未知目标类型不自动放行，应返回“不支持的引用类型”；未来扩展须由目标 owner 提供可核验的身份与最小状态投影。

### 2.2 引用、配置选择、执行绑定三层

- **引用**：Space 保存“Context 关联了谁”，由关系 ID、目标 owner/ID、用途和修订表示。
- **配置选择**：Space 仅保存经目标 owner 明确允许的 Context 局部选择或配置引用；具体模型参数、角色定义和全局 Connection 配置仍归各 owner。
- **执行绑定**：某次对话、Agent 或工作流使用哪个目标，以及是否有权运行，由实际消费者和 permissions 决定；Space 不产生可执行授权或运行实例。

同一 Context 可以没有 API、Role、Agent、工具或工作流引用；**缺省引用不意味着继承最近使用的目标**。有效配置优先级未冻结时，仅返回已确认的显式选择及冲突，不推断默认执行绑定。

## 3. 每个功能的可施工行为

下表中“写入”均要求可信主体/入口、操作意图和预期修订（新建对象除外）；成功返回权威 ID、修订及获准投影，旧修订返回冲突，权限拒绝不产生副作用。提交结果未知时按原意图回读，不能新建意图盲重试。查询必须按真实入口授权。

| 功能 | 状态 | 操作、输入与结果 | 必须禁止或明确处理 |
|---|---|---|
| F01-001 类别 | 基础必做；删除阻塞 | 创建/读取/重命名类别；按 categoryId 将 Space 归类，返回类别/归类修订 | 类别不绑定物理目录、不授予权限；类别删除策略待决 |
| F01-002 Space | 基础必做；归档/删除候选或阻塞 | 创建/按 spaceId 读取/编辑名称和描述；返回稳定 spaceId 与修订 | 归档、恢复、实际删除细节未冻结；删除不得级联删除 Context |
| F01-003 工作区登记 | 基础必做；迁移阻塞 | 按 spaceId 登记用户明确选择的目录，查询定位与观察状态 | 失盘时保留原定位；不得自动生成空目录或搬迁资料 |
| F01-004 Group | 基础必做；跨 Space 移动候选 | 在 spaceId 下创建/读取/重命名/排序 Group；返回 groupId、组织关系及修订 | Group 可选；移动不迁移 Context 文件；跨 Space 移动/删除政策待决 |
| F01-005 Context 创建 | 必做 | 无 Space 前置条件，创建 Context；返回 contextId、初始修订、存储定位；重启按 ID 读取 | 不把名称或目录当 ID；不隐式创建 Agent、Task、Space |
| F01-006 Context 配置 | 基础必做；覆盖优先级阻塞 | 按 contextId 读取/编辑名称、说明及自身配置；返回同一 ID 与新修订 | 不把外域 Agent/会话/权限数据塞入 Context；旧修订不得覆盖 |
| F01-007 多处放置 | 必做 | 以 contextId、spaceId、可选 groupId 添加 Placement；按 placementId 移动/解除 | A、B 两处引用同一本体；解除 A 不影响 B、本体或目录 |
| F01-008 组合引用 | 必做 | 按 contextId、目标 owner/ID 添加、查询、解除 Association | 不复制目标、不递归开放其他 Context、不自动授权 |
| F01-009 有效配置 | 部分必做；覆盖策略阻塞 | 返回 Context 自身设置、明确关联及来源/冲突/失效状态 | 覆盖优先级未决；不得静默采用旧配置或擅定默认顺序 |
| F01-010 删除分离 | 解除必做；本体删除阻塞 | 支持 Placement/Association 单独解除；可提供只读删除影响预检 | Context 本体破坏性删除暂缓；检查不完整不得删除 |
| F01-011 可见查询 | 必做 | 按主体、入口、范围查询可见 Space/Group/Context/关系及修订 | 不泄露无权目标的名称、数量、反向引用或存在性 |
| F01-012 接回诊断 | 诊断部分必做；迁移阻塞 | 按 contextId 与记录定位检查失联、重复身份、待接回状态 | 自动物理迁移/自动合并暂缓；不能以同名空对象冒充恢复 |
| RESOURCE-001 多条引用 | 必做 | 一个 contextId 可新增多条有独立 referenceId 的资源关系 | 不用单个 projectPath 取代集合 |
| RESOURCE-002 描述字段 | 必做 | 每条引用独立保存名称、路径/URL、备注、类型、来源、用途 | 显示名和路径不是资源真实身份；不存文件正文 |
| RESOURCE-003 编辑 | 必做 | 按 referenceId、期望修订修改描述或请求重定位 | 真实目标改变时不能静默改指；来源无法核验则标记未决 |
| RESOURCE-004 解除 | 必做 | 按 referenceId 解除指定关系，返回关系修订 | 不删除目标文件、仓库、产物；不取消 Task |
| RESOURCE-005 状态 | 候选/部分施工 | 返回未验证、可用、失联、过期、身份冲突、无权等观察及时间 | 失联不等于已删除；旧观察不冒充当前状态 |
| RESOURCE-006 别名 | 候选/部分施工 | 使用资源 owner 的身份依据报告确认相同/可能重复/未知 | 不能靠名称或路径字符串自动合并 |
| RESOURCE-007 版本 | 候选/部分施工 | 保存来源 owner 返回的版本/修订观察，标识来源变化 | 不复制来源正文、不代替工作流验收 |
| TOOL-001 工具开关 | 必做 | 按 contextId、能力身份添加/启用/停用/移除 ToolSelection | A Context 启用不使 B 启用；停用不卸载全局连接 |
| TOOL-002 局部配置 | 候选/部分施工 | 保存 Context 专属工具参数和安全凭证引用及修订 | 不改全局 Connection；不存明文 Key；覆盖规则未决则不覆盖 |
| TOOL-003 候选解析 | 必做 | 返回已选、停用、失联、配置冲突的 Context 工具状态 | 不代表 AI 资格、工作流许可或 permissions 最终授权 |

## 3.1 API、角色与 Agent 的显式引用操作（沿用 §2 Association）

**Context 必须能主动添加、查询、更换和解除 API 配置引用与角色引用**，不能仅用“组合关联”四个字代替功能。三种概念严格分离：

- **API / Model 引用**：Context 选择一个由 `connections/api/` 管理的 API Connection、Provider/Model 或模型配置对象（以该模块实际公开身份为准）。Space 保存目标 owner、目标 ID、用途、关系 ID 和修订；不保存 API Key 明文、不复制 Provider 配置，也不直接发起模型请求。
- **角色（Role）引用**：Context 从 `AI/` 所拥有的角色定义中选择角色；保存角色目标身份、关系 ID、用途、启用状态（如业务确有需要）及修订。角色的提示词、权限资格和实际定义仍由 AI owner 管理；Space 不创建角色副本。
- **Agent 引用**：若 Context 需要绑定具体 Agent 实例，则单独引用 Agent 身份；**角色引用不自动创建 Agent，API 引用也不自动创建 Agent**。岗位、角色、Agent、API/Model 是不同概念，不能用一个字符串字段混合存储。

| 功能 | 输入 | 成功输出与行为 | 异常与拒绝 |
|---|---|---|---|
| 添加 API/Model 引用 | contextId、API owner 的稳定目标身份、用途、调用主体/入口、操作意图 | 新 associationId、目标身份、关系修订；重启后仍可查询 | 目标不可验证或无权时不伪装可用；不能把 API Key 写入 Space |
| 更换或解除 API 引用 | associationId、明确的新目标身份（更换时）、期望修订 | 原关系按明确意图更新或解除；不修改全局 API 配置 | 不静默改指其他 Provider/Model；不撤销其他 Context 的引用 |
| 添加角色引用 | contextId、roleId（由 AI owner 提供）、用途、操作意图 | 新 associationId、roleId、关系修订；可查询 | 角色不存在、无权或不可用时返回受控状态，不复制角色定义 |
| 更换或解除角色引用 | associationId、新 roleId（更换时）、期望修订 | 只修改本 Context 的关系；其他 Context 不受影响 | 不删除角色，不修改角色全局提示词或权限 |
| 关联 Agent | contextId、agentId、关系意图 | 独立的 Agent 关联与修订 | 不把 Agent ID、Role ID、API Connection ID 混成同一身份 |
| 解析 Context 的 AI 组合 | contextId、可信主体/入口及目标 owner 的当前观察 | 返回已选 API/Model、角色、Agent 的引用及可用/失联/无权状态 | **不自行推断默认模型或角色绑定优先级**；组合选择不等于授权模型调用 |

**验收补充**：创建 Context C，分别添加 API 引用 A 和角色 R；重启后两条关系及各自目标 ID 不变；更换 A 不影响 R，更换 R 不影响 A；同一 API/角色可被另一个 Context 引用；解除 C 的关系不删除全局 API/角色；无权入口不能查询其名称或存在性。API 模型真实调用、角色运行行为由各自 owner 的测试负责，Space 只验证引用、解析和权限隔离。

## 3.2 引用生命周期与状态契约

| 动作 | 状态转换及修订 | 禁止的副作用 |
|---|---|---|
| 添加 | 无关系 → 已关联；创建独立关系 ID/初始修订；重复意图回读原结果 | 不创建目标、不复制凭证、不自动授权 |
| 替换 | 已关联 → 指向明确的新目标；须核验新目标及旧关系预期修订；目标身份不同须保留可追溯变更依据 | 不静默改指、不修改其他 Context 的引用 |
| 停用 | 对支持 enabled 的选择：启用 → 停用；关系仍存在且修订递增 | 不撤销全局连接、不自动取消在途任务 |
| 目标失效 | 关系仍存在；观察投影变为失联/不兼容/不可查询，附来源和观察时间 | 不自动删除关系、不创建同名替身 |
| 目标恢复 | 经 owner 重新核验后更新观察投影；原关系 ID 保持不变 | 不自动恢复执行权限、不复活已解除关系 |
| 解除 | 已关联 → 已解除；确认提交后该关系不进入当前候选集合 | 不删除目标、不撤权、不停止在途操作 |

**失效是目标观察状态，不是 Space 擅自改变引用意图。** 不支持启停的 Association 不得伪造 enabled 字段；应返回不支持操作。解除后的在途任务仍由实际运行 owner 决定，新的执行请求必须重新判权。

### 统一结果分类

所有操作须区分：`committed`（已确认提交，附权威修订）、`rejected`（业务/权限/校验拒绝，确认未提交）、`unavailable`（依赖不可用，不能假定目标已删除）、`failed_no_commit`（已证实未提交）、`unknown`（结果未知，按原意图回读）。另用结构化原因表达 `revision_conflict`、`unsupported_type`、`unsupported_action`、`identity_conflict`、`target_unverifiable`；这些结果区别是本轮最低施工要求；TypeScript 类型名和枚举拼写由实现决定，不要求机械照抄。无权与不存在的对外呈现必须遵守不泄露存在性要求。

### 3.3.1 可信请求、去重、取消与提交结果

1. **可信上下文由宿主注入**：真实主体、入口实例及代次、适用职责来源与修订、操作动作和目标身份。外部文本、模型输出、UI 自报角色/管理员标识不能直接作为可信事实。Context 为空只表示没有 Context 范围，绝不代表全局范围或继承上一次选择。
2. **写入意图键**：按主体、入口、能力、意图 ID 识别重复请求。相同意图、相同规范化请求返回原结果；相同意图、不同内容拒绝。去重期限与跨重启保证在持久化适配验证前标为未证实，不得宣称无限期幂等。
3. **修订检查**：修改/解除需核对目标本体或关系的期望修订。旧修订拒绝，不采用最后写入获胜；冲突回执只能包含当前调用者获准查看的依据。
4. **取消**：提交前已确认未提交才返回取消成功；提交后取消不回滚事实；无法确认是否提交时返回结果未知，并按原意图回读。禁止用新意图绕过未知结果。
5. **外域目标状态**：引用写入前向 owner 取得最小可见身份及来源修订；owner 不可用不创建空替身。外域状态变化不构成 Space 的跨域原子事务承诺；必要时重验或报告依赖变化。
6. **写入证据**：至少可追溯意图、可信来源、目标、前后修订、变更与结果；不记录明文密钥或无权对象名称。

### 3.3.2 查询、缓存、变更通知与恢复

- 逐对象执行当前主体及入口的 read/list 判定；列表、数量、反向引用、分页游标均不得暴露无权目标。入口 A 的缓存和游标不能供入口 B 直接使用；撤权后重新判权。
- 查询区分目标已知失效、暂时不可查询、无权与尚未验证；对外错误细节必须服从防存在性泄漏策略。状态观察包含来源修订及观察时间，不能把旧快照说成实时事实。
- Space 的变更通知只携已提交对象/关系身份及修订的失效提示；消费者必须重新查询、重新判权。通知丢失以权威查询恢复，不要求全局可靠事件总线。
- 重启、失盘、身份复制冲突时保留原 ID 与诊断依据；替身测试不能代替真实多目录恢复测试。来源版本变化不能自动继承旧工作流验收结果。

### 3.3.3 真实执行资格链与删除竞态

- 工具有效候选至少依赖全局能力可用、AI 工具资格、Context 选择已启用及当前入口/工作流位置许可；**最终操作**仍须 permissions 对主体、入口、资源和动作判权。Space 只提供自己的选择事实，不能声称自己完成全部资格判定。
- 角色选择、AI 职责绑定、permissions 授权是三个独立提交；解除其中一项不自动撤销其他事实。
- 删除影响预检必须报告来源修订、完整性和观察时间；缺失任一项时阻止删除。即使预检无引用，检查后新增引用或在途工作仍可能发生；没有并发屏障和跨存储恢复验证前，不实现实际本体删除。

### 3.3.4 研究状态与施工证据

- **A（已确认原则）**：领域权威边界、独立 Context、多处放置、解除不隐删/扩权。
- **B（历史研究建议）**：未被当前施工要求收敛的高级目标观察、跨域协议及扩展行为仍是候选。本文 §3.2、§3.3.1 和 §4 明确规定的最小结果区别、去重与取消边界按当前施工要求执行；历史 B 标签不再用于否定这些要求，也不代表其他 B 全部获批。

### 4.1 数据权威、ID 与版本（本轮工程设计）

本节是本次授权补全的工程方案，尚无代码及故障验证证据，不表示已实现或已验收；技术方案若验证失败须报告具体反例并修正，不以替身通过宣称兼容性成立。本节收敛技术机制，不扩大 §3 的功能范围。采用现有 shared SQLite Store；不引入第二套存储引擎、不承诺跨目录原子事务。工程选择与依据：把全部 Context 放公共库不符合已确认的数据位置要求；要求多个目录同时原子提交超出现有 Store 能力，因此采用“本体单库提交 + 可恢复登记索引”。

| 数据 | 权威位置 | 索引及副本边界 |
|---|---|---|
| Category、Space、Group、Placement | 公共数据根内 Space 专属 Store 命名空间 | Placement 只引用 Context ID，不保存 Context 配置副本 |
| Context 身份、名称、说明、自身配置、Association、ResourceReference、ToolSelection | 用户明确选择的 Context 数据目录内 Space 专属 Store 命名空间 | Association/ResourceReference/ToolSelection 与 Context 本体处于同一事务聚合；不因此存入其他模块的正文 |
| Context 定位登记、创建/接入进度 | 公共数据根内 Space 专属登记记录 | 可含 Context ID、目录定位、登记意图、阶段和最后观察修订；不是 Context 本体，不作为配置权威 |
| 目标状态、可见列表、反向引用、缓存 | 可重建投影 | 不作为外域身份或授权权威；不得由缓存直接允许访问 |

- 新对象使用宿主提供的随机 ID 生成器，生产实现可用 Node `crypto.randomUUID()`；测试可注入确定序列。ID 作为不透明字符串，不暴露算法依赖；禁止按名称/路径生成、复用旧 ID，检测到碰撞即拒绝。该选择是工程实现，不是用户指定算法。
- 每个存储聚合保存格式版本、所属领域、根/Context 身份；首次创建写入后不可因目录名改变而改写身份。Context 身份记录和本体写入同一 shared Store 事务，不另建一份可独立改写的身份文件。
- 对外对象/关系修订和 Store 聚合修订分离：业务变更增加受影响对象/关系修订，CAS 使用实际读到的聚合修订；仅修改一个关系不增加无关对象的业务修订。不得把任意聚合变化误报为所有 Context 均已修改。
- 技术文件名、命名空间和序列化结构由实现确定，首次落盘前在存储适配器与格式夹具中固定并测试；打开旧数据必须校验格式版本与身份。不支持的新版本或损坏记录阻写并返回诊断，不自动清空、降级重建或覆盖。格式变更须提供显式兼容/迁移验证，不能靠重新生成 ID。
- 一个目录不能隐式创建第二个不同 Context；一个 Context ID 在两个不同位置出现时标记身份冲突，不自动认定为同一本体或最新副本。Windows 路径别名识别未验证前不得宣称跨别名唯一性已保证。

### 4.2 创建、接入与公共索引恢复

**创建和接入是不同动作。** 创建要求明确的数据目录及创建意图；接入要求读取已有 WEX 身份。空目录、普通资源目录不自动成为已有 Context，读取/诊断不隐式创建任何目录或本体。

创建最小步骤：
1. 可信宿主核验真实入口、操作权限和用户选定位置；检查路径边界、已有身份及写入可用性。若需创建新的专属子目录，必须属于本次明确创建请求，不能在读取失联记录时补建目录。
2. 在公共登记 Store 原子记录创建意图、预分配 Context ID、定位和 pending 阶段。意图重复先回读；该记录不进入可用 Context 列表。
3. 在目标目录的 Store 原子写入身份、初始 Context 本体和原意图结果；已有其他身份拒绝覆盖。不得因重试再分配 ID。
4. 确认目标提交后，再以 CAS 将公共登记更新为 ready，并保存本体来源修订。只有本体提交和登记就绪均可确认时，整个创建请求返回 committed。本体已提交但登记失败/响应丢失，整体返回 unknown，附获准回读标识；不得返回“已证实未提交”。
5. 恢复按原意图检查 pending、目标身份和目标提交结果：未写本体可在重新判权、验证同一请求后继续原操作；已有匹配本体则补登记；缺盘/未知则保留 pending；身份不符则阻塞。恢复不自动重放外域操作、不删除遗留文件。

接入已有 Context 先验证格式、身份和当前权限，再登记已有 ID；重接同一已核验位置不生成新本体。发现同 ID 的不同位置先进入冲突诊断，不自动替换现登记。定位变更与物理迁移分开，本期不自动迁移或自动合并。

公共索引丢失或陈旧时，只能从用户明确选择且当前获准的目录读取身份和本体重建登记；不扫描所有磁盘。失联登记保留原 ID/定位，不能由索引“找不到”推断本体已删除。跨目录查询可部分失败，必须报告可见范围内的完整性；不能将未读到的部分按空集合计数。

### 4.3 写入、去重、结果回读与并发

- 每个业务命令包含能力、规范化输入、预期业务修订和意图 ID；可信宿主绑定主体、入口实例及代次。以这些可信范围组成内部意图键；不得直接拼接可歧义字符串，须使用确定编码或摘要，适配 shared 的 256 字符意图长度限制。
- 在同一次本体/组织聚合提交中保存变更与业务意图记录，包括规范化请求依据、结果 ID、前后修订。业务请求比较应独立于 Store 的整份聚合 JSON 比较：重试时不能用最新聚合重新构造“原请求”。
- 先验证当前身份及查询/回执可见权限，再查同作用域原意图：同内容回读原结果，不再次执行；不同内容拒绝。原意图结果也不得向撤权主体泄露；撤权后不得补做未提交阶段。
- 修改/解除先检查业务修订，再按聚合修订 CAS；其他对象并发导致聚合冲突时，只能重读并重验原命令，禁止覆盖最新聚合。提交未知必须先 query 原 Store 意图并核对业务记录；query 无记录不证明从未提交，不能单凭空结果自动重写。
- shared 的 committed 映射确认提交；not_committed 按原因映射冲突、无提交或依赖失败；unknown 原样保留。业务多阶段操作按 §4.2 汇总，不能只看最后一次写入。
- 本期不自动清理意图记录，不承诺无限期去重；保证范围为同一兼容存储中记录仍完整保留的原意图。重启测试必须真实关闭并重开数据库。损坏或丢失记录返回不可判定，不声称仍有去重保证。
- 最小取消实现可只保证提交前检查取消；提交开始后不承诺可中断。提交后返回已提交事实，状态不明返回 unknown。关系解除保留必要意图/修订证据，不复用 ID。
- 同一公共根及 Context 数据根的写者协调复用 app/shared 的公开能力；shared 的 SQLite CAS 只解决单库写竞争，不证明跨根锁、路径别名或跨目录事务已解决。锁证据不可核验时阻写。

### 4.4 权限与目标 owner 端口

**真实权限依赖**：现有 `PermissionReader.evaluate/recheck` 来自 `permissions/src/index.ts`；主体与入口事实由宿主的 TrustPort 绑定。Space 只消费窄判定能力，不实现 grant/revoke、不读取权限私库，也不接受调用者自报 `authorized=true`。

| 环节 | 最小语义输入 | 必须处理的结果 |
|---|---|---|
| 组织/本体操作 | 宿主绑定的请求、精确动作、对象/关系及所属范围；列表请求声明枚举范围 | allow 才读写；deny/indeterminate 不执行；写入提交前 recheck，查询返回前对实际输出重判 |
| 创建 | 精确创建动作和选定容器/目录，不能依赖尚不存在对象的旧授权 | 缺少可映射的创建范围返回阻塞，不继承父目录无限权限 |
| 外域身份解析 | 当前可信请求、目标 owner/类型/ID、用途；资源定位变化带旧身份和新定位 | 获准最小身份、来源修订、观察时间；或不可查询、依赖不可用、不支持、身份冲突 |
| 工具局部配置验证 | 已核验能力身份/版本、拟保存的配置引用或允许参数 | owner 明确支持才保存；拒绝秘密值及不支持的覆盖，不改全局配置 |
| 关系解除 | 本域关系 ID、当前权限、预期修订 | 不因目标 owner 离线而要求删除目标；无需外域成功确认即可解除本域关系 |

目标端口由 app 绑定实际 owner 的公开能力，Space 中只定义消费方最低语义；不冻结其他模块接口。测试替身须标明身份/权限事实为注入。真实 owner 无端口时保留稳定领域代码与受控 unavailable，不编造可用目标或建立外域配置副本。

- 新增/替换须有可核验的目标身份；资源 owner 尚不能确认时不提交为可用关系。既有关系目标失联时保留关系，当前投影不可用；无权响应不暴露目标是否存在。
- 普通 Association 不默认支持 enabled；API/Role/Agent 更换保留关系身份、记录明确的新目标及修订；资源改指不同真实对象依 §3 的 RESOURCE-003 建新引用或显式解除再新增，不能套用普通替换静默改指。
- 查询关系同时满足本域可见性和目标最小投影权限；不能先返回关系总数再过滤秘密目标。首期可不做缓存与分页，直接权威读取；一旦实现缓存/游标，必须满足 S17，不能因此免除隔离要求。
- owner 观察不是跨域原子承诺。核验后来源变更可使观察过期；执行消费者重新解析并最终判权，Space 不保存可永久复用的允许决定。

**当前接入阻塞**：现有 permissions 对 `local/task/callback` 返回 `entry_policy_unresolved`；Space 的直接用户操作属于真实 local 入口，禁止伪装 conversation。可完成领域测试、真实存储测试与真实权限拒绝测试；实际直接操作正向闭环须由 permissions owner 按已确认 D01 政策收敛本地入口范围、由 app 注入可信事实后再组合验收。此处只登记依赖，不授权 Space 修改权限政策或扩大本模块施工范围。创建/读/list 的范围映射缺失同样是接入阻塞，不能用测试宿主通过替代。
