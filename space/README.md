## 一、职责与数据权威

- **类别（Category）**是 Space 的导航归类，不等于物理目录或权限域。
- **Space** 是可登记用户选择工作区目录的组织入口；**Group** 是可选的组织层。
- **Context** 是独立的长期工作对象：有稳定身份、名称、描述、配置、定位与修订；可以不属于 Space，不需要 Project、模板、Task 或 Agent。
- **Placement（放置关系）**连接 Space/Group 与 Context；同一 Context 可以有多处放置，只有一个权威本体。**Association（组合引用）**连接 Context 与资源、Agent/角色、连接、工具能力、其他 Context 等；关联不等于复制或授权。
- Space 只维护上述本域事实及可见投影。实际 Agent/角色归 `AI/`，会话归 `conversations/`，连接与 Operation 归 `connections/`，权限归 `permissions/`，调度归 `scheduler/`，资源正文与来源版本归其真实 owner。不得把各域状态集中写入 Space。

公共数据根、Space 工作区目录、Context 独立目录是不同概念；登记目录不自动搬迁文件。目录失联保留身份与定位，禁止生成同名空本体冒充恢复。

## 三、公开能力的输入、输出与约束

以下是**业务接口语义**，不是已经批准的 TypeScript 函数名、表结构或 IPC 协议。实现签名按现有代码与宿主端口收敛，禁止创造第二套领域权威。

| 能力 | 必需输入语义 | 返回与失败语义 |
|---|---|---|
| 创建/修改/读取类别、Space、Group、Context（SPC-01） | 可信调用身份/入口、目标或父级、操作、明确配置；修改含期望修订、写入意图 | 本域稳定 ID、已提交修订、获准投影；无权、父级失效、旧修订、存储不可用或结果未知必须区分 |
| Context 放置/移动/解除（SPC-02） | Context ID、源/目标组织位置、关系 ID/意图、期望关系修订 | 返回放置关系及修订；解除仅改变关系，不删本体或目录；旧修订拒绝 |
| Context 组合引用（SPC-03） | Context ID、目标 owner/身份、用途、关系意图与修订 | 只提交本域关系；目标不存在、不可见、不可用、身份冲突要受控处理 |
| 查询与失效诊断（SPC-04） | 可信主体、实际入口、获准目标/范围 | 只返回获准对象、关系、修订和观察状态；无权不泄露存在性、名称、数量 |
| Context 资源条目（SPC-06） | Context ID、关系 ID、名称、定位、备注、类型/来源/用途、期望修订 | 单条新增/修改/解除；定位变更不能静默换目标；返回关系修订及可见状态 |
| Context 工具组合（SPC-07） | Context ID、能力身份、加入/启停/移除意图、可选局部配置及修订 | 返回 Context 选择状态；未加入或停用不得进入本 Context 候选；不代表执行已获权 |
| 删除预检（SPC-05，非实际删除） | 明确删除目标、授权及引用/在途影响查询 | 只返回获准影响与阻塞；检查不完整或竞争未关闭不得执行本体删除 |

**统一规则**：可信主体、入口与授权依据由宿主/permissions 提供，不接受模型文本自报；写操作检查期望修订与意图去重；同一意图重送相同请求不能重复创建，相同意图不同内容拒绝。返回至少区分已确认提交、业务拒绝、确定未提交、依赖不可用、结果未知；超时/断连/取消不能直接当作回滚。未知结果按原意图查询或回读权威修订，禁止盲目换新意图重试。读操作每次重新判权。

## 四、资源引用与工具开关的具体行为

**资源引用**：每条关系有独立身份；可保存名称、原始路径/URL/仓库定位、备注、类型、来源、用途、目标 owner 及获准的来源观察。资源的真实身份、正文、版本和读写权由来源 owner 决定。一个 Context 可以引用多项资源；同一资源也可以被多个 Context 引用。编辑备注不改目标；修改定位若被解析为另一个真实对象，不得静默改指。解除引用不删除文件、仓库、工作产物，也不撤权或取消任务。状态至少能表达未验证、可用、失联、观察过期、身份冲突与无权；无来源证明时不得靠路径字符串自动合并。

**工具组合**：Context 独立保存已选择工具/连接器能力及启停状态；A 启用不使 B 启用。停用或移除不卸载全局 Connection、不删除凭证、不宣称取消在途 Operation。局部配置不能覆盖其他 Context 或全局配置；秘密明文不进入 Space。工具最终可调用必须另满足模块/Connection 可用、AI 资格、Context 启用、当前入口与工作流位置授权及 permissions 对具体动作的判定；Space 只提供 Context 侧选择事实，**不能自行批准执行**。

## 五、模块独立验收用例

| 用例 | 必须断言 |
|---|---|
| S01 独立 Context | 不存在 Space/Group/Agent/Task 仍可创建、修改、重启读取同一身份 |
| S02 组织与目录 | 类别/Group 变化不迁移文件、不改变权限；目录失联后保留原定位并报告不可用 |
| S03 多处放置 | A/B 同时引用 C，解除 A 后 B 和 C 不变；目标删除、撤权、取消调用均未发生 |
| S04 配置与并发 | 修改名称不换 ID；旧修订拒绝；同意图重复请求不重复提交；未知结果可回读 |
| S05 资源条目 | 一 Context 多条不同资源引用，名称/地址/备注独立编辑；解除单条不删资源 |
| S06 资源身份 | 目标身份改变不得静默重定向；无法确认别名时不合并；失联与已删除不混淆 |
| S07 工具隔离 | A 启用工具 X、B 停用；B 无候选；全局停用或 AI 无资格时 A 也不能实际派发 |
| S08 权限隔离 | 未授权入口的读取、列表、统计、反向关系不泄露目标；Context 关联不自动扩权 |
| S09 故障恢复 | 存储故障、重启、重复身份、来源不可用和提交结果未知均不创建替代空对象 |
| S10 删除边界 | 解除放置/关联不触发本体或外域删除；删除预检无法证明安全时实际删除被阻止 |

验收需提供**真实模块源码和可重复测试**，消费者使用公开接口而非读取私有数据；依赖未就绪时可用窄端口替身测试，但必须标记“替身通过，真实集成未验收”。Windows 多目录、ACL、跨存储恢复和外部服务实测另行标注，不得冒充已通过。

## 六、实施步骤与交付状态

1. **核查现有代码**：最新 main 下检查 `space/` 的实际文件、公开出口、测试、存储与依赖；对照本表逐项标注已实现、部分实现、未实现、阻塞，禁止重写已有功能。
2. **本体与组织**：先实现可独立持久化/恢复的 Context、Space/Group、身份与修订，再做放置关系。
3. **引用与查询**：按已确认范围实现资源引用、Context 工具启停、组合关联及获准查询；只消费其他模块的公开能力。
4. **异常与测试**：覆盖 S01～S10 中本版可执行的用例；真实依赖缺失则报告具体阻塞，不私自扩大模块范围。
5. **交付回执**：提交 SHA、源码/测试路径、测试命令和结果、逐项功能状态、未验证项及需要裁决的问题。工作模式**不得修改任何 README/CONTRACT/研究文档**。
