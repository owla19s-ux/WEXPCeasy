# WEX｜AI 施工与验收入口

> 仓库：`owla19s-ux/WEXPCeasy`｜产品：WEX｜当前主线：Windows PC｜默认分支：`main`
>
> 本文件只负责 AI 协作规范、仓库操作和模块导航。完整项目说明见 [docs/PROJECT.md](docs/PROJECT.md)，不是日常施工前置阅读。

## 当前模块与下一模块

- **当前模块：[shared/](shared/README.md)** — 基础模块复验入口。开始前先检查实际代码和测试；已有成果不得重写。此处仅指向既有施工顺序，**不表示已确认当前存在未完成工作**。
- **下一模块：[permissions/](permissions/README.md)** — 只有当前模块经普通对话模式检查、验收并更新入口后才切换。
- 后续模块由普通对话模式在验收时更新本入口；不要按历史批次编号自行跳转。

## 两种模式的职责

**工作模式（施工）**
1. 读本 README → 读当前模块 README → 检查最新 `main`、源码与测试。
2. 以**单个模块**为施工单位，核对已实现功能，只补未完成部分；按模块职责、公开接口和既定要求实施、独立测试、修复并提交。
3. **不得修改仓库内的施工文档**，包括根 README、模块 README、任务要求和研究/契约文档。施工发现文档错误、范围冲突或新增需求时，只在回执中报告，不自行改写规范。
4. 回执包含提交 SHA、变更代码、测试命令与结果、未验证项及阻塞问题。提交不等于验收通过。

**普通对话模式（检查与验收）**
1. 检查实际代码、测试、接口和施工回执，判断已完成、待修复或未验证的具体内容。
2. 负责更新模块 README 的阶段、已有实现、已验证内容、剩余任务和验收证据。
3. 验收当前模块后，才更新根 README 的当前/下一模块入口；未通过时保持当前入口并明确修复项。

> 工作模式只施工和报告；普通对话模式负责验收与维护文档。两者不互相代替。

## 模块化施工规则

- 模块 README 必须明确模块职责、功能要求、当前阶段、已有代码、已验证功能、剩余任务、接口边界及验收标准；**施工前仍须核对源码，避免因文档滞后而重复实现**。
- 业务数据与行为由所属模块负责；跨模块只通过公开能力，不建立全局业务状态总管，不将业务逻辑集中到 `shared/`。
- **不按跨模块业务链路组织施工**。业务链路只用于需求检查及模块独立完成后的组合验收。
- 遇到普通缺陷先在授权施工范围内修复；遇到未决产品决策、权限边界、真实依赖阻塞或文档矛盾，报告具体证据，不擅自扩大范围。
- 默认拒绝未授权入口；模型输出、角色名和提示词不能代替授权。研究原型、候选契约和历史报告不等于正式产品实现。
- 当前按**单 AI 施工**执行，不引入多 AI 任务领取、锁定或并发协调流程。

## GitHub 操作与验证

- 默认在 `main` 施工；仅在确有高风险隔离需求时使用短期分支。写入前核对最新 HEAD，避免覆盖已有修改。
- **每次检查 CI，先查 [Actions 总工作流运行列表](https://github.com/owla19s-ux/WEXPCeasy/actions/runs)**，确认最新运行集合、关联提交 SHA、状态与结论，再进入具体 workflow → job → 日志；不要只看单个固定工作流，也不要要求用户反复提供 Actions 链接。
- 已授权使用 GitHub Actions 执行必要测试，无需因额度回避。失败先查根因，修复后再验证，不盲目重跑。
- 代码提交、Actions 通过、实验通过不自动等于模块验收，更不等于 Windows 实机验收。
