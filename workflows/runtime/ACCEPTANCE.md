# Runtime 与调度｜独立施工和验收规格（2026-11-01）

状态：**业务契约细化 / 未实现**。本文件是 workflows/runtime 的施工与验收基准，不是正式状态机、算法冻结或测试通过报告。上位依照 workflows/CONTRACT.md 中 W02/W03/W05/W06/W07 与 WORKFLOWS-* 编号。

## 一、归属与最小实现单元

- workflows 拥有 Task、Run、Step Run、轮次、推进依据、检查点、产物/Review/Verification/Acceptance；runtime 是其内部执行协调子域，不新建顶层平台。
- connections 独占 Operation 意图、attempt、外部观察与 Receipt；permissions 独占授权；app 提供可信入口与生命周期；真实资源身份由具体连接器核对。Runtime 不能调用 GitHub SDK、DSH SDK 或 Shell 私有协议。
- 定义修改不影响已创建 Run 的修订快照；节点不是 Task；Operation completed 不等于 Task accepted。
- 普通聊天、单次工具调用及不需要调度的连接操作无须先创建 Task 或完整 Workflow。对真实资源存在冲突的副作用，可按需使用同一协调入口。

## 二、候选公开能力（只定语义）

| 编号 | 输入 | 输出/约束 | 独立验收 |
|---|---|---|---|
| R01 运行创建 | Workflow 定义修订、触发意图、主体/入口、权限方案引用 | 固定 Run 身份、定义修订、来源与审计关联 | 相同启动意图提交未知后按意图回读，不重复创建；变更定义不改旧 Run |
| R02 就绪计划 | Run、已满足的业务依赖、资源/能力摘要 | 候选 StepRun、等待/阻塞原因 | 依赖未满足、能力缺失、输入不合法不进入可派发队列 |
| R03 执行者路由 | 能力需求、Agent 资格、连接状态、责任修订 | 候选执行者及版本依据 | 名称相同不等于能力匹配；撤权不派发 |
| R04 配额与资源准入 | 真实资源身份、工作项、原占用/冲突观察 | 准入/排队/未知冲突及可核对关联 | 两 Context 同文件不得并发冲突写；路径别名判不清则阻塞 |
| R05 受控派发 | 已持久化工作依据、当前授权、资源许可、目标 Operation 意图 | connections 的 Operation 引用或明确零派发失败 | 必须先有持久意图与当前允许，再调用连接宿主；失败不伪装为执行失败 |
| R06 状态推进 | StepRun/轮次版本、Operation 观察、验证依据 | 新修订与推进理由 | 乱序/迟到回执仅写原 attempt；不覆盖新轮次；无证据不自动 accepted |
| R07 停止与暂停 | Task/Run/StepRun 标识、控制动作、原 Operation | 待停止/已确认/不支持/未知 | 关闭画布不是取消；已派发需外部真实确认；不支持时不能显示已停止 |
| R08 失败/重试/人工接管 | 原 attempt、错误分类、资源及授权核对 | 新轮次/新 attempt 或待人工裁决 | timeout/断连不盲重试；原结果未知不得产生第二次副作用 |
| R09 崩溃恢复 | 本地运行/操作引用、实例代次、远端 Session/文件/Git 观察 | 可继续观察、可安全推进、阻塞或待裁决 | 本地引用缺失不能推断未派发；重启先查 connections 和真实资源 |
| R10 持久检查点 | Task/Run 修订、目标、输入/版本、轮次、Operation、产物、阻塞、下一步 | 可跨对话回读的结构化检查点 | 新 AI/模型读取后重新判权与核对资源；不能只靠聊天摘要接续 |
| R11 可见投影 | 获准主体/入口、查询范围、当前 owner 修订 | 状态/进度/证据链接与新鲜度 | 撤权缓存失效、漏通知可补读、显示颜色不能修改事实 |

## 三、实现批次与完成标准

**R-B1 基础可施工：** Run/StepRun/Task 修订、固定快照、队列/依赖就绪、只读投影、检查点；用替身验证重复创建、并发 CAS、迟到结果、修订漂移。验收是公开消费测试，而不是仅私有单测。

**R-B2 受控派发链：** 持久意图 → permissions 判权 → 资源准入 → connections attempt → 受控派发 → Receipt 引用 → 核验推进。先以无副作用替身验证零派发及未知状态，再组合一个真实只读能力；任何写入外部动作必须另有明确授权。

**R-B3 持续性和冲突：** 两 Context 同资源、并发、旧回执、断连后写入未知、撤权竞态、进程残留、重启后重新核对。C 级机制未通过前不宣称资源互斥硬保证、恰好一次派发或自动恢复安全。

**R-B4 组合验收：** Space/Context → Workflow 定义 → 节点能力 → AI 资格 → 任务/运行 → GitHub 或 Local 连接器 → Artifact/Verification/Acceptance；包含 401/403/429、断网、冲突、用户暂停、人工接管。业务链路仅用于组合验收，正式施工仍按 owner。

## 四、硬性否决条件

1. 业务 Workflow/Task、Operation、Agent Session 三者混为一个状态机。
2. 编辑器移动节点或正交线改道导致派发/授权/依赖变化。
3. 重试在 unknown 下自动再次执行有副作用动作。
4. 资源协调按 Context 名称隔离，漏掉真实目录/Git 元数据冲突。
5. 将 DSH 或某 GitHub SDK 实现写进 workflows/runtime。
6. 无常驻宿主却声称关窗或系统关机后持续执行。
7. 把已有概念测试标为 Windows/真实外部端到端通过。

技术未冻结：持久队列/租约算法、冲突锁粒度、跨存储恢复屏障、后台进程形态。相关实验通过再定实现接口。
