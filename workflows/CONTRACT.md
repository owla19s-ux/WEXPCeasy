# workflows / runtime 业务契约（第四批设计草案）

基线：`owla19s-ux/WEXPC1@a62996af9863e60b15e4513389c7654719907920`。本文件为模块级设计，不是实现、正式状态机、函数签名、schema、IPC 或调度算法。W01 等仅为文档 ID。覆盖 L06/L07/L09/L10；链路用于分析与组合验收，不拆成多域共写 Task 的施工单元。

标记：**A 已定约束**；**B 本批推荐未批准**；**C 待实测门槛**；**D 重大产品/权限决策**。A 不代表已实现；具体算法/存储候选未定不因本文升级为 A。下文能力的细化语义均为 B，明确引用的既定职责除外。

## 1. Owner 与边界

**A** workflows 维护工作流定义及修订、Task 与工作轮次/分配、流程运行/步骤进展、产物引用、Review/Verification/Acceptance 记录。runtime 在本域承接派发、等待、继续、退回、恢复、资源及并发协调。connections 宿主唯一维护 Operation 意图/尝试/观察/回执，本域保存引用及“为何据此推进”的业务依据，不复制其正式状态。真实文件、提交、远端产物仍以来源系统为准。

**A** 定义不是运行实例，节点不是 Task，Task 不是 Operation；外部 completed、退出 0、回执保存、Review 通过、Verification 通过、最终 Acceptance 分别成立。`workflows/editor` 负责交互/呈现，不拥有业务事实；当前产品方向为 WEX 自研轻量自由格子画布。编辑定义和移动节点不触发执行。广义专业视图归 views，专业模式不把展示连线自动变成执行依赖。

可信入口由 app 建立主体与动作/目标范围。Context 可空；Context/角色名/分配记录不能授权。Task 可独立于工作流存在，普通聊天及单次调用无需 Task。**A** runtime 的资源协调以真实冲突资源为依据，可经宿主按需注入到 connections 普通副作用入口，不以前置完整调度器为条件、不造 Task；本域不得因拥有协调职责而实现 DSH/其他 Agent 协议。

## 2. 公开能力及行为样例

### W01 定义读取、结构化编辑与修订

提供给 editor、获准 UI/AI、modes 与运行规划；消费 permissions、持久化及必要专业规则公开能力。用户与 AI 通过相同编辑语义校验授权、目标版本及业务规则。Context 可空；跨 Space 可见不等于可修改。布局由视图 owner 维护，不写进执行定义或成为运行条件。

前提：有明确目标定义与预期修订；本域校验执行依赖、参数/类型和适用规则。对不存在/不可见目标返回适当诊断，不泄露隐蔽定义。确认提交后才公开新修订；已证实未提交与ACK丢失/提交确认未知分开，未知不宣称未写，按原意图读回确认。版本过期拒绝静默覆盖，返回调用者可见冲突；结构化重试须基于重新读取的版本，不整文件覆盖。

本域保存定义权威；运行绑定明确修订，后续编辑不默默改写在途执行依据。能力不支持的节点或规则阻止该修订启动，不能因画布能渲染就可执行。取消编辑是取消未提交修改，不能终止旧运行；timeout/断连后先查询目标修订是否已提交，不重复提交未知写入。

断言：两个编辑者基于 r4 修改，首个提交 r5，第二个冲突且 r5 不丢失；编辑/拖动后外部 dispatch 次数为 0；运行 x 绑定 r4，发布 r5 后 x 仍引用 r4；恢复编辑器不从任何画布库内部 JSON 倒写任务真相；保存已提交但ACK丢失后，原意图读回仍只有一个新修订，不能再提交一次。通知仅含可见变更提示/修订，消费者重新读取。

### W02 Task 建立、范围/职责分配与工作轮次

提供给对话转任务、UI、获准 AI 规划和模式；消费可见 Context 事实、角色职责配置、权限与存储。Task 记录明确目标、范围、输入依据和适用验收规则；角色配置只作职责依据，本域只保存本次分配，不改写角色模板或 Context 本体。Context 可空；缺 Context 不能推断全局资源授权。

本域是 Task 与轮次权威。分配改变工作责任，不等于派发、获权、完成；换执行者/返工/重派保留旧轮次和 Operation 引用。目标范围、输入版本或验收规则变更采用预期修订，过期拒绝覆盖；会影响在途工作的修改不得悄悄替换原轮次依据，应形成可审计修订及明确后续决定。

拒绝无权创建/修改/分配、不满足必要输入的任务；不因角色拥有工具名就允许执行。保存未提交或确认未知时均不发起外部调用；未知先按原意图回读，不能断言Task未创建。重复创建意图先定位已有结果，不能因 UI 超时创建两个任务；未知提交先查询，不能无条件重试。Task 取消请求进入本域后由 W06 处理，不能只删卡片。

断言：给角色“审查者”分配 Task 不改变 permissions 决定；普通消息不生成 Task；返工后轮次 2 存在，轮次 1 证据可查且未覆盖；同目标文字但不同用户意图不能仅按文本去重。

### W03 运行计划、推进与受控派发

提供给获准启动/继续者及程序规则；消费固定定义/Task 修订、职责依据、permissions、connections 能力及 Operation 观察、资源协调和存储。Context 可空；执行条件必须来自明确任务/定义/规则，模型建议不能修改目标或自批完成。

本域决定何时、以哪个候选能力/执行者、在哪一工作轮次发起请求。W03 对资源只作计划预检，不另持有一份执行占用；C02 派发前通过注入的 W05，以同一 Operation 意图、资源依据和适用修订获取/复核同一协调引用。前提为依赖已满足、版本仍适用、资源无冲突、并发配额允许且具备当前权限；排队不代表授权或执行。判权只有明确允许才能派发/取数，需要审批、不可判定、拒绝、超时/断连均零动作。实际外部协议/进程/文件操作只经 connections，调用前后本域只保存轮次及 Operation 关联；connections 负责先存 attempt 再派发。

连接拒绝应成为“本轮未派发/受阻”的业务依据，不能写成外部执行失败。外部明确失败、timeout、断连、unknown、观察保存失败分别处理：连接 timeout 不自动判 Task 最终失败；unknown 保持受影响工作阻塞并进入 W06。先存本域准备依据/关联后，跨域关联出现崩溃歧义时查询 connections，不能凭引用缺失补发。**C** 两域持久关联的原子性/恢复屏障待实验，不能声称 exactly-once。

取消排队只撤销未派发计划；派发后按控制能力请求停止。重试创建新尝试/轮次依据，保持原历史；不得把“再点一次继续”当未知结果的自动重派。并发修改计划时使用本域预期修订；旧计划/旧结果不覆盖当前轮次。

断言：排队后撤权则 dispatch 为 0；connections attempt 写失败，本域有受阻依据但无外部成功；文件已改后断连，本域不第二次发起修改；同一运行定义 r2 被编辑为 r3，不改变原运行依赖图；本域测试不导入 DSH SDK/NDJSON 解析。

### W04 产物、Review、Verification 与最终 Acceptance

提供给获准审查/验证/验收主体、UI 与程序推进规则；消费 Operation 可见证据及独立资源读取/核验能力。产物引用必须能指向具体来源、版本/内容证据、环境和本轮关联；外部给出的路径与文本均不可信，读取/发布仍须独立授权。Task/运行可无 Context；验证资源权限不能从 Task 分配继承。

本域保存核验/审查/验收记录及其依据，真实产物由资源系统维护。核验规则、验证执行者与最终验收权限应可区分；模型可提供分析，不因此有权改变最终 Acceptance。外部 completed 仅作为证据；缺少产物、来源/版本无法确定或环境不符时不能据此通过。

验收前复核目标版本与规则修订；验收后资源变化使旧结论仅适用于旧版本，当前版本必须显示未核验/需重核，不沿用通过。并发验收请求按本域修订检查，防止两个主体覆盖相反结论；重复同一证据接收可去重，新增或矛盾证据保留出处。核验工具失败/超时/断连应记录“未完成核验/未知”，不能当产物失败或通过；验证过程副作用须另经 connections。

验收保存明确未提交或确认未知均不能宣告已提交；未知亦不能宣称未写，断连重试先以原意图查验收修订，ACK丢失读回不新增第二条提交。取消验证不撤销已经观察事实，补偿/回滚产物是另一个获权 Operation。**D** 哪类任务允许程序自动 Acceptance、最终验收主体及规则变更权限须产品/权限决策；本文不默认用户每次手工确认，也不授权模型自批。

断言：DSH completed 且 exit 0，但文件版本与目标不符，Task 不通过；v7 通过后文件改为 v8，v7 记录保留，v8 不显示已验收；Review 通过而 Verification 未完成不能自动等价 Acceptance；结果保存成功但核验失败，Operation 事实不被本域改写。

### W05 真实资源冲突与占用协调（runtime 对宿主可注入）

提供给 W03 以及 connections 受控副作用入口；后者可无 Task/流程，宿主按需装配此能力。消费适配器提供的真实 backend、路径/别名、Git 元数据/工作区、远端对象及外部 session 线索；授权仍归 permissions。只协调 WEX 纳管工作，不承诺阻止用户或外部 Agent 自主执行。

本域维护 WEX 工作资源协调依据/未决占用；connections 维护 Operation 观察，两者互相引用而不双写。资源以实际冲突判定，不按 Context/Agent 名区分；不同 Context 的同一目录、Git 共享元数据、构建输出或外部 session 可能冲突，远程/容器 cwd 不当作本机路径。身份无法确认时返回无法安全协调，不能臆造无冲突。

协调请求绑定同一 Operation 意图、规范化资源依据和预期协调修订。W03 计划预检不占用；C02 派发前获取/复核的协调引用同时供本域追踪，重送沿用原关联，不能各自申请造成自锁。最小结果须说明请求是否登记、是否由该意图持有、是否因未知占用阻塞、是否已释放，以及适用修订和决定证据；这些是业务信息，不冻结枚举、字段或锁算法。修订过期拒绝变更，协调提交未知按原意图读回且不派发，不假定已释放。取得协调许可不授予读写权。动作前资源版本变化或新冲突使许可不再适用，应重新判断；同一协调引用不能对其他意图、路径或失效资源依据复用。unknown 或已请求取消未确认停止时维持受影响资源冲突，不因 timeout、租约到期、关闭视图或进程退出释放；释放必须写入与原持有引用关联的证据及新修订，依据为足够停止/资源核验/有权裁决；单纯取消请求不构成释放证据。无冲突工作可以继续。

排队取消可撤销待协调请求；已执行动作只能请求停止/核验。重复协调请求返回原关联，不产生双份可用许可；重启先恢复未决依据，未完成恢复前不得宣布资源空闲。**C** 占用持久化、别名与 Git 资源粒度、并发原子获取、崩溃及租约/fencing 均待窄实验，不预选算法或承诺全局文件锁。

断言：Task T 对目录 P 结果未知，普通聊天对 P 的副作用被阻止且没有新 Task；对无冲突 Q 的获权动作可继续；Context C1/C2 指向别名同一 P 仍冲突；外部自行改文件后，即使本地无占用仍需版本复核；取消请求已发送但未确认，P 不释放。

### W06 暂停/退回/继续、停止请求及重启恢复

提供给有相应控制权的主体、app 生命周期及程序规则。消费本地任务/轮次/协调历史、connections 可查询观察/可选控制与外部定位、独立资源核验、当前权限及存储。Context 可空；关闭窗口/解除 Space 引用不触发取消，应用退出与任务停止分开。

本域决定继续、返工、阻塞、升级和是否允许新轮次，不自行操作外部进程。恢复先建立本地关联，再查询实际可得外部会话/操作/资源事实；会话历史恢复不等于附着活跃执行，外部 not found 不必然未执行。不支持 query/resume/interrupt 的连接明确保留限制，不迫使连接器伪造一致能力。

恢复遇到已持久准备依据却缺派发确认、外部已改文件、结果保存失败或备份落后时保持歧义，先核对版本/归因；不能从缺少记录推出未执行。迟到 a1 结果归原轮次，不能覆盖 a2 当前状态；重复证据去重，矛盾证据保持可见。恢复/停止请求按当前身份和范围重新授权，旧批准仅为历史，不是永久凭证。

请求取消、执行方确认停止、停止等待、已知副作用和补偿各自留证。明确无新副作用且依赖/权限/版本仍满足才能继续；未决时有权主体可作显式裁决并记录风险/依据，但不能改写外部历史。重试必须说明原 Operation 为何可安全重试，或者获权启动新的不同工作；清空 unknown/删除卡片不是恢复策略。

所有本域写入均区分确认提交、证实未提交和提交确认未知；ACK丢失按原意图回读，不以新意图生成重复修订/记录。存储恢复失败则禁止依赖未恢复状态的新冲突派发；外部查询 timeout 保留原未决状态；取消竞争中的新执行世代不可被旧取消误停。**D** 退出时驻留、排空/等待策略及允许有权主体解除未决阻塞的权限/条件需产品决策；没有常驻宿主不承诺关机后继续。**C** Windows 重启/休眠/进程树与 DSH 真实会话恢复待实测。

断言：重启恢复到已提交准备记录但查不清是否发出时不自动 submit；备份回滚后外部已有提交，不当作外部也回滚；a1 completed 晚于 a2，不通过 a2 验收；停止确认仍保留已发生文件变更；撤权后禁止后续外发，但不声称收回已交给 Agent 的资料。

### W07 获准投影、状态诊断与通知

提供给 UI、views、conversations、modes。返回获准 Task/定义/运行/证据引用及诊断，而非可变内部对象；按当前权限过滤，引用不可见时给适当不可用诊断，不泄露隐藏目标细节。Task 业务状态、连接在线性、外部报告、回执持久性、核验及验收分别呈现。

投影可重建，不接受其倒写权威。通知只是有新修订/证据可查，允许漏失/重复；消费者按可见版本重新查询，断连标示截至时间。查询失败不把未知变成空任务或已停止。撤权后不得继续通过缓存呈现受限资料。读取可有界重试，状态写入须走对应能力和修订校验。

断言：视图把节点染绿不会完成 Task；漏通知后查询可得已保存验收；无权消费者看不到产物路径；Operation 新观察到达而 Task 尚未重新判断时，UI 不推断最终通过。

## 3. 必需依赖、私有实现与装配

| 依赖能力 / 提供方 | 最小行为及双方契约测试 |
|---|---|
| 当前判权 / permissions | 对真实入口、主体、动作、资源与版本给决定及依据；排队后撤权测试本域零派发，提供方证明分配/Context 不扩权 |
| 操作执行/观察/可选控制 / connections | 先保存尝试再外发，报告确定失败/未知/保存失败与 observed，按尝试查询；本域只引用不改写；双方用断连已改文件、乱序、取消不支持夹具 |
| 事务/保存/恢复 / shared/storage | 返回提交或失败/歧义，支持读取已保存修订和关联；本域决定业务恢复，不要求跨外部原子；双方故障夹具检验“未提交不派发”及提交歧义不重派 |
| 组织引用/修订及定位 / space | Context 可空，返回获准组织/Context引用、修订和定位，引用不搬数据/不授权；不提供真实文件/Git/远端资源版本的权威事实 |
| 真实资源事实 / 对应 owner 或适配器 | 提供backend、真实资源身份/别名、版本及观察依据；失效/无权不泄露，本域不从路径/Context名自造身份或版本 |
| 本次工作配置依据 / AI 的 AIC-04（含roles） | 返回获准、不可变的配置/职责修订及连接/模型依据引用，消费方保存工作关联，不拿最新配置替换在途依据；新工作与获准历史解释区分，依据不是授权，本域不反写模板 |
| 专业规则 / modes 等对应提供方 | 给明确类型/规则与适用版本，不按同名标题分派；未知规则拒绝执行，通用域不依赖具体模式私有实现 |

私有实现：Task/定义/轮次存储、推进规则内部组织、队列/并发算法、协调索引与恢复扫描。不得向 editor/连接器传内部数据库或可变全局对象。app 绑定可信入口、公开依赖和 runtime 协调出口；缺提供方返回明确不可用。runtime 不导入外部协议 SDK、Node 进程控制或具体 DSH 内部模型；适配器提供资源事实及外部状态，本域作业务判断。

## 4. 按模块施工、替身及组合完成证据

### W01/W03：定义、实例与循环推进（F02）

运行保存所用定义/节点稳定身份、规则与配置依据。发布新修订只供后续启动；不得按标题、画布数组下标或相同节点位置映射旧结果。首期建议不支持在途实例迁移：可编辑新定义，原实例继续原依据；需要迁移时先形成影响计划，逐节点说明保留、重做、阻塞及旧Operation归属，不能偷偷实现“热换图”。删除定义节点不停止旧实例/外部执行；停止另走W06。

循环、条件、失败/重试边须为显式控制语义；业务上允许循环不等于允许无条件等待环。每轮区分迭代与attempt；条件在规定轮次使用带来源版本的输入，未满足、明确跳过、失败、未知不能都当作完成。汇合必须说明等待全部、指定分支或其他已声明规则；未知规则/无退出条件不能默默运行。一个分支完成只推进其满足规则的后继，不将整个流程标完成。算法、循环上限与首次支持范围仍为B/C，未定规则对应能力暂不启动。

断言：实例I绑定r4，r5删节点N且换连接，I的N回执仍归r4原轮次；UI仅保存r5时停止调用为0。条件分支B明确未选不使“等待全部已选分支”永久等待；B结果未知时不得伪造跳过。循环第2轮的同名节点不能消费第1轮迟到回执完成自身。

### W03/W05/W06：等待、责任交接与准入限额（F01/F05/F06）

runtime唯一拥有WEX内推进/等待决定及资源协调记录；适配器提供真实资源与执行事实，permissions独占资格，connections执行准入和实际派发。建议在可观察等待依据中关联等待对象、持有资源、责任轮次及需核对的证据；不可见资源仅返回受限阻塞，不泄露其他Context内容。跨工作流等待环与连接回调递归须可诊断；超时只升级核对，不自动释放未知占用。避免持数据库事务或等待中的宿主调用占住唯一执行槽；具体锁顺序/全量资源申请/排队算法以C实验择优，不在此冻结。

人工接管/改派创建责任交接记录，说明旧执行是否确认停止、已完成子项与剩余目标、原/新轮次及证据引用；不能把前任产物改署名给后任。只阻塞受影响资源，独立分支可继续。无法确认旧执行停止时不自动放行同资源新执行；有权解除条件仍D04。

预算/并发的工作准入策略和预留/未决额度建议归runtime统一协调，包含无Task操作的宿主注入入口，不制造Task。connections提供估算、用量观察、外部结算来源及取消能力；app观察进程健康，shared提供技术容量/提交，均不自造第二份预算决定。预算许可不是权限许可。准入需关联政策修订、范围、币种/单位、预留及到期依据；unknown费用不自动归还。降低预算时建议阻止不满足条件的新派发，在途标出可能超额，不声称停止计费；提高预算也不自动恢复未知操作。该owner细化是B，硬上限、超额动作/共享池优先级为D，原子预留/回收与并发公平性为C；未有可证外部限额不得承诺绝对封顶。

断言：A持P等Q、B持Q等P时显示等待环及责任，不能永久只显示运行中；C对R正常推进。相同预算最后一份额度两个入口并发申请只能有一个有效预留（待C）；已外发后断连不得归还全部额度并再派。接管后旧结果仍可核对但不能验收新轮次。

### W04/W06：外部变更、归因与恢复入口（F07）

验收依据需覆盖产物版本、输入清单、规则版本和核验环境；不是只有输出文件变更才影响适用性。外部编辑/批量文件变化由连接适配提供观察；workflows决定哪些当前结论需重核。文件监听是失效线索，不是完整审计；mtime/路径相同不证明内容未变。不能把时间接近当作者归因，缺归因时明确混合/未知来源。

用户点击恢复后先进入核对：读取原关联、查询外部、核验资源、评价现行权限/限额/依赖，再明确继续观察、保存已知结果或启动新轮次。只读核对本身不要求旧副作用获得新写权；主动外部查询仍按实际动作授权。不能让恢复按钮在准备核对之前调用submit。断言：旧输入清单变更但输出未变，旧Verification仍只证明原清单；恢复时外部not found且文件已变化，新submit计数为0。

### 第五批收敛补丁：F01等待边界与F05限额适用范围（B候选，2026-10-31）

**自由画布基础规则：** 二维自由摆放，不是固定行列网格或固定流水线；节点为可调整矩形格子；连线只允许正交路径和方向箭头。自动布局是辅助而非唯一布局。移动节点、改线条弯折、平移/缩放、自动整理均不得修改业务依赖、节点权限或运行状态。

**明确不在 editor：** Workflow/Node/Edge 业务身份与持久化、Task/Run/StepRun 状态、Operation 账本、授权判定、资源冲突协调、节点工作内容和最终验收；这些分别归 workflows、connections、permissions、views 或对应工作界面 owner。

## G1/G4/G5 与跨对话持续工作补充（2026-10-31）

本节把 Task 资料引用、操作结果关联、内部检索和持久检查点归入 Workflows；详细 owner 矩阵见[基础能力落地映射](../docs/planning/FOUNDATION-CAPABILITY-IMPLEMENTATION-MAP-2026-10-31.md)。

**G1：Task 输入与产物引用。** Task 可引用 Context 资料、外部文件/仓库、会话输入、其他 Task 产物和核验依据。Workflows 保存引用及使用时的来源版本/观察，不复制来源正文或接管外部文件。Artifact 记录产物身份、来源 Task/轮次、输入与规则依据、实际定位及版本观察；实际字节由对应资源 owner/连接器管理。Verification 必须绑定具体 Artifact、输入清单、规则版本和核验环境。

**G4：Task 与 Operation 分离。** Workflows 拥有 Task、工作轮次、等待/阻塞、责任交接、Requirement、Artifact、Review、Verification 和 Acceptance。Connections 独占 Operation/attempt/外部观察/取消结果；Task 仅引用 Operation 并据其证据推进。Operation 的“完成”不等于 Task 完成，Task 的“暂停/取消”也不证明外部执行停止。

**G5：本域检索。** 提供获准的 Task、定义、轮次、Requirement、Artifact、Verification、阻塞/待核对项查询；不创建跨域全文搜索服务。搜索投影必须区分 Task 状态、Operation 观察、核验和最终验收；打开时重查当前来源和权限。

**跨对话检查点（核心要求）。** Task 必须能在不依赖原 Conversation、原模型上下文或原 Agent 实例的条件下，保存并读取足以判断“下一步能否安全继续”的持久工作状态。检查点至少覆盖：
- 目标、范围、验收条件及对应修订；
- 当前阶段/轮次、已完成项、未完成项和明确阻塞；
- 任务输入引用及其来源版本/观察；
- 相关 Operation 引用及其已知/未知状态（不复制 Operation 账本）；
- Artifact、Review、Verification 及适用的 Acceptance 依据；
- 当前责任主体/执行配置修订与交接记录；
- 下一步建议动作及其前置条件。

检查点不是 AI 自由文本总结，也不包含 API Key、永久授权、模型隐藏状态或“保证 Agent 仍在运行”的断言。阶段边界、重要产物提交、执行者交接、阻塞/恢复前应形成可回读检查点；保存结果 unknown 时按原意图查询，不另建 Task 或重复推进。

**恢复顺序。** 新对话或新执行者接手时：读取 Task 当前修订 → 核对输入资源版本 → 查询原 Operation/外部状态 → 检查产物及验证依据是否仍适用 → 重新判定权限和资源冲突 → 决定继续观察、继续本地工作、请求人工裁决或建立新轮次。任何未决副作用未核对前，不得向同一冲突资源盲目派发。恢复只恢复工作事实，不承诺应用关闭期间持续执行。

本节不冻结检查点字段、存储格式、周期策略或调度算法；Task 语义仍由本域唯一拥有。


## D01/D02：工作流节点位置权限（2026-11-01）

工作流节点的工具/动作/资源/目标范围及执行策略由 workflows 随工作流定义修订维护。权限声明绑定稳定节点身份和定义修订，不绑定画布坐标、数组下标或 UI 颜色。

- 节点需分别声明可用能力、动作类别、资源范围、实际目标、自动/询问/预授权策略和必要限制。
- 节点未声明的工具或动作不得从相邻节点、其他分支、循环轮次、Task 分配或发起对话继承。
- 工作流启动/Task 创建不等于所有节点副作用已授权；connections 每次派发前仍须调用 permissions 判权和复核。
- 节点可以表达用户明确设置的有限范围预授权，但不能覆盖全局关闭、Agent资格、Context开关、来源限制或高风险确认。
- 工作流模式不读取对话四级权限；由对话创建的 Task 进入工作流后，按当前工作流节点策略重新判权。
- 在途运行绑定启动时定义修订；权限撤销和当前策略变化仍需在每次执行前生效。

完整动作风险、节点授权维度与验收样例见[ D01–D02 权限矩阵 ](../docs/product/PRD-D01-D02-PERMISSION-DECISION-MATRIX-2026-11-01.md)。


## D02：工作流运行启动时一次性授权（2026-11-01，已确认）

节点权限配置可由用户手动建立，也可由 AI 根据任务生成或修改。AI 生成的权限配置只是提案，不是授权。

每次启动工作流时，WEX 必须汇总本次运行涉及的节点、工具/连接器、动作、资源、目标及执行范围，由用户对本次完整权限方案确认一次。确认后，本次运行内的节点可在该方案范围内自主执行，不逐节点重复询问。

启动确认必须绑定工作流定义修订、节点配置修订、目标范围和本次运行身份。定义/节点权限/目标发生变化，或实际操作超出已确认范围时，原确认不适用，必须重新授权。运行期间全局关闭、Context工具关闭、主体资格撤销或来源策略变化，仍须在实际派发前复核并阻止新的副作用。

此规则不使用对话四级权限；由对话创建的Task进入工作流后，仍以本次工作流启动确认和节点范围为准。风险标签本身不强制重复确认，但§6特殊信任边界及H2强制拒绝仍有效。
