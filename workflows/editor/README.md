# workflows/editor — WEX 工作流自由画布交互层

**当前方向（2026-11-01）：** WEX 自研轻量级自由画布。节点为可自由摆放的矩形格子，连接线只允许水平、垂直和 90° 转角；支持手动布局与自动整理。画布只是表层 UI 和交互工具，不拥有工作流定义、运行状态或调度权威。

## 1. 职责边界

- 本目录负责工作流画布交互：节点卡片渲染、拖动/缩放/选择、连接端口、正交连线、布局操作，以及打开节点工作界面的入口。
- workflows 拥有 Workflow Definition、节点业务身份/配置、执行依赖、修订、Task/运行状态及证据关联。
- workflows/runtime 负责调度、等待、派发协调、恢复和运行推进；画布操作不触发运行。
- views 拥有画布布局、节点位置/大小、viewport、视觉连线路径、布局方案和视图修订。
- connections 拥有外部 Operation/attempt/观察/回执及具体工具连接；permissions 拥有授权判定。
- 节点工作界面前期复用 WEX 通用对话、代码、审查、文件和数据界面；专业 3D/视频等工作台后续独立扩展。

## 2. 画布基本规则

1. **自由格子**：不是固定行列的表格，也不是固定纵向/横向流水线；用户可以在二维画布中自由组织节点位置。
2. **正交连接**：只允许水平/垂直线段和 90° 转角，显示方向箭头；不使用任意曲线或手绘线。
3. **关系与路径分离**：执行依赖由 workflows 维护；连线视觉弯折和节点位置由 views 维护。移动节点或整理布局不改变执行依赖。
4. **节点摘要**：名称、详情、状态颜色、任务数量、完成/执行/等待数据、当前任务和结果摘要来自权威业务投影。
5. **自动整理**：支持横向/纵向和基础拓扑布局；可预览、应用、撤销；局部整理不应重排无关区域。
6. **编辑与执行分离**：新增/删除/移动节点、创建关系或修改布局均不隐式启动/取消运行；正式关系修改走 workflows 受控入口。
7. **可替换**：画布内部节点对象、SVG 路径和渲染组件不能泄漏为 Workflow Definition 的持久化格式。

## 3. 节点工作界面范围

前期通用界面覆盖普通任务、AI 对话、代码编写、代码审查、文件/数据处理。画布卡片先显示摘要；点击后进入相应通用工作界面。节点不需要全部拥有同一种详情弹窗。

3D、视频、音频等复杂工作台后续按 Context 的真实需求开发，可以组合观察多个相关节点和共享资产。此阶段不预建完整专业 UI 插件协议，不阻塞基础画布。

## 4. 技术实现方向

当前推荐使用 React + HTML DOM 渲染节点、SVG 绘制连接线，自行实现最小画布控制、正交路由和基础自动布局。具体坐标模型、路由算法、布局算法和性能策略仍需原型验证。

不把 React Flow、X6、JointJS 或 Rete.js 作为 WEX 工作流核心依赖。ELK 等布局算法可独立评估，不能拥有业务数据或执行语义。

## 5. 现有原型

prototype/ 保留既有 React Flow 12.12.0 实验。其构建、模型和 DOM 测试记录见 prototype/VERIFICATION-2026-10-30.md。

该原型是历史技术样本，不代表产品画布已经选定 React Flow，也不代表真实浏览器拖拽/连线或 Windows Electron 验收通过。后续可比较、提取概念或废弃，不要求沿用其数据结构和组件实现。
