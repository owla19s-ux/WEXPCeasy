# shared 业务契约：存储、路径、凭证与技术诊断

- Owner：shared。只拥有可复用技术机制，不拥有任何领域业务对象、业务状态或授权政策。
- 适用功能：F10-001/003/004/005/007/008，F14平台数据与凭证接线，F15-001/002/015。
- 状态：A为既有边界；B为候选能力细化；C为Windows/备份/凭证真实环境验证。本文不冻结数据库schema、IPC、驱动、文件锁算法或平台API。

## 1. A：唯一归属边界

1. Space、AI、Conversations、Connections、Workflows、Permissions等各领域拥有自己的对象、状态、来源和业务修订；shared只提供技术存储、路径、凭证和诊断机制。
2. shared不拥有Task、Operation、权限审计、消息、Agent记忆、Artifact/Evidence或专业关系，不建立第二份权威账本。
3. permissions唯一拥有授权判定、授予、撤销和审计；凭证存在/可解密不等于本次使用获准。
4. app拥有安装、数据根选择、启动/升级/恢复的宿主协调；shared提供技术能力，不决定跨模块业务恢复结果。
5. 外部文件/目录正文由实际资源owner或connections适配器负责；路径字符串不是稳定身份或访问能力。

## 3. F10跨域能力的owner解释

- F10-001/003/004/005由shared拥有的是通用持久化、技术存储类别、稳定引用表示/路径定位规则和CAS原语；每个领域仍拥有自己的对象身份语义、数据内容、业务修订及冲突处理。
- 存储类别至少区分：权威结构化业务数据、持久文件/附件字节、可重建索引/缓存、普通技术日志、秘密凭证。类别决定技术存储/备份/轮转约束，不决定对象业务含义；领域owner负责给自己的对象声明类别。
- F10-007由app拥有备份/恢复工作流；shared提供SH-03技术快照能力；各领域提供范围清单、冻结/导出/验证/恢复钩子。
- F10-008由app拥有迁移协调；各领域拥有自身schema迁移；shared只提供技术提交/备份/回退支撑。不能宣称跨域迁移原子。
- F10-006导入/导出编排不归shared；由app协调用户发起的传输作业，各领域提供自己的序列化/验证/导入写入出口，permissions控制读取和披露。

## 4. 错误与提交语义

至少区分根不存在/卷不可用/无权/格式损坏/身份冲突、存储不可用、修订冲突、意图冲突、明确未提交、提交未知、凭证缺失/不可用/拒绝、备份不完整、格式不兼容、恢复部分成功、日志写入失败。不得将读取失败转成空数据；unknown先按原意图回读，不另造新意图。

## 5. 实现与验证事实

- 已实现：SH-01部分根身份/路径观察/合作目录锁；SH-02限定命名空间SQLite快照、CAS和意图记录；SH-06只有受限技术诊断sink，尚无持久日志/轮转平台。
- 未实现：SH-03完整备份恢复/迁移原语；SH-04/05系统凭证后端和秘密生命周期；Windows句柄级路径安全/ACL/跨用户锁。
- Linux/Electron实验通过不等于Windows E4；SH-01/02当前实现也不等于跨目录、跨数据库或外部服务原子性。

## 6. 验收门槛

1. 领域对象始终由原owner读写；shared不能根据命名空间推断业务含义。
2. 存储提交ACK丢失后可按原意图查询；同ID不同内容拒绝。
3. 根失联/身份冲突/链接逃逸不创建替代空库，不覆盖原数据。
4. 凭证引用与秘密值分离；拒绝/无权时适配器未取得秘密；秘密不进入普通日志或备份。
5. 备份恢复逐域验证范围、版本、附件、部分成功和外部事实核对。
6. 普通日志轮转不删除正式审计/Operation/Evidence记录。
