# UI/avatar｜虚拟形象入口

> Owner：UI 的独立形象展示/交互子模块。产品设计见 [PC 基础 UI](../../docs/A1-正式产品设计/PC基础UI布局与交互设计.md)；版本与验收见 [A2](../../docs/A2-版本与工程状态/0.1.1/功能与工程状态总表.md)。与 [交互栏](../interaction-bar/README.md) 是平级模块，不互为业务 owner。

## 职责及当前源码

- `avatar.tsx` 维护**形象入口的表现与用户指针交互界面**，当前是窗口内可拖动 W 标记；主窗口的坐标计算/位置存储/展开联动由 `../src/interaction-dock.tsx` 兼容装配层承担。
- 当前已支持窗口内自由悬浮、栏内相对位置、点击展开/收起联动；自由位置与栏内位置分别保存在既有 `wex.interaction-dock.v1` UI 偏好中。**目前没有实际人物素材或形象动作模型**，不冒充角色成品。
- 不属于 Space 左导航的固定头像；也不是 Windows 桌面级悬浮窗。后者须经后续版本独立设计。

## 与 AI/Agent 的联动边界

虚拟形象是 **AI 的可视化入口与展示载体**，可以按用户选择关联主 AI、秘书或某个 Agent 的呈现配置，未来可响应当前对象/对话的真实状态；形象身份、素材/表现配置、对话/Agent 业务数据、模型调用必须分开。AI 模块拥有 Role/Position/Agent 配置；Conversations 拥有会话/生成；Space 拥有 Context 引用；UI 仅经可信 DesktopBridge 读取获准的身份/状态并提出交互意图。

**不可把当前可拖动 W 标记等同于已经绑定 AI。** 真实 Agent/秘书选择、视觉素材/动画、情绪/语音反馈、状态映射、点击动作须另行细化版本操作与回归；入口点击不能直接授予工具权限、创建未授权会话或启动自动执行。撤权、切换 Agent/Context 时不得继续展示旧敏感信息或接纳旧响应。

## 本版与验收

0.1.1 优先保全基础形象入口、展开联动、位置保存/坏数据恢复及应用内拖动；AI 联动明确为接口方向，具体交付以 A2 当前批准范围为准。验收应分别覆盖自由悬浮/栏内拖动、点击与拖动区分、隐藏/展开、位置恢复、切换 Context/Agent、权限失效和旧响应隔离；目前未完成真实 AI 交互或 Windows 实机验收。

源码入口：`avatar.tsx`、`../src/interaction-dock.tsx`；测试：`../tests/interaction-dock.test.mjs`。不得另建角色运行时或业务持久表。
