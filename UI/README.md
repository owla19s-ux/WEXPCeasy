## 已确定的 UI 边界

- **第一列**：顶部横向并排三个竖形 Space 类别按钮；导航可缩窄或隐藏；设置入口独立可达。
- **第二＋第三列**：一个共享工作窗口。底部是当前 Context 的浏览器式视图标签，默认第一视图“Context 配置”；无文件时**整个视图占满**，打开文件时才在旁侧出现可调整宽度的预览/编辑区，关闭预览恢复完整视图。
- **第四列**：默认收起，不在本轮先做旧式上中下三段辅助区。
- **拖动分隔线**：保留现有原生 Pointer/键盘交互；根据需要用于导航、按需预览，未来辅助/双视图；Windows 缩窄时临时降级，不覆盖保存的用户偏好。
- **虚拟形象与交互栏**：相互独立、可在 WEX 页面内联动。交互栏收起时形象自由悬浮；点击可展开交互栏并恢复栏内位置；栏内可连续拖动。二者不能混为导航区头像或第二列视图标签。
- **顶层 Windows 窗口**：优先使用 Electron/Windows 原生标题栏、最小化/最大化/还原/关闭/移动/Snap；适配不同 DPI、Windows 文字增大、窄窗及多显示器，不重造原生窗口管理。
- **未来扩展**：两个完整视图并排、功能/架构树关联、高级 Docking、独立桌面级悬浮、交互栏四向布局不是因本次设计而立即获准的 0.1.1 全量施工项目。

## UI 源码模块化的就近拆分规则

先复用现有功能，再由实际 D-08 施工把**中间工作窗口**拆成少量清晰的 UI 职责：`MiddleWorkspace`（工作空间编排）、`ViewTabBar`（标签）、`ViewHost`（当前视图）、`PreviewHost`（按需预览/编辑）、必要的纯状态转换/持久化工具。名称是职责示例，**不是已存在文件、必须新增的目录或独立业务模块**。

`workbench.tsx` 只装配第一列、中间工作窗口、默认收起第四列和独立浮层，不直接实现 Context/文件/对话业务操作；`layout.ts` 专注可测的几何布局与版本迁移；视图/预览 UI 状态不得复制 Space、Conversation、Permission、Operation、Verification 的权威数据。每次新建文件都应有实际组件消费与就近测试，不为了模块化而拆碎成大量单函数文件。

**施工验收**：源码职责、真实页面入口、受控 IPC、状态生命周期与测试须成套完成。**当前 D-08 已有部分真实源码变更、尚未取得构建与 Windows 实机通过证据**。文件编辑、完整多类型视图、真实角色素材与交互栏业务入口尚未完成，不得提前标为交付。

通知/搜索必须经领域公开的获准查询构建结果，不能绕过权限或把缓存当最新业务事实；撤权、目标失联、旧通知跳转及旧搜索结果须重新校验来源。主UI只保存临时焦点与交互，不维护第二套Task、Operation、许可、连接状态。Windows菜单、系统托盘、快捷键和拖放按app平台接线与UI实际交互协作，不为每种原生功能建独立目录；高DPI/键盘/无障碍支持随真实窗口验收。

验收需检查通知误报、无权搜索泄漏、跨窗口过期结果、旧缓存、消息/日志导出脱敏及程序未配置完整时的可用性；目前只有设计，没有桌面成品。

## G5/G7：内部检索与输入附件

UI 聚合各业务 owner 的获准查询并负责导航；外部互联网 Search/Fetch 不等于内部检索。输入页支持文本及后续文件选择/拖入/粘贴、附件预览和来源提示，但文件访问通过 App/Connections 窄能力，Renderer 不直接读取任意路径。UI 可呈现 Task 检查点与“继续”入口，点击后先交 Workflows 核对，不直接派发。
